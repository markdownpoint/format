# MarkdownPoint file format reference

This reference lists every key in the files and what it does.

In each table, the required column says when a record needs the key. Yes means always. Otherwise it names the case, such as "with max". The values column lists the words or numbers the key can be set to. A range includes both of its ends. On a key with an x and a y, a range applies to each of them.

## <a id="files"></a>Files

### <a id="presentation-folder"></a>The presentation's folder

A presentation is a folder with two files at its root: `slides.md` and `presentation.mdpoint`. Their names can be in any letter case. The folder's name is the presentation's name. The presentation doesn't open if its root has another .mdpoint file, or another .md file whose name starts with the word slides. A sync service's conflicted copy is such a file.

- [`slides.md`](#slides-md): the sections, the slides' order and text, and the speaker notes.
- [`presentation.mdpoint`](#presentation-mdpoint): the theme, the slides' objects and animation, and the settings. It is JSON.
- media/: the author's files.
- generated/: the files MarkdownPoint makes, and the [.json files](#generated) that record how each image was made.
- themes/: the presentation's [themes](#theme-folder).
- versions/: the presentation's [saved versions](#versions).

Files and folders whose names start with `.markdownpoint` belong to MarkdownPoint. Everything else in the folder belongs to the author.

### <a id="theme-folder"></a>A theme's folder

A theme is a folder in themes/. The folder is named after the theme's key. Its root has the theme's [master](#the-master), master.json, and a .json file for each [layout](#layouts). A layout's file is named after the layout's key.

### <a id="theme-package-file"></a>A theme package

A theme package is one .mdptheme file. The file is a ZIP archive of one folder. The folder is named after the theme's key, and it contains [manifest.json](#theme-package) and the theme's files. The archive has no symbolic links.

The folder can also have two folders that aren't the theme's files, and manifest.json lists neither. In previews/, cover.jpg is a picture of the theme. Its slides/ folder has a picture of each example slide in order: 1.jpg, 2.jpg, and so on. example/ has a presentation folder that a new presentation can start from.

### <a id="paths"></a>File names and paths

A file path is relative to the presentation's folder or the theme's folder. It has / between names. A name can't be empty, `.`, or `..`. It can't start with a dot or end in a space or a dot. It can't contain a backslash, <, >, :, ", |, ?, *, #, or a control character. CON, PRN, AUX, NUL, COM1 to COM9, LPT1 to LPT9, COM¹ to COM³, and LPT¹ to LPT³ can't be file names in any letter case or with any extension. A path spells each name exactly as its folder lists it. Names are in Unicode's composed form (NFC). No folder has two names that are the same under the full case folding of Unicode 17.0.0. Under that folding, ß and SS are the same.

A presentation's files are under media/ or generated/. A .json file under generated/ isn't one of them. A theme's files can be anywhere in its folder, except manifest.json, previews, and example at its root. An image file's name ends in .png, .jpg, .jpeg, .gif, .webp, .svg, .avif, or .bmp. A video's ends in .mp4, .m4v, .mov, .webm, or .ogv, an audio file's in .mp3, .m4a, .wav, .ogg, or .flac, a model's in .glb, and an embedded font's in .eot. The extension can be in any letter case. A file reached through a symbolic link or an alias is never one of the presentation's files.

### <a id="format-version"></a>The format version

Every file states its format version in `markdownpoint`. It is a major and a minor number in quotes: "1.0". Every key in this reference is from version 1.0. MarkdownPoint 1.x opens any version 1.x file. A later minor version only adds what an earlier MarkdownPoint can skip, such as a key, a word, an object type, or a number outside a range. The earlier MarkdownPoint draws it as nothing or as its key's default. A save never lowers a file's version. A file of a newer major version needs a newer MarkdownPoint. A JSON file of a version MarkdownPoint knows has only the keys this reference lists. Each key appears once. Any other key is an error, most likely a typo.

### <a id="ids"></a>Ids

An id starts with a lowercase letter. The rest is lowercase letters, digits, and single hyphens, such as title-card. It ends with a letter or a digit. Where ids are put in order, they are compared character by character. A hyphen comes before a digit, and a digit comes before a letter. So `k10` comes before `k9`. Slides and compositions share one set of ids. A presentation's id, a save's id, and a theme's id in its master are lowercase UUIDs. A theme's key and a layout's key are ids that every supported system can use as a file name. A layout's key can't be master or manifest. The names a theme gives its schemes, color roles, brand colors, and text styles are spelled as ids. A binding names a key, or a number part of a record, such as `tilt.x`. Each name in it is spelled as an id. A font family's name starts with a letter or a digit in any script. The rest is letters, digits, spaces, dots, underscores, and hyphens.

### <a id="colors"></a>Colors

A color is a role in the theme's color scheme, such as accent, or a hex color in sRGB. A hex color is written #RGB, #RGBA, #RRGGBB, or #RRGGBBAA. Its alpha is straight, not premultiplied.

### <a id="units"></a>Units

A canvas unit is one pixel of the slide at full size. In 3D, a canvas unit is the theme's `unit-scale` in meters. An icon unit is a 24th of an icon's frame. Each icon is drawn on Lucide's square. The square is 24 icon units wide. It stretches to fill the frame. A blur is measured by its radius. CSS `box-shadow` uses the same radius. The radius is twice the Gaussian's standard deviation. CSS `filter: blur(8px)` is a blur of 16. A text's `tracking`, `text-stroke-weight`, and drop shadow are in ems of its `font-size`. A heading in the text uses the same lengths as the rest of its words. On a shape, `tracking` and `text-stroke-weight` are in ems of its words' `font-size`, and its drop shadow is in canvas units. On a chart, `tracking` and `text-stroke-weight` are in ems of the size of the words they apply to.

### <a id="numbers"></a>Numbers

Every number is read as the IEEE 754 double nearest to it. ECMAScript's numbers are of this kind. The double is rounded to six decimal places the way ECMAScript's `Number(x.toFixed(6))` rounds it. `toFixed` rounds a half away from zero. A negative zero is read as 0. Then the number is checked against its range. 1.0000004 is read as 1. The half −0.0078125 is read as −0.007813. The double nearest 0.1234565 is just under it. So 0.1234565 is read as 0.123456. A theme's `unit-scale` is read to 12 significant digits the way ECMAScript's `Number(x.toPrecision(12))` rounds it. A byte count, an image's size in pixels, and a `parent-inverse` are read exactly as written. A chart cell is read as the double nearest to it and isn't rounded to six places.

### <a id="links"></a>Links

A link is an http or https URL with a host, a mailto: or tel: address, or slide: followed by a slide's id. It has no spaces or control characters. A URL has no backslash. A link to anything else, or to a slide that isn't there, is kept but does nothing.

### <a id="code"></a>Code

No key's value is code. MarkdownPoint runs no code from a presentation's folder or a theme. A text shows an HTML tag as plain text, and an SVG image runs none of its scripts. The one exception is a web video. Its YouTube or Vimeo player runs the provider's own scripts.

## <a id="slides-md"></a>`slides.md`

#### frontmatter

The keys MarkdownPoint reads, each on one line as key: value. Other keys are kept as written. A notes app can add its own keys, such as tags, and the presentation still opens.

Where: the frontmatter at the top

| key | required | values | description |
| --- | --- | --- | --- |
| `markdownpoint` | yes |  | The format version. It is a major and a minor number in quotes: "1.0". |
| `id` | yes |  | The presentation's id. The .mdpoint file has the same id. |
| `footer` |  |  | The footer text. Every slide with a footer field shows it. Without quotes, a space followed by `#` starts a comment. |
| `save-id` |  |  | The id of the save that last wrote the files as an editor handed over the shared presentation, closed it, or signed out. Other tools leave it unchanged. |

**`save-id`.** Only the .mdpoint file's `save-id` is read. A save writes the same id into the frontmatter.

#### markers

The markers that divide the .md file into sections, slides, and their text. Spaces or tabs before or after a marker on its line don't change it. Each marker ends with a line break, even at the end of the file. Each of a slide's own objects with text has a text marker, even when its text is empty. A layout's placeholder needs a text marker only once it has words. Until then, an empty marker means the same as none.

Where: a line of its own in the body

| marker | required | values | description |
| --- | --- | --- | --- |
| `section` |  |  | `<!-- section: id -->` starts a section. Its id is unique among sections. One level-1 heading after it is the section's name. |
| `slide` |  |  | `<!-- slide: id -->` starts a slide. Each slide has one, and the markers come in presentation order. |
| `composition` |  |  | `<!-- composition: id -->` starts a composition's text. Each composition has one. |
| `text` |  |  | `<!-- text: id -->` starts an object's text. `<!-- text: <instance id>.<control id> -->` starts an instance's words for a text control. Each id appears once in its slide or composition. |
| `control` |  |  | `<!-- control: id -->` starts the default text of a composition's text control. The id is the control's, and it appears once in its block. |
| `notes` |  |  | `<!-- notes -->` starts the slide's speaker notes. |

**Sections.** A section's heading is the only line in its block. The section's name is the heading's words without their marks. It has one space between its words. Once there is a section, every slide must be in one. A slide before the first section is an error.

#### body

How the body is divided, and what is kept as written. Only a marker starts a slide. The slide continues until the next slide, section, or composition marker, or the end of the file. A paragraph id in speaker notes is never shown, and no step can name it.

Where: the body, between and inside the markers

| form | required | values | description |
| --- | --- | --- | --- |
| `escape` |  |  | A line that looks like a marker stays in its block when a backslash follows its `<!--`: `<!--\ notes -->`. Outside code, the backslash isn't shown. |
| `blank-line` |  |  | Blank lines only separate. Several blank lines in a row are the same as one. Under a marker or before the next one, they mean nothing. In a code block that's never closed, all but the last are code. |
| `comment` |  |  | An HTML comment in a text or notes block is a note. It is kept but not shown. An `id` comment is the exception. |
| `unsupported` |  |  | Markdown that MarkdownPoint doesn't support, such as an image or an HTML tag, is kept as written and shown as plain text. |

**Misspelled markers.** A comment line with a marker's word in any letter case and at most one other word is a misspelled marker. It is an error.

#### markdown

The Markdown that text, tables, and speaker notes use.

Where: text blocks, table cells, and speaker notes

| form | required | values | description |
| --- | --- | --- | --- |
| `paragraph` |  |  | Lines separated by a blank line are paragraphs. A paragraph of only `<br>` has one line break fewer than it has `<br>`. A `<br>` alone is an empty paragraph. |
| `id` |  |  | A paragraph's id ends its last line, as in `<!-- id: k3x9a2 -->`. Spaces or tabs can follow it. A later paragraph with the same id is read as a new one. |
| `heading` |  |  | `# Heading` to `###### Heading` are headings. A line underlined with `===` or `---` is a level-1 or level-2 heading. |
| `list` |  |  | Lines starting with `- `, `* `, or `+ ` are a bulleted list. Indent for deeper levels. Any other paragraph between items ends it. |
| `numbered-list` |  | a first number from 0 to 999,999,999 | Lines starting with `1. ` or `1) ` are a numbered list. It starts at its first number and counts up. Any other paragraph between items ends it. |
| `quote` |  |  | Lines starting with `> ` are a quote. |
| `code-block` |  | bash (sh, shell, zsh), c, cpp (c++, cc, cxx, h, h++, hh, hpp, hxx), csharp (c#, cs), css, diff (patch), go (golang), java (jsp), javascript (cjs, js, jsx, mjs), json (json5, jsonc), kotlin (kt, ktm, kts, ktx), markdown (md, mkd, mkdown), php, python (gyp, ipython, py), ruby (gemspec, irb, podspec, rb, thor), rust (rs), sql, swift, typescript (cts, mts, ts, tsx), xml (atom, html, plist, rss, svg, wsf, xhtml, xjb, xsd, xsl), yaml (yml) | Lines between fences of three or more backticks or tildes are a code block. It is colored for its language by highlight.js 11.12.0. A marker in it is code. A code block with a marker must be closed. |
| `rule` |  |  | A line of `***`, `___`, or `---` is a horizontal rule anywhere in its block. A `---` directly under a paragraph's text isn't a rule. It makes that text a heading. |
| `table` |  |  | A table's or a chart's text is one Markdown table: a header row, a divider row, and body rows. `\|` goes between cells. No HTML comment can follow it. A divider's colons align columns. `\\|` is a pipe. |
| `bold` |  |  | `**text**` or `__text__` is bold. |
| `italic` |  |  | `*text*` or `_text_` is italic. |
| `highlight` |  |  | `==text==` is highlighted. |
| `strikethrough` |  |  | `~~text~~` is struck through. |
| `code` |  |  | `` `text` `` is code. It can have a color and a link, but no other mark. |
| `link` |  |  | `[text](address "title")` links to a webpage, an email address, a phone number, or a slide as `slide:id`. The title is optional. `<address>` is a link that shows its address. |
| `color` |  |  | `[text]{color=accent}` or `[text]{color="#2F7D4F"}` colors text with a color role or a hex color. |
| `font-weight` |  | 300, 400, 500, 600, 700, 900 | `[text]{font-weight=600}` gives text its own weight, and bold overrides it. With a color, it's one span: `[text]{color=accent font-weight=600}`. |
| `field` |  | slide-number, slide-count, section-number, section-name, date, footer | `{{name}}` shows a value that MarkdownPoint fills in. Fields, below, describes each one. |
| `line-break` |  |  | A backslash or two spaces at the end of a line make a line break inside the paragraph. `<br>` makes one too, except in a table cell. |

**Paragraph ids.** When a paragraph is split, its first part has the id. When paragraphs are joined, the first one's id stays.

**Bold and italic** follow CommonMark except in one way. A run of `*` between punctuation and a letter can both open and close.

**Code blocks.** Lines indented by four spaces are also a code block. A fence's language name can be in any letter case. The words after the language are the fence's options. They are in braces as Slidev writes them. `{lines:true}` numbers the lines. Any other option is kept as written.

**Escapes.** A backslash before punctuation makes it plain text. Outside code, a character reference such as `&amp;` or `&#169;` is read as its character. An address that isn't a link stays plain text.

**Spans.** A span's attributes, `color` and `font-weight`, can come in either order. Each value can be bare or quoted. A span with any other key, a repeated key, or a value its key doesn't accept stays as written, and none of it applies. A span with no attributes, `[words]{}`, groups its words and gives them no formatting. A bold word is drawn at bold's weight. Otherwise a word is drawn at its own weight. A word with no weight of its own and with a mark is drawn at its text style's weight for that mark. Any other word is drawn at its block's weight.

**Headings** are 2, 1.5, 1.17, 1, 0.83, and 0.67 times the text's size. Their weight is 700, or the text's weight where that's heavier.

**Tables.** A table, or a chart's table, has at most 5,000 cells. A chart's table names its series in the header row, after the first cell. It names its categories in the first column. Its other cells are numbers in Latin digits. They use the decimal mark and group mark set by Unicode CLDR 48.2.0 for the presentation's `locale`. The whole digits are ungrouped, or grouped in the language's widths by its group mark or by a space, never by both: 1,234.5 or 1 234.5 in English, 1 234,5 in Swedish, and 12,34,567 in Hindi. That space can be a space, a no-break space, a narrow no-break space, or a thin space. Where the group mark is an apostrophe, a right single quotation mark, U+2019, is the same mark. One number may mix the two. A number can have a sign, a prefix, or a suffix, such as $ or %. A negative number can be in parentheses or end with a minus: (1,234.50) or 1 234,50 kr-. A parenthesis with no partner on the number's other side belongs to the prefix or suffix. A minus after a colon, a comma, or a period belongs to the suffix too. 100:- is 100. A cell that contains no number has no value. So 1,23 has no value in English, and 1,234 is 1.234 in Swedish. A label spells its value as its cell does. A pie or a donut draws the first series' positive values. A counter counts to the number in the second cell of the first body row, or to 0 if that cell is blank.

**Fields.** `slide-number` is the slide's number among the shown slides, counted from 1. `slide-count` is the number of shown slides. A skipped slide has no number, and a composition has none. The field shows nothing there. With the slides A, B, and C, and B skipped, `{{slide-number}} of {{slide-count}}` on C shows 2 of 2. `section-number` is the number of the slide's section, counted from 1. `section-name` is the section's name. Both are empty for a slide that isn't in a section. `footer` is the footer from the frontmatter. `date` is the presentation's `date` with a full year and a two-digit month and day. Their form is set by Unicode CLDR 48.2.0 for the presentation's `locale`. It uses the Gregorian calendar and Latin digits: 2026-03-04 in sv-SE and 03/04/2026 in en-US. When CLDR doesn't have a locale's language, the date is written as in en-US. Without a `date`, the field stays as written. A field's value is inserted as text. It's never read as Markdown or as a field.

## <a id="presentation-mdpoint"></a>`presentation.mdpoint`

A key that names an object the slide doesn't have is skipped with a warning, and the rest of the slide plays. Such a key can be a parameter under `initial` or in a step, a cue, a constraint's target, a group's or a 3D object's parent, or a line end without a last position.

#### presentation

The presentation: its theme, slides, and settings.

Where: the root

| key | required | values | description |
| --- | --- | --- | --- |
| `markdownpoint` | yes |  | The format version. It is a major and a minor number in quotes: "1.0". |
| `type` | yes | presentation | What the file is. |
| `id` | yes |  | The presentation's id. The .md file has the same id. |
| `theme` | yes |  | The key of the presentation's theme. It's the name of the theme's folder in themes. The theme's master sets the slide size and `unit-scale`. |
| `slides` | yes |  | The slides by id. The .md file has their order and text. |
| `background` |  |  | The background every slide shows, unless the slide sets its own. |
| `background-image-style` |  |  | The style generated background images use when their background doesn't set one. It's written as text, and `none`, the default, means no style. |
| `comments` |  |  | Comment threads by id. Each one is pinned to a slide or a composition. |
| `compositions` |  |  | Reusable animated scenes by id. Slides show them as instances. |
| `countdown` |  | whole numbers, 1 to 4294967296 seconds | How long the talk should take in seconds. Without it, the talk has no set length. |
| `date` |  |  | The date the date field shows. It is written YYYY-MM-DD. It must be a real calendar date in year 0001 or later. |
| `default-text-style` |  |  | The text style and color of a new text box. Without a text style, a new text box has none. Text boxes already on the slides don't change. |
| `image-style` |  |  | The style generated image objects use when they don't set one. It's written as text, and `none`, the default, means no style. A background's image uses `background-image-style` instead. |
| `locale` |  |  | The presentation's language tag, such as fr-CA. It sets how the date field is written, chart cells are read, and words are split to animate. The default is en-US. |
| `save-id` |  |  | The id of the save that last wrote the file as an editor handed over the shared presentation, closed it, or signed out. Other tools leave it unchanged. |
| `self-playing` |  |  | With it, the presentation plays by itself. |
| `soundtrack` |  |  | Music that plays under the whole presentation. |
| `swatches` |  |  | The hex colors the author has saved for this presentation. |
| `transition` |  |  | The transition from every slide to the next, unless the slide sets its own. Without it, slides cross-dissolve over 0.5 seconds. |

**`locale`.** A locale's parts are joined by hyphens: a language code, then a script, a region, and variants where it has them. It can't have extensions, private-use subtags, or the posix variant. The cells of a theme's charts are always read as en-US. The locale also sets the forms of Chinese, Japanese, and Korean characters.

### <a id="settings"></a>Settings

#### size

The size of a slide or a composition in canvas units.

Where: `compositions.<id>.size`; `size` in `master.json`

| key | required | values | description |
| --- | --- | --- | --- |
| `width` | yes | whole numbers, 1 to 8192 canvas units | The width. |
| `height` | yes | whole numbers, 1 to 8192 canvas units | The height. |

#### transition

A slide transition. The defaults are interpolation ease-in-out, match object, direction left, color #000000, and delay 0.

Where: `transition`, `slides.<id>.transition`

| key | required | values | description |
| --- | --- | --- | --- |
| `effect` | yes | none, cross-dissolve, carry-over, push, scroll, move-in, reveal, wipe, zoom, fade-through-color | Which transition plays, or none. |
| `color` |  |  | The color of a fade through color: a color role or a hex color. |
| `delay` |  | 0 to 4294967296 seconds | How long a transition that starts by itself waits after the slide's last step ends. |
| `direction` |  | left, right, up, down | Which way a push, scroll, move in, reveal, or wipe travels across the screen. |
| `duration` | unless the effect is none | more than 0 and at most 4294967296 seconds | How long it takes. It's left out when the effect is `none`. |

**Effects.** With `cross-dissolve`, the next slide fades in over this one. With `carry-over`, each object with the same id on both slides moves to its place on the next slide. Everything else cross-dissolves. An object that a step brings in on the next slide fades in instead. With `push`, the next slide pushes this one off. With `move-in`, the next slide moves in over this one. With `reveal`, this slide moves off and shows the next one. Which way they travel is set by `direction`. With `wipe`, an edge uncovers the next slide. With `zoom`, the next slide grows from the center. With `fade-through-color`, the slides fade through `color`.

**Scroll.** A scroll moves both slides along one strip. Each slide's 3D objects stay at their place in its stacking order and are clipped at its edge. A model or 3D text with the same id on both slides crosses between them whole. Neither slide's camera drifts during a scroll. Both cameras drift during any other transition.

**The animated column.** `yes` means a step's keyframes move the key through the values in between. `discrete` means the key changes at once at its keyframe, whatever the interpolation. A list names the parts of the key that a step animates.

**Overrides.** A null that would leave a required key missing is ignored. When an override gives an inherited image or video a `file`, the object becomes an image or a video. Which one depends on the file's type. A `null` file leaves an empty image. An override's key that the object doesn't have, such as `cone-angle` on a light that is directional on its layout, is ignored with a warning. A value that only another type can have is ignored with a warning too. A value that isn't valid with what the object inherits is ignored the same way. Each stays in the file and applies once the object can have it. A key or a value that no object can have, such as a misspelled key, is an error. `type` or `bindings` in an override is an error too. On an object that isn't an override, a value that isn't valid is an error. In an override, `frame`, `position`, `icon-position`, `rotation`, `scale`, `point-of-interest`, `tilt`, `size`, `anchor-point`, and `tail` change only the parts given. But `rotation` changes only the parts given when both it and the inherited rotation are in degrees. Otherwise it replaces the inherited one whole. An axis that a rotation in degrees leaves out is then 0. Any other record or list replaces the inherited one whole. An object on a master or a layout can't be a composition instance or have a generation or bindings. Its text can't have a 3D text `model`.

**Bindings.** A binding names a number part of a record as a curve does. The control must be of a type that can set what it binds. A number control sets a number key or a number part of a record. A color control sets a key that takes a color. A boolean control sets a key that is true or false. A choice control sets a key whose values are its options' ids. A media control sets `file`. `text` binds the object's words in the .md file. A text control sets a text's, a shape's, or a table's words. A number control can set a text's or a shape's words too. A number control's value becomes words the way ECMAScript writes the number. A bound key has no value or keyframes of its own. A bound part still has its value in its record.

**Groups.** Groups nest at most 200 deep. A group's rotation is the angle at which its members' box is measured. It doesn't turn the members. Their own positions and rotations don't change. When a keyframe animates the group's rotation, the members turn by the difference between the keyframe's value and the group's rotation. A group's members paint in order right after the group. With blend-mode `normal`, they blend only with each other. A group's default is `pass-through`. With it, the members blend with what is beneath the group. In Figma and Photoshop, this is Pass Through. The members' blending stays inside the group when the group has a blur or a `tilt`. When the group is placed in depth in a tilted group, their blending stays inside the tilted group. The group's wipe masks each member alike, and they still blend with what is beneath it. A group fades as one picture. Where a member's blend mode reaches past the group, or the group is placed in depth in a tilted group, the group's opacity fades each branch on its own. A branch is a member, or a member group that fades as one picture.

**A shape's words.** On a shape with a fill, the default `color` is whichever of background and text is easier to read at the text's first line. That default is used instead of the text style's color.

**Lines.** Where a curved line has no `bend`, it is −|dx × dy| ÷ (4 × (dx² + dy²)). dx and dy are how far its end is from its start. So a line whose ends are level or plumb is straight. One on a diagonal bends most: by −1/8. A line that isn't curved still has its bend. The bend shows once the line is curved.

**Charts.** A chart's `spread` works like a text's `spread`. A counter has no legend, no value labels, and no `spread`. A chart's `align` sets only a counter's figure. Where an entry of a chart's `colors` is `null`, or the list ends before it, the chart uses the slide's `accent` and `text` colors in turn: `accent` at the first entry, `text` at the second, `accent` again at the third, and so on. Where `text` is the same color as `accent`, and `muted` isn't, `muted` takes the place of `text`. Each round after the first is drawn at a lower opacity: half, then a third, then a quarter, and so on. Each opacity is rounded to a whole percent.

**Web videos.** A web video's `url` is the https address of a YouTube or Vimeo video. It has no user name or password, and no port other than 443. YouTube addresses are youtube.com/watch?v=id, youtube.com/embed/id, youtube.com/shorts/id, youtube.com/live/id, youtu.be/id, and youtube-nocookie.com/embed/id. The id is 11 letters, digits, underscores, or hyphens. A youtube.com address can start with www. or m., and a youtu.be or youtube-nocookie.com address with www. Vimeo addresses are vimeo.com/, www.vimeo.com/, or player.vimeo.com/video/, followed by the video's number. The number has no leading zero. An unlisted video's hash is letters and digits. It comes after the number or as h. When an address has both, they are the same. A start time is whole seconds, or hours, minutes, and seconds such as 1m2s. YouTube uses t or start, and Vimeo uses t or #t=. Each of v, h, t, and start appears at most once.

**The 3D layer.** A slide's models, shadow catchers, floors, and texts with a 3D `model` are drawn together as one image: the slide's 3D layer. The layer is placed where the backmost of them is in the slide's paint order. A hidden one counts too. Lights and the camera draw nothing in it, and they can be anywhere in the order. The layer is lit in linear light, tone-mapped with Khronos PBR Neutral at an exposure of 1, and written in sRGB. sRGB is the color space of the slide's flat colors. Before tone mapping, a directional light of intensity 1 lights a white surface that faces it to white. A point, spot, or area light falls off with the square of the distance in meters. A camera's lens is measured on a 36 mm film across the slide's longer side. It is the same as Blender's Sensor Fit Auto. The distance at which the slide shows at full size is at least 1 canvas unit. It sets the field of view, a camera's default z, and a tilted group's perspective. The 3D layer draws nothing nearer to the camera than 1 canvas unit. A World with no color lights the layer at the World's intensity with `environments/studio.hdr`. That file is an equirectangular Radiance HDR file whose SHA-256 is ce14a3984f83a8d231cad84cddc9ede84c73743d6d7956daf209f62e1afd1282.

**Model files.** A model's file is binary glTF 2.0, or a later 2.x, that contains everything it uses. Its one buffer is its BIN chunk. Each texture's image is a PNG, a JPEG, or a WebP, in that chunk or in a data: URI. It can use EXT_texture_webp, KHR_materials_anisotropy, KHR_materials_clearcoat, KHR_materials_dispersion, KHR_materials_emissive_strength, KHR_materials_ior, KHR_materials_iridescence, KHR_materials_sheen, KHR_materials_specular, KHR_materials_transmission, KHR_materials_unlit, KHR_materials_volume, KHR_mesh_quantization, KHR_texture_transform, and KHR_xmp_json_ld. A file that requires any other extension is refused. A file that uses KHR_draco_mesh_compression, EXT_meshopt_compression, KHR_meshopt_compression, KHR_texture_basisu, or EXT_mesh_gpu_instancing is refused too. Any other extension it uses is ignored. A model's own lights are ignored too. A skinned vertex moves with at most four joints. Its joints and their weights are in its `JOINTS_0` and `WEIGHTS_0`. No other set is read. A model with a primitive that has a second set, `JOINTS_1`, is refused on import. A model's node trees are at most 256 nodes deep. A mesh counts once for each node that draws it. A model then has at most 65,536 primitives, 65,536 skin joint copies, and 1,048,576 morph weights. Each target and each rest weight is a morph weight. Its buffer views together, and its accessors' values together, fit in its BIN chunk. A sparse accessor's values count in full. Each primitive of the model's meshes is counted once. The morph targets then use at most 256 MiB: 16 bytes for each vertex and target, 32 with normals, and 48 with colors. Each image is counted once for each sampler. The textures then decode to at most 268,435,456 pixels.

**Materials and nodes.** A material named `color:` followed by a color role, such as `color:accent`, uses that role's color in the slide's scheme as its opaque base color. If the scheme doesn't have the role, the material uses the file's color. A number Blender adds to a copied material's name, such as `.001`, is ignored. A node whose `extras.markdownpoint` has `"cast-shadow": false` casts no shadows. Nothing under it casts shadows either. An animation whose `extras.markdownpoint` has `"loop": "repeat"` is an Action made to repeat: a clip added for it repeats. A key that names a node, such as `parent-node`, can name any node of the file. That includes a skin's joint. The name follows the rule the cue record gives for a clip's Action. An unnamed node is named Node followed by its number in the file. The file's first node is number 1.

**Path data.** The path data of a path, a text path, a mask, or a motion path has at most 2,097,152 characters and 8,192 points. A point is where a contour starts or a segment ends. Each line and curve has one. A move has one too. A move has none when another move follows it at once, or when it ends a path that has other points. An arc has one for each of the fewest pieces of at most a quarter turn that it divides into. An arc that ends where it starts has none. An arc is read as one cubic Bézier curve for each of those pieces, and the pieces turn equally. On a circle, a piece that turns θ has handles 4 ÷ 3 × tan(θ ÷ 4) of the radius long. An ellipse's pieces are a unit circle's, scaled by its two radii and turned by its rotation. Each point and handle, once made absolute, is a finite number. When a contour of more than two points closes and its last point lies on its start, that last point isn't counted. The close draws that segment.

**Pieces.** A paragraph includes the bullets nested under it. Words are split at Unicode's word boundaries for the presentation's `locale`. A word includes the punctuation that touches it. Punctuation that touches two words goes with the earlier word. So “Hello, world! (yes) e-mail” is five pieces. A character is one grapheme cluster. Characters are counted as typed before `case` changes them. A space counts as a piece only with `spaces`, and a line break never does. With delivery `by-paragraph`, a paragraph that isn't named by a cue is shown from the start, and a text with a `text-path` enters all at once.

**Turns.** Pieces start one interval apart in their order. Each piece moves for `spread` intervals. By word or by character, each paragraph and heading that has a piece gets a turn. The turns go in reading order, or in reverse with `backward`. Each turn plays the order on its own: from its own middle or with its own shuffle. With no pause, a turn starts one interval after the last piece of the turn before it starts. By paragraph, the order runs over the paragraphs, and paragraphs that start together share one turn. `pause` applies only between turns. For N pieces, `progress` runs evenly over N − 1 + `spread` intervals. With a `pause` above 0, it runs over `pause` + `spread` − 1 more intervals before each turn except the first. With `center-to-ends` or `ends-to-center`, two pieces that are equally far from the middle start together. When the order runs over n pieces, their starts are spread evenly over n − 1 intervals. With only two pieces, they start one after the other.

### <a id="3d"></a>3D

#### space-position

A point in the 3D space in canvas units. The x axis runs right from the slide's left edge, the y axis runs up from its bottom edge, and the z axis runs toward the viewer. The slide is at z 0. The axes are right-handed. glTF and three.js use the same axes. A parented object's position is in its parent's space.

Where: `objects[].position` of a model, a light, the camera, or a shadow catcher, `objects[].point-of-interest`

| key | required | values | description |
| --- | --- | --- | --- |
| `x` | except the camera's | −1 × 10¹⁸ to 1 × 10¹⁸ canvas units | How far across. |
| `y` | except the camera's | −1 × 10¹⁸ to 1 × 10¹⁸ canvas units | How far up. |
| `z` | except the camera's | −1 × 10¹⁸ to 1 × 10¹⁸ canvas units | How far toward the viewer. |

**Parented objects.** A parented model, light, shadow catcher, or camera has its position and point of interest in its parent's space, through its `parent-inverse` if it has one. A parented shadow catcher's width and height are in its parent's space too. The object's world matrix is its parent's world matrix, times its parent-inverse, times its own position, rotation, and scale. When `parent-node` names a node of the parent, that node's world matrix is used in place of the parent's. Each matrix acts on a column of x, y, z, and 1 to its right: `world = parent × parent-inverse × local`. Blender composes a Parent Inverse the same way. The object's own constraints apply after that. A parented camera turns with its parent but never scales with it. A camera with a point of interest also banks with its parent.

**The camera.** The camera's position can leave out any part. When x or y is left out, the camera is centered on the slide on that axis. When z is left out, the camera is where the slide shows at full size. Every point of interest has all three parts. That includes the camera's.

#### space-rotation

A 3D object's rotation about its origin, in the 3D space's axes: x right, y up, and z toward the viewer. It is in degrees, or a quaternion in quaternion mode.

Where: `objects[].rotation` of a model, a light, the camera, or a shadow catcher

| key | required | values | description |
| --- | --- | --- | --- |
| `x` | yes | −8589934592 to 8589934592 | Degrees about x, or a quaternion's x. |

| `z` | yes | −8589934592 to 8589934592 | Degrees about z, or a quaternion's z. |
| `w` | with rotation-mode quaternion | −8589934592 to 8589934592 | A quaternion's w. It is used in quaternion mode only. |

**Degrees.** In degrees, the object turns in Cinema 4D's HPB order. First, it turns by the heading about y. Then it turns by the pitch about its own x. Then it turns by the bank about its own z. In three.js, this is Euler order YXZ. Seen along its axis toward the origin, each rotation is counterclockwise. With a positive z, the object turns counterclockwise on the slide. With a positive x, its top tilts toward the viewer. With a positive y, its left side comes forward. A flat object's `rotation` and a group's `tilt.x` turn the other way. The slide's y axis runs down. A step animates each axis's rotation on its own as `rotation.x`, `rotation.y`, or `rotation.z`. One keyframe can spin the object more than once. In its glTF file, a model faces +z. At zero rotation, it faces the viewer. At zero rotation, a light shines into the slide along its own −z, and the camera looks along its own −z. Both have their own y up.

**Quaternions.** In quaternion mode, the rotation has w, x, y, and z. It is the same rotation as glTF's quaternion but has w first. Each part is read to six decimal places. After that, the quaternion's length doesn't change the rotation. A quaternion whose parts all read as 0 is refused. Each keyframe of `<object>.rotation` is such a quaternion. Between two keyframes, the object turns the shorter way round at the pace of the keyframe's interpolation. At exactly a half turn, it turns toward the keyframe's quaternion as written.

**`relative-to-target`.** Blender's Copy Location Offset works the same way.

#### drift

#### text-model

A text's 3D model in one of two forms. With an `extrusion`, MarkdownPoint builds the words' letters into a model. With a `file`, the model is a GLB that a program built, and `built-from` is the fingerprint of what it was built from. One unit of the model is one em of the text's size. Its origin is on the first line's baseline at the left of the text's column. The model moves, turns, and scales with the text's frame. A text in a group stays flat. Its depth scales by the square root of the text's x scale times its y scale. A step's clips play the Actions of a GLB `file` the same way they play a model's. An `extrusion` has no Actions.

Where: `objects[].model` of a text

| key | required | values | description |
| --- | --- | --- | --- |
| `built-from` | with file |  | The fingerprint of what the GLB was built from. The reference gives the rule. A reader that doesn't know the rule treats the model as out of sync. |
| `extrusion` | unless it has file | 0 or more ems | The depth and bevel MarkdownPoint builds the words' letters to in ems. With an empty record, the letters are built to the defaults. |
| `file` | unless it has extrusion |  | The path in the presentation's folder of the GLB a program built from the words. |

**Flat effects.** While a text's model draws, its `drop-shadow`, `text-stroke`, `text-stroke-weight`, and `blend-mode` don't apply. They stay in the file and apply again when the text draws flat.

**The model's letters.** A text's model has its letters under one node. That node is its scene's only root, and it draws no mesh of its own. Each child of that node is a letter. The child draws the letter itself or through the nodes under it. A letter's `extras.markdownpoint.characters` lists the characters it draws. Each is `[block, start, end]`. `block` is the block's index in reading order. The first block's index is 0. The blocks are the text's paragraphs and headings, its code blocks, and its kept Markdown. An empty paragraph or heading counts too. `start` and `end` are UTF-16 offsets in that block's text, and the letter draws the characters from `start` up to but not including `end`. In that text, the fields are filled in, and each hard break is one character. A letter's `extras.markdownpoint.box` is the box the letter is laid out in on the slide. It is `[left, bottom, right, top]` in the model's units. Y is up. The node with the letters lists the text's paragraphs in its `extras.markdownpoint.paragraphs`. Each is `[paragraph, left, bottom, right, top]`. `paragraph` is the paragraph's number in reading order among the text's paragraphs, headings, and list items. The first paragraph's number is 0. The four numbers after it are the box the paragraph is laid out in. A list item's box includes its nested list. A letter enters and exits with the pieces its first character is in. A letter with no `characters` stays where it is. A model laid out any other way enters and exits as one piece, about the center of its text's frame. In a model of the word Hi, the JSON has this, besides its meshes and the rest glTF needs:

```json
{
  "scene": 0,
  "scenes": [{"nodes":[0]}],
  "nodes": [
    {"children":[1,2],"extras":{"markdownpoint":{"paragraphs":[[0,0,-0.21,0.97,0.88]]}}},
    {"mesh":0,"extras":{"markdownpoint":{"characters":[[0,0,1]],"box":[0,-0.21,0.73,0.88]}}},
    {"mesh":1,"extras":{"markdownpoint":{"characters":[[0,1,2]],"box":[0.73,-0.21,0.97,0.88]}}}
  ]
}
```

**`built-from`.** A text model's `built-from` is `markdownpoint/text-model/`, its rule's number, `:sha256:`, and 64 lowercase hex digits. By rule 14, it is `markdownpoint/text-model/14:sha256:` followed by the SHA-256 of its text's record. The record is a JSON object written in UTF-8 according to RFC 8785's JSON Canonicalization Scheme. Its keys are sorted by their UTF-16 code units, and it has no spaces. Each number and string in it is written the way ECMAScript writes it. A negative zero is written 0. The record has only what the presentation's folder states. Each key and value is spelled as the files spell them. A key with nothing in it is left out. An em is the text's size. Each length in ems is worked out in IEEE 754 double precision. ECMAScript's numbers are of this kind. A length in canvas units is first divided by the text's size. The length in ems is then multiplied by 1000, rounded to a whole number as ECMAScript's `Math.round` rounds it, and divided by 1000. `Math.round` rounds a half toward positive infinity.

- `content`: the text's words as its block reads them in the .md file. Outside code, an escape's backslash is left out. A line feed, U+000A, ends every line except the last. The blank lines before and after the words are left out. Blank lines that are code stay in. The blank lines that are code are given in `blank-line`. A code block that's never closed ends with a line that closes it: its fence's indent and its run of backticks or tildes. Where a paragraph id repeats, the words match a model only once MarkdownPoint has saved them with each id once.
- `fields`: each field the words show that has a value. The key is the field's name, and the value is what MarkdownPoint fills in.
- `locale`: the presentation's `locale`, or en-US if the presentation has none.
- `style`: the text's `font-family`, `italic`, `font-weight`, `color`, `align`, `text-direction`, `line-height`, `tracking`, `case`, `bullet-styles`, `paragraph-spacing`, `list-indent`, `column-count`, `column-gutter`, `tabular`, and `kerning`. They come from the text, its text style, and their defaults. `tracking`, `paragraph-spacing`, `list-indent`, and `column-gutter` are in ems. A text in one column has no `column-gutter`.
- `marks`: each mark in the text style's `marks` and the mark's keys. Bold and a highlight are never lighter than the text. The rule is in the text style's `marks`.
- `width`: the frame's width in ems, unless the text's width grows to its words.
- `text-path`, `path-offset`, and `height`: for words along a path, the path, its offset, and the frame's height in ems.
- `column-height`: in more than one column, the frame's height less the text's `padding-top` and `padding-bottom`. It is in ems.
- `ligatures`: false where the text's characters travel apart. Each is then shaped on its own. They travel apart when the text's entrance or exit is by `character`, or when a `carry-over` transition that matches characters carries the text.
- `size`: the text's size in canvas units, when its words include a quote or a horizontal rule. A quote's inset and a rule's line have a fixed size in canvas units, whatever the text's size.
- `fonts`: each font role the words use by its name. That includes the roles of headings and code. Each has the `family` the theme names for it. Where the theme has its own faces for the family, it also has the SHA-256 of each of its `files` in lowercase hex. They are in the order `font-files` lists them.
- `optical-sizes`: each such role whose family has an optical-size axis by its name. It has one list for each of the family's axes. The axes are ordered by their least size, then by their greatest, and each is listed once. A list has each size the role's words are set at, once, from the smallest: the text's size, a heading's size, and code's size. Each size is worked out in double precision and limited to the axis's range. Then it is rounded to six decimal places the way ECMAScript's `Number(x.toFixed(6))` rounds it. So two sizes past the axis's end are both at that end. An embedded face's axis is its file's `opsz`. A family whose faces have several axes has a list for each. The bundled families' axes are Inter 14 to 32, Source Serif 4 8 to 60, and Fraunces 9 to 144.

For example, take the words "Ship **it**." at 72 canvas units and weight 700 in a frame 900 wide. The theme's display role is Inter. Their record is `{"content":"Ship **it**.","fonts":{"display":{"family":"Inter"}},"locale":"en-US","marks":{"highlight":{"font-weight":700}},"optical-sizes":{"display":[[32]]},"style":{"align":"left","bullet-styles":["disc","circle","square"],"case":"none","color":"text","column-count":1,"font-family":"display","font-weight":700,"italic":false,"kerning":"metrics","line-height":1.05,"list-indent":1.25,"paragraph-spacing":0.5,"tabular":false,"text-direction":"ltr","tracking":0},"width":12.5}`. Their built-from is `markdownpoint/text-model/14:sha256:9ee4d74678156d64934d50054c8a9763db952449b72382d9e706f7c736c6115d`.

Rounded this way, a `tracking` of −0.0625 is −0.062 in the record. With a text size of 72 canvas units, a frame 72.036 wide is 1.001 ems wide. A frame 900.036 wide is 12.5 ems wide. In double precision, 900.036 ÷ 72 is just under 12.5005. It rounds down.

#### text-model-extrusion

How MarkdownPoint builds a text's letters into its model. Each length is in ems of the text's size. The default depth is 0.2, and the default bevel is 0.02.

Where: `objects[].model.extrusion`

| key | required | values | description |
| --- | --- | --- | --- |
| `bevel` |  | 0 or more ems | How far the letters' edges are rounded in ems. At 0, they are sharp. |

### <a id="steps"></a>Steps and keyframes

#### step

One step: the keyframes and cues that a click or the previous step sets off. Its times and the times of its keyframes and cues are in seconds. They are rounded to six decimal places.

Where: `slides.<id>.steps[]`, `compositions.<id>.steps[]`

| key | required | values | description |
| --- | --- | --- | --- |
| `id` | yes |  | The step's id, unique on its slide or composition. |
| `cues` |  |  | Events at set times in the step by id. They are read by their time, then by their id. Each shows a paragraph, starts an audio object, a video, or a web video, or plays a clip. |
| `curves` |  |  | The step's animation. Each curve is under an "object.parameter" key such as card.opacity. |
| `loop-start` |  | 0 to 4294967296 seconds | The time in seconds into the step that it loops back to while waiting for a click. It is before the later of its `min-duration` and its keyframe and cue times. A paragraph's entrance doesn't count. |
| `min-duration` |  | 0 to 4294967296 seconds | The least time the step lasts in seconds. A later keyframe, cue, entering paragraph, or repeated copy makes it longer. Without it, or at 0, the step lasts as long as what is in it. |
| `name` |  |  | The step's name: one line that isn't blank and has no control characters. |
| `repeat-count` |  | whole numbers, 2 to 64 | How many times the step plays before it completes. Without it, the step plays once. |
| `start` |  | with-previous, after-previous | When the step starts: with the previous step, or after it ends. Without it, the step starts a new click. |

**Clicks.** A step has no delay of its own. A keyframe's move begins at its `start`. When two steps of one click animate one parameter, the earlier step's motion shows until the later step's first move begins. That move starts from where the earlier motion is then. A first keyframe at the value the parameter has as its step starts doesn't move until its time. One with `interrupted` or a `path` moves from the step's start. A move that ends where it starts has no path. The object stays where it is. A `start` at or before the previous keyframe, or on a key or keyframe that doesn't move, is [ignored](#keyframe). A first step that starts by itself plays after the slide's transition. With a scroll, the next slide's first step plays along with it. The step's `start` doesn't change that. A click plays when any of its steps plays. A step that has keyframes or cues has no click of its own when each keyframe names an object the slide doesn't have or a hidden object, and each cue names such an object or a video, web video, or audio that doesn't start on click. Such a step stays in the file. An object is hidden when its own `visible`, or that of a group above it, is false. A step with no keyframes and no cues has its own click. A step that repeats plays alone on its click. A file that breaks this is read with a warning, and the step doesn't repeat. When a step loops while it waits, the step after it starts when the loop's first pass ends. The loop plays on under it.

#### curve

One parameter's animation in a step: its keyframes and what happens after the last one. A position can also be keyed as one point. `frame.xy` and `translation.xy` have {x, y}, and `position.xyz` has {x, y, z}. Each of their keyframes has every part. A step keys a position either as a point or by its parts, not both. A step that keys both is read with a warning, and the point plays. An initial value sets each part on its own.

Where: `steps[].curves["<object>.<parameter>"]`

| key | required | values | description |
| --- | --- | --- | --- |
| `keyframes` | yes |  | The keyframes by id, one or more. They are read by their time, then by their id. |
| `loop` | with loop-keyframe | repeat, ping-pong | How it loops after its last keyframe until the step ends. With `repeat`, it replays from `loop-keyframe` to the last. With `ping-pong`, it plays that back and forth. Without it, it plays once. |
| `loop-keyframe` | with loop |  | The id of the keyframe the loop starts at. If the keyframe has a `start`, the loop begins with its move. If it names no keyframe of the curve, the first is used. |

**Loops.** A curve that repeats is at its last keyframe at the moment it starts over.

#### keyframe

One keyframe: a value a parameter reaches at a time. Its id is unique in its step among its keyframes and cues. Two keyframes of one parameter at one time are read with a warning, and the one with the later id plays. A `start` at or before the previous keyframe is ignored. On the first keyframe, a `start` of 0 is ignored. A `discrete` key and interpolation `hold` have no move. A `start` on either is ignored. A keyframe whose value is `null` clears the whole parameter. The parameter's text style or default then shows. It can't clear a part of a key, a point, `visible`, `rotation`, `scale`, a constraint's strength, `shape-type`, `icon`, or `geometry`.

Where: `steps[].curves["<object>.<parameter>"].keyframes.<keyframe id>`

| key | required | values | description |
| --- | --- | --- | --- |
| `time` | yes | 0 to 4294967296 seconds | When the parameter reaches the value. It is in seconds into the step. |
| `value` | yes |  | The value. It is written as the parameter is. It can be `null` to clear the whole parameter. |
| `exponential-scale` |  |  | Whether a scale move changes by a steady ratio. A zoom then looks even. Its pace is even from or to 0, or across it. It applies only to `scale`, `scale.x`, `scale.y`, `scale.z`, and `crop.scale`. |
| `interpolation` |  | linear, ease-in, ease-out, ease-in-out, smooth, hold, anticipate, overshoot, anticipate-overshoot, bounce, elastic, or a record | How the value reaches the keyframe: gradually, or at once with hold. It is a named curve, a named curve with its settings, a cubic Bézier, or a spring. The default is linear. |
| `interrupted` |  |  | The longer move this keyframe interrupts. Up to the keyframe's time, the motion follows that move toward its `value`. Then the parameter has the keyframe's own `value`. |
| `oscillate` |  |  | A wave added to the value from this keyframe to the next, or to the step's end. On a looping curve, the wave plays again each time around. |
| `path` |  |  | A curved motion path for the move into the keyframe. Only a point keyframe can have it. |
| `start` |  | 0 to 4294967296 seconds | When the move into the keyframe begins. It is in seconds into the step. It must come before `time`. Without it, the move begins at the previous keyframe, or at 0 for the first keyframe. |

**How a value moves.** A color moves in sRGB with premultiplied alpha. So a color that fades out to a transparent one keeps its own color as it fades. A color role moves as the slide's scheme colors it. A gradient moves into a gradient of its own type with as many stops. A radial gradient also needs the same `shape`. A linear gradient with a `line` needs another with a `line`. Each stop moves into the stop at its place, and the angle, line, or center moves into the other gradient's. Between any other two paints, such as a color and a gradient, the first paint shows until the keyframe. Each point of the path data in a `geometry`, `mask`, or `text-path` moves to the point at its place when the two paths' contours have as many points and are closed alike. The contours are paired in order. A curve's handles move to the handles at their place. A straight segment moves as a curve whose handles sit on its points. Any other two paths still morph, but the format doesn't set the shapes between them. The morph still starts exactly at one keyframe's path and ends exactly at the next one's. To set the shapes between two paths, give each pair of contours as many points, closed alike.

#### keyframe-interrupted

The move a keyframe interrupts: where it was going and when it would have ended.

Where: a keyframe's `interrupted`

| key | required | values | description |
| --- | --- | --- | --- |
| `value` | yes |  | Where the move was going. |
| `end` | yes | 0 to 4294967296 seconds | When it would have ended. It is in seconds into the step and at or after the keyframe's time. |

#### keyframe-path

A curved motion path for the move into a point keyframe in the move's own coordinates. 0 0 is where the move starts, and 1 0 is where it ends. Seen on the slide, its y points 90 degrees clockwise from its x. SVG's y does the same. So for a move to the right, a negative y bends the path up the slide.

Where: a keyframe's `path`

| key | required | values | description |
| --- | --- | --- | --- |
| `geometry` | yes |  | The path: SVG path data from the move's start at 0 0 to its end at 1 0. It is one open contour of 2 to 8,192 points. It has at most 2,097,152 characters. |
| `orient` |  |  | Whether the object turns to face along the path. |

**Along the path.** The object moves along the path at the pace of the keyframe's interpolation. The interpolation sets how much of the path's length the object has traveled. Past either end, it moves on in the path's direction at that end. A 3D position's path bends its x and y, and its z moves straight. With `orient`, a flat object and a text with its model turn with the path's tangent. A model turns about its parent's y to face where it travels across x and z. No other 3D object turns.

#### keyframe-oscillate

A wave added to a parameter's value. Only a parameter with a single number that animates smoothly can have one. `volume` never can.

Where: a keyframe's `oscillate`

| key | required | values | description |
| --- | --- | --- | --- |
| `amplitude` | yes | any number | How far the value swings either way in the parameter's own unit. The value stops at the end of the parameter's range. |
| `frequency` | yes | more than 0 cycles a second | How many full cycles each second. |
| `phase` |  | −8589934592 to 8589934592 degrees | Where in its cycle the wave starts. A cycle is 360 degrees. The default is 0. |
| `seed` |  | whole numbers, 0 to 4294967294 | The noise seed. A seed picks one wave. The default is 0. |
| `wave-shape` | with seed | sine, triangle, square, sawtooth, noise | The wave's shape. With a seed, it must be `noise`. The default is sine. |

**Waves.** At a phase of 0, a sine, a triangle, and a sawtooth start at 0 and rise. A square starts at 1. Halfway through each cycle, a square falls to −1, and a sawtooth falls from 1 to −1. A noise wave wanders smoothly at random. It passes through 0 at the start of each cycle and never repeats. The format doesn't set a noise wave's shape. On a ping-pong's way back, a wave plays backward. On a looping curve, the last keyframe's wave doesn't play.

#### cue

Cinema 4D's Motion Clip works the same way. A text built from an `extrusion` has no Actions. A clip on it plays nothing and causes a warning.

Where: `steps[].cues.<cue id>`

| key | required | values | description |
| --- | --- | --- | --- |
| `time` | yes | 0 to 4294967296 seconds | When it happens. It is in seconds into the step. |
| `type` | yes | paragraph, play, clip | What it does. A `paragraph` cue shows a paragraph. A `play` cue starts an audio object, a video, or a web video. A `clip` cue plays an Action of a model or a 3D text. |
| `object` | yes |  | The id of the object it acts on: for a clip, a model, or a 3D text. |
| `action` | with type clip |  | The name of the Action that a clip plays. An unnamed Action is named Animation followed by its number in the file. The file's first Action is number 1. |
| `blend-in` |  | 0 or more seconds | How long the clip takes to blend in fully over the model's current motion. Without it, the clip is fully blended in from its start. |
| `clip-scale` |  | more than 0 | How much longer a clip's Action plays than its file says. 2 is half speed, and 0.5 is double. Maya's Clip Scale works the same way. The default is 1. It isn't used by a model's clip with a `stride`. |
| `clip-trim` |  | 0 or more seconds | The part of the Action that plays: a start and an end in seconds into the Action. |
| `loop` |  | repeat | With `repeat`, the Action plays again from its start each time it ends. Without it, the Action plays once. |
| `paragraph` | with type paragraph |  | The id of the paragraph that appears. The id is in the `<!-- id: … -->` that ends the paragraph's last line. A reader warns when no paragraph of the text has the id. |
| `stride` |  | more than 0 meters | How far the model travels per cycle of its Action in the GLB's meters. The Action's timing then follows the model's travel. It doesn't apply to a 3D text's clip. |

**A model's pose.** Before a model's first clip starts, it shows that clip's first trimmed pose. With `blend-in`, it shows its rest pose and blends from there. A clip that plays once holds its last trimmed pose. Each later clip changes only the node properties its Action animates. Other properties keep the earlier clips' results or the rest pose.

**Action names.** A clip names an Action by its name in the file, matched exactly. An Action with no name, or an empty name, is named Animation followed by its number in the file. The file's first Action is number 1. An Action can have the same name as an earlier one, or a generated name that is already taken. It then gets the first of name 2, name 3, and so on that isn't taken yet. The names the file gives are reserved first. So Walk, Walk, Walk 2 are read as Walk, Walk 3, Walk 2.

#### parameters

Animation parameters that aren't object keys. Each is written after its object's id and a dot. Together they make one key, such as "card.opacity". The object table lists each key's own parameters.

Where: `initial["<object>.<parameter>"]`, `steps[].curves["<object>.<parameter>"]`

| key | required | values | description |
| --- | --- | --- | --- |
| `scale` |  | 0 to 511 | How far a group, an instance, or a chart scales about its anchor point. It is one number. They have no `scale` key. |
| `translation.x` |  | −65536 to 65536 canvas units | How far the object is moved right from its frame in canvas units. |
| `translation.xy` |  |  | `translation.x` and `translation.y` as one point, {x, y}. A move along a motion path keys them together this way. A step that keys it can't also key either part. |
| `translation.y` |  | −65536 to 65536 canvas units | How far the object is moved down from its frame in canvas units. |

**What can have a parameter.** A parameter inside an object's record, such as `enter.progress` or `repeater.rotation`, needs that record on the object. A table can't have a parameter that lays out its words. A text box that grows to fit its text can't have one either. That rules out their width, a table's columns or its header row and column, and their typography, such as the font, size, spacing, inset, or padding.

#### interpolation

Named interpolations: how a value changes over a move, gradually or at once. Transitions can use linear, ease-in, ease-out, and ease-in-out. A keyframe's or a text's interpolation can instead be a named curve with its settings. That includes a cubic Bézier of its own.

Where: a keyframe's, a transition's, and a text's `interpolation`

| name | required | values | description |
| --- | --- | --- | --- |
| `anticipate` |  |  | Pulls back before it moves. |
| `anticipate-overshoot` |  |  | Pulls back first, then passes the keyframe's value and settles back on it. |
| `bounce` |  |  | Falls onto the keyframe's value and bounces off it three times. Each bounce is lower. It never passes the value. Its bounciness is 0.5. |
| `ease-in` |  |  | Starts slowly from the previous keyframe. CSS's ease-in works the same way. |
| `ease-in-out` |  |  | Starts slowly and ends slowly. CSS's ease-in-out works the same way. |
| `ease-out` |  |  | Slows down as it reaches the keyframe. CSS's ease-out works the same way. |
| `elastic` |  |  | Springs past the keyframe's value and swings into it. Each swing is smaller. |
| `hold` |  |  | Keeps the previous value until the keyframe's time, then jumps. |
| `linear` |  |  | Moves at a constant speed. |
| `overshoot` |  |  | Passes the keyframe's value and settles back on it. |
| `smooth` |  |  | Starts and ends gently, over a shorter part of the move than ease-in-out. |

**The named curves.** `ease-in`, `ease-out`, and `ease-in-out` are CSS's easing functions of those names. In CSS's cubic-bezier() form, `smooth` is (0.25, 0, 0.75, 1). Let b be the `back`. Its default is 1.70158. Then `anticipate` is (0.333333, 0, 0.666667, −b ÷ 3), and `overshoot` is (0.333333, (b + 3) ÷ 3, 0.666667, 1). They are Robert Penner's back in and back out. `anticipate-overshoot` is his back in and out, `elastic` is his elastic out, and `bounce` is his bounce out at a bounciness of 0.5. Blender's Back, Elastic, and Bounce are the same curves.

#### keyframe-interpolation

An interpolation with its settings: how far `anticipate`, `overshoot`, or `anticipate-overshoot` pulls back or swings past, an elastic's swing, a bounce's bounciness, a spring's damping ratio, or a cubic Bézier's two handles. The handles' keys are named the way CSS's cubic-bezier() names its four numbers. A named curve with no settings is written as just its name. A cubic Bézier that is the same as a named curve is written as that named curve's name too.

Where: a keyframe's or a text's `interpolation` written as an interpolation with its settings

| key | required | values | description |
| --- | --- | --- | --- |
| `type` | yes | anticipate, overshoot, anticipate-overshoot, elastic, bounce, spring, cubic-bezier | Which interpolation it is: a named curve, a cubic Bézier, or a spring. |
| `amplitude` |  | 0 or more | The size of an elastic's swing in multiples of the move. The default is 1. |
| `back` |  | 0 or more | How far `anticipate`, `overshoot`, or `anticipate-overshoot` pulls back or swings past. Robert Penner's back curves use it the same way. The default is 1.70158. |
| `bounciness` |  | 0 to 1 | A bounce's rebound speed in fractions of its landing speed. At 0, it lands dead. At 1, it rebounds to its height each time. The default is 0.5. |
| `damping-ratio` | with type spring | 0.3 to 1 | How strongly a spring is damped. At 1, it doesn't swing past its keyframe. Less damping swings further. |
| `period` |  | more than 0 seconds | How long one swing of an elastic lasts. The default is 0.3 of the length of the move into the keyframe. |
| `response` |  | more than 0 seconds | The spring's natural period. A shorter one springs faster. Without it, the spring settles by the keyframe's time. |
| `x1` | with type cubic-bezier | 0 to 1 | The time of a cubic Bézier's first handle in fractions of the move. |
| `x2` | with type cubic-bezier | 0 to 1 | The time of a cubic Bézier's second handle in fractions of the move. |
| `y1` | with type cubic-bezier | any number | The value of a cubic Bézier's first handle in fractions of the change. It can be below 0 or above 1. The move can then go past an end. It stops at the end of the parameter's range. |
| `y2` | with type cubic-bezier | any number | The value of a cubic Bézier's second handle in fractions of the change. It can be below 0 or above 1. The move can then go past an end. It stops at the end of the parameter's range. |

**Springs.** A spring's `response` is its natural period, in seconds: how long one swing would take with no damping. Its `damping-ratio` d is how strongly it is damped. SwiftUI's response and dampingRatio mean the same. A ratio of 1 is critical damping. With damping, each swing lasts the response divided by √(1 − d²). At a ratio of 0.3, that is about 1.05 times the response. A Position constraint's `response` and `damping-ratio` mean the same. A spring keyframe reaches its value at its time. The format doesn't set the motion between beyond its response and damping ratio. A SwiftUI spring keyframe with no duration lasts for its spring's settling duration.

## <a id="schemas"></a>JSON Schemas

Each JSON file has a draft-07 JSON Schema in [schemas/v1.0](schemas/v1.0/). The schema is named for the `type` the file states. The folder is named for the version, 1.0. Each minor version's schemas are in a folder of their own. A published folder never changes. A schema's `$id` is https://markdownpoint.com/format/schemas/v1.0/ followed by its file name. Refer to a schema by its `$id`. Its `definitions` are its own and may change. A schema checks a file's keys, their values, and the keys a record needs. It refuses a key of a later minor version. MarkdownPoint reads such a key. MarkdownPoint also reads a number to six decimal places before checking it. A schema checks the number as written. The schemas' patterns are ECMA 262 regular expressions, the dialect draft-07 names, and they use lookahead. A validator whose engine has no lookahead, such as RE2, can't compile them.

MarkdownPoint also checks what a schema doesn't:

Every JSON file:

- A JSON object never has the same name twice. A file that does is refused.

[presentation.schema.json](schemas/v1.0/presentation.schema.json):

- A locale names each variant once.
- Every file a background or an object names is in the presentation's media or generated folder.
- A composition's id isn't also a slide's id. No composition contains itself, directly or through another. The instance that closes the loop draws nothing and causes a warning. A composition's text has no `model`.
- A composition's controls have unique ids. A number control's minimum is below its maximum. Its default is from its minimum to its maximum. A choice control's options have unique ids. Its default is one of their ids.
- Only the camera and the World have the ids `camera` and `world`.
- A slide's or a composition's objects have unique ids. None of its own objects has an id that its overrides change.
- A 3D object's rotation in degrees has no w. In quaternion mode, it has w, x, y, and z. A quaternion's parts don't all read as 0.
- A web video's address names a video.
- A path's `geometry`, an image's `mask`, and a text's `text-path` are well-formed SVG path data that starts with a move. Each point and handle, once made absolute, is a finite number. An icon's `icon` names an icon in the bundled Lucide set. A video's or an audio object's `media-trim` ends after it starts. An object's constraints have unique ids.
- A text's enter or exit can set `spaces` to true only when `based-on` is `character`. It has a `seed` only when `order` is `random`. An enter with a `delivery` has `based-on` set to `paragraph`. Its `order`, `spread`, `pause`, and `progress` are then at their defaults.
- A video's file, a shape's `shape-type`, and an icon's `icon` are required unless a composition's control binds them. A binding is on a composition's own object and names one of its controls, of a type that can set the key. A value written beside a bound key isn't read and causes a warning. A save writes the binding alone. A control can also bind one number part of a record, such as a group's `tilt.x`. That part's value stays in the record and causes no warning. While the part is bound, the control's value is used in its place.
- An override's key and value apply only to an inherited object that can have them. Other overrides are kept but ignored, and cause a warning.
- An override that makes a growing text box's `frame.x` or `frame.y` name another point also gives that x or y. If it doesn't, the change is kept but ignored, and causes a warning.
- An animated parameter is one its object has. A keyframe's value is a valid value of that parameter. A name or a value that isn't valid for any object's parameter is refused. One that is valid elsewhere but not on its own object is ignored with a warning.
- Only a keyframe of `scale`, `scale.x`, `scale.y`, `scale.z`, or `crop.scale` can have `exponential-scale`. Only a parameter of one number that moves smoothly can have `oscillate`. `volume` only fades and can't have it. An `initial` value can't set a point parameter, such as `frame.xy`. It can set the point's parts.
- A slide's or a composition's steps have unique ids. A step's keyframes and cues have unique ids among them all. A keyframe's move starts before its time. An interrupted move ends at or after the keyframe's time. Only a noise wave can have a seed.
- A step's `loop-start` comes before its end.
- A composition's steps have no cues. They have no `loop-start` either. Either one is ignored with a warning. With every pass counted, they last at most 4,294,967,296 seconds. Otherwise, the composition is read with a warning.
- Only a point keyframe can have a motion path. It is one open contour from 0 0 to 1 0. A clip's trim ends after it starts.
- A comment's words are well-formed Unicode.

[master.schema.json](schemas/v1.0/master.schema.json):

- A font family's name starts with a letter or a digit of any script. It has only letters, digits, spaces, periods, underscores, and hyphens. No two `font-files` keys name the same family. They are matched the same way `fonts` matches a family.
- A brand color a scheme names is one the brand has.
- The scheme named light is light, and the one named dark is dark.
- The words in `text` belong to the master's own text, table, chart, and shape objects.
- Guides have unique ids.
- Its objects pass the presentation's object checks.

[layout.schema.json](schemas/v1.0/layout.schema.json):

- The words in `text` belong to the layout's own text, table, chart, and shape objects.
- An image names a video only as a placeholder's sample. A placeholder names one file, not one per scheme.
- Its objects and overrides pass the presentation's object checks.

[theme-package.schema.json](schemas/v1.0/theme-package.schema.json):

- No two entries name the same file.

[version.schema.json](schemas/v1.0/version.schema.json):

- Nothing beyond its schema.

[style-library.schema.json](schemas/v1.0/style-library.schema.json):

- Nothing beyond its schema.

[image-generation.schema.json](schemas/v1.0/image-generation.schema.json):

- A prompt is in Unicode's composed form, NFC.
- An output has no more pixels than an image can have. It has the aspect ratio asked for.
