# MarkdownPoint file format reference

This reference lists every key in the files and what it does.

A presentation is a folder with two files at its root: `presentation.mdpoint` and `slides.md`. The names are fixed. Their case doesn't matter. `presentation.mdpoint` holds the presentation's theme, slides, and settings as JSON. `slides.md` holds the sections, the slides' order and text, and the speaker notes. The folder's name is the presentation's. Renaming the folder renames the presentation. Another .mdpoint file at the root, or another .md file whose name starts with the word slides, such as `slides 2.md` or a sync service's conflicted copy, stops the presentation from opening. MarkdownPoint names those files. The presentation doesn't open until one of each is left, under its fixed name. The presentation's themes are under themes/. Its other files are under media/ and generated/, as described below. Its saved versions are under versions/. Anything else in the folder is the author's own. MarkdownPoint never copies it.

Each key belongs to one category:

- **Theme**: type, color, layout, and effects
- **Motion and media**: time, motion, and media
- **Presentation**: what only a presentation has, such as step timing and slide transitions
- **File**: the file's own bookkeeping

An id is a lowercase letter, then lowercase letters and digits with single hyphens between them, such as title-card: `^(?:[a-z](?:[a-z0-9]|-(?!-))*[a-z0-9]|[a-z])$`. Slides and compositions share one set of ids. A document's id, a save stamp, and a theme's id in its master are lowercase UUIDs: `^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$`. A theme's key, the name of its folder in themes, is an id that every supported system can hold as a folder name. A name a theme gives is spelled as an id: a scheme, a color role, a brand color, a text style, a choice control's option, and a property a binding names. A layout's key is the name of its file: an id other than master and manifest that every supported system can hold as a file name. A font family is a letter or a digit in any script, then letters, digits, spaces, dots, underscores, and hyphens: `^[\p{L}\p{N}][\p{L}\p{N} ._-]*$`.

A file path is relative to the presentation's or the theme's folder, with / between names. A name isn't empty, `.`, or `..`, and doesn't start with a dot. It holds no backslash, <, >, :, ", |, ?, *, #, or control character, and doesn't end in a space or a dot. CON, PRN, AUX, NUL, COM1 to COM9, LPT1 to LPT9, COM¹ to COM³, and LPT¹ to LPT³ name no file, in any case and with any extension. A presentation's file is under media/ or generated/, other than a .json file under generated/, which records how an image was made. The author's files go under media/. MarkdownPoint writes what it makes under generated/: images made with AI, and 3D text models. The record names the file under generated/ that the image was first written to. It also names the SHA-256 digest of the image's bytes. Any PNG directly under generated/, or anywhere under media/, with those bytes is that image. A renamed or moved image keeps its record. A theme's file is anywhere in its folder but manifest.json, previews, and example at its root. An image's file ends in .png, .jpg, .jpeg, .gif, .webp, .svg, .avif, or .bmp. A video's ends in .mp4, .m4v, .mov, .webm, or .ogv. A sound's ends in .mp3, .m4a, .wav, .ogg, or .flac. A model's ends in .glb and holds binary glTF 2.0. An embedded font's ends in .eot. The case of an ending doesn't matter. A file reached through a symbolic link or an alias is never one of the presentation's files. Copy the file itself into the folder.

A link is an http or https URL with a host, a mailto: or tel: address, or slide: and a slide's id. It holds no spaces or control characters, and a URL holds no backslash. A link to anything else, or to a slide that isn't there, is kept and does nothing.

An online video's address is an https address of a YouTube or Vimeo video, with no user name, password, or port. YouTube's are youtube.com/watch?v=id, youtube.com/embed/id, /shorts/id and /live/id, youtu.be/id and youtube-nocookie.com/embed/id, where the id is 11 letters, digits, underscores, or hyphens. A youtube.com address may also start with www. or m., and youtu.be and youtube-nocookie.com with www. Vimeo's are vimeo.com/ or www.vimeo.com/ and the video's number, which has no leading zero, and player.vimeo.com/video/ and the number. An unlisted video's hash, letters and digits, follows the number or comes as h; the two agree. A start time is whole seconds, or hours, minutes, and seconds such as 1m2s: t or start on YouTube, and t or #t= on Vimeo. Each of v, h, t, and start appears at most once. MarkdownPoint drops tracking parameters when it reads an address.

The files hold no scripts. No key takes code. MarkdownPoint runs no code from a presentation's folder or a theme. A text shows an HTML tag as plain text. An SVG image runs none of its scripts. A link opens only the addresses above. A 3D model's file keeps no build program. The one exception is an online video. Its YouTube or Vimeo player runs the provider's own scripts.

A key's values column gives the numbers it takes, both ends included. A range on a key that holds {x, y} holds for each of them. A canvas unit is one pixel of the slide at full size. In 3D, a canvas unit's length in meters is the theme's `unit-scale`. Every number is read to six decimals, then checked against its range: 1.0000004 is 1, so a key that takes 0 to 1 takes it. A theme's `unit-scale` is an exception. It keeps 12 significant digits, because a real unit scale can be smaller than a millionth. So are a byte count and a picture's size in pixels, which MarkdownPoint checks against the file they describe: they're read as written. A color is a hex color or a role in the theme's color scheme, such as accent. A hex color is in sRGB, written as CSS writes it: #RGB, #RGBA, #RRGGBB, or #RRGGBBAA. Its alpha is straight, not premultiplied.

An object's font size, insets, corner radius, strokes, text spacing, and flat depth each reach at most 33,554,431.984375 canvas units. Chromium lays out no longer length. Text flows into at most 65,535 columns. Path data holds at most 1,048,576 characters and 8,192 anchors, in a drawing, a text path, a mask, and a motion path alike.

Most times reach at most 4,294,967,296 seconds. Past it, a number no longer tells two neighboring microseconds apart. Most turns reach at most 8,589,934,592 degrees either way. Up to there, millionths of a degree stay apart. A 3D position reaches at most 1,000,000,000,000,000,000 canvas units either way. A length the GPU squares then still fits its 32-bit floats. Repeats, compositions, and charts make at most 512 objects on a slide. Each frame draws them all. A chart counts as if every cell of its table held a number, so what its cells say never changes what fits. An object that would make more makes nothing, with a warning. A table, or a chart's table, holds at most 5,000 cells. All of its cells are read and laid out at once, so a table with more is refused. Groups nest at most 200 deep. Chromium stops nesting a page's elements at 512. Most values that must stay above 0 take 0.000001 as their least. Each key's own range is in its values column. The Inspector's sliders and drags cover a useful part of a key's range. A typed value takes all of it.

The 3D layer is lit in linear light. It is tone-mapped with Khronos PBR Neutral at an exposure of 1 and written in sRGB, the color space of the slide's flat colors. A camera's lens is measured on a 36 mm film across the slide's longer side, as Blender's Sensor Fit Auto measures it. A World with no color lights the 3D layer at its intensity, 0 unless given, with `environments/studio.hdr`, an equirectangular Radiance HDR file whose SHA-256 is ce14a3984f83a8d231cad84cddc9ede84c73743d6d7956daf209f62e1afd1282.

A model's file holds everything it uses. Its one buffer is its BIN chunk. Each of its pictures lies in that chunk or in a data: URI, and is a PNG, a JPEG, or a WebP. A file that uses KHR_draco_mesh_compression, EXT_meshopt_compression, KHR_meshopt_compression, KHR_texture_basisu, or EXT_mesh_gpu_instancing is refused. Importing a model into MarkdownPoint removes them. It decompresses Draco and meshopt, converts Basis Universal pictures to PNG, and copies each GPU instance into a node of its own.

A model's node trees are at most 256 nodes deep. Its nodes draw at most 65,536 primitives together, a mesh's once for each node that draws it. Each primitive of a skinned node copies its skin's joints, at most 65,536 together. The primitives drawn hold at most 1,048,576 morph weights together, counting each target and each rest weight. A primitive's morph targets take 16 bytes for each vertex and target, 32 with normals, and 48 with colors. Together they take at most 256 MiB. Its textures decode to at most 268,435,456 pixels together, a picture's once for each sampler it's drawn with.

A material named `color:` followed by a color role, such as `color:accent`, takes that role's color in the slide's color scheme as its base color. A role the scheme doesn't have leaves the file's color. A number Blender adds to a copied material's name, such as `.001`, is ignored. A node whose `extras.markdownpoint` holds `"cast-shadow": false` casts no shadows, and neither does anything under it, whatever a node further down holds. A text's model gives each letter a node of its own, whose `extras.markdownpoint.source` lists the characters it draws, each as `[block, start, end]`: the block's place among the text's paragraphs, headings, code blocks and kept Markdown in reading order, and a UTF-16 range of that block's text, with its fields filled in and each hard break one character. An animation's `extras.markdownpoint.loop`, `true` or `false`, is only a hint. When it's `true`, a clip MarkdownPoint adds for that Action starts with `loop` at `repeat`. The hint doesn't affect playback.

Every file states the format version as markdownpoint, a major and a minor in quotes: "1.0". Every key here is from version 1.0. MarkdownPoint 1.x opens any version 1.x file. A later minor only adds what an earlier MarkdownPoint can pass over. That one keeps a key, a word or an object type it doesn't know as the file has it, through every save, and draws it as nothing or as the key's default. A save never lowers a file's version. A file of a newer major needs a newer MarkdownPoint.

A JSON file holds only the keys this reference lists, up to its own minor. Any other key there is an error, most likely a typo. A record names each key once, however it spells it. A condition in the required column, such as "with max", says when the key is required.

### transition

A slide transition. A scroll moves both slides along one strip. Each slide's 3D objects keep their place in its stacking order and are clipped at its edge. A model or 3D text with the same id on both slides crosses between them whole. Neither slide's camera drifts during a scroll. During any other transition, both cameras drift. Keys left out default to interpolation ease-in-out, match object, direction left, color black, and delay 0. At `transition`, `slides.<id>.transition`.

| key | required | values | category | description |
| --- | --- | --- | --- | --- |
| `effect` | yes | none, cross-dissolve, carry-over, push, scroll, move-in, reveal, wipe, zoom, fade-through-color | presentation | Which transition plays, or none. |
| `duration` | unless the effect is none | 0.000001 to 4294967296 seconds | motion | How long it takes. With effect `none`, it's left out. |
| `interpolation` |  | linear, ease-in, ease-out, ease-in-out | motion | How the transition speeds up and slows down. Only `carry-over` and `scroll` take it. |
| `match` |  | object, word, character | presentation | What `carry-over` matches between two texts: whole objects, words, or characters. |
| `direction` |  | left, right, up, down | presentation | Which way a push, scroll, move in, reveal, or wipe travels across the screen. |
| `color` |  |  | presentation | The color of a fade through color: a color role or a hex color. |
| `start` | with delay | automatically | presentation | When it starts. Left out, it starts on a click. `automatically` starts it after the slide's last step. |
| `delay` |  | 0 to 4294967296 seconds | motion | For a transition that starts by itself, how long it waits after the slide's last step ends. |

### versions

The presentation's saved versions. Each one's folder, `versions/<number>/`, holds copies of the presentation's two files as they were saved: `slides.md`, and the .mdpoint file as `presentation.json`, so the folder is never a presentation of its own. A numbered folder holding both files is a version even where the catalog doesn't list it, saved when its files last changed. A version names its theme by key and shows the theme as it is now. It uses the presentation's own media. Delete Theme refuses a theme a version uses, and Delete Unused Media keeps a file one uses. While a version's folder holds only some of its files, or a listed version's folder isn't there, as while a sync service brings it, no theme can be deleted and Delete Unused Media deletes nothing. A catalog that can't be read is never written over, so no version is saved until it reads. At the root of `versions/versions.json`.

| `kind` | yes | versions | file | What the file is. |
| `next` | yes | whole numbers, 1 to 9007199254740991 | file | The least number the next version takes; MarkdownPoint goes past every number listed or found, so a deleted version's number is never given again. |
| `versions` |  |  | file | The versions it lists, each a saved-version record, or none when left out. |

### object

One object on a slide, a layout, or a master, by type. An override needs none of the required keys. It changes an object that has them. An override's key set to null removes what the object inherits for it, so its default shows. A null that would leave a required key missing is ignored, with a warning. An override's key that the object doesn't take, such as `cone-angle` on a light that a layout makes directional, is ignored with a warning. So is a value that doesn't read over what the object inherits, such as one outside its range. The object shows what it inherits. The slide can still be edited and exported. The override stays in the file and applies once the object takes it. On an own object, a value that doesn't read is an error. An override's key that no object takes, such as a misspelled key, is an error. So is `type` in an override. Groups nest at most 200 deep. A group nested deeper is read at the top level, with a warning. A group's members paint in order right after the group. When other objects come between them, MarkdownPoint warns and moves the members back together after the group. With blend-mode `normal`, a group's members blend only with each other. Left out, they blend with what lies beneath the group, unless the group has a blur or a wipe, which keeps their blending inside it. In an override, frame, position, rotation, scale, and target change only the parts given. Their other parts keep the inherited values. Any other record or list in an override replaces the inherited one whole. An object on a master or a layout can't be a composition instance or hold an image-result. Its text can't hold a 3D text `model`. At `slides.<id>.objects[]`, `overrides.<id>`; `objects[]` in `master.json` and a layout.

| key | objects | required | values | default | animated | category | description |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `id` | every object | yes |  |  |  | file | The object's id, unique on its slide. Text markers and step curves refer to the object by it. The ids `camera` and `world` belong to the camera and the World alone. |
| `type` | every object | yes |  |  |  | file | What kind of object it is. Only a master holds the camera and the World. A layout or slide changes them through its overrides. A floor lies level without end, as Cinema 4D's Floor. |
| `name` | every object |  |  |  |  | theme | The layer's name in the Layers list, on one line. |

### space-rotation

A 3D object's turn about its origin, in the 3D space's axes: x right, y up, and z toward the viewer. In degrees it turns in Cinema 4D's HPB order: heading about y, then pitch about its own x, then bank about its own z, as three.js's YXZ Euler composes them. Each turns counterclockwise looking along its axis toward the origin: a positive z turns it counterclockwise on the slide, a positive x tilts its top toward the viewer, and a positive y brings its left side forward. At zero rotation, a model faces the viewer, as its glTF file faces +z, and a light shines and the camera looks along its own −z, into the slide. Its own y then points up. In quaternion mode it holds w, x, y, and z, the same turn as glTF's quaternion with w first. Blender's axes differ, with z up. ### drift

## <a id="steps"></a>Steps and keyframes

In the .mdpoint file: [step](#step) · [keyframe](#keyframe) · [keyframe-incoming](#keyframe-incoming) · [keyframe-path](#keyframe-path) · [keyframe-oscillate](#keyframe-oscillate) · [interpolation](#interpolation) · [keyframe-interpolation](#keyframe-interpolation) · [cue](#cue)

### step

One step: the moves, cuts, and media starts that a click or the previous step sets off. Every time in a step, and in its keyframes and cues, is in seconds, rounded to six decimals. Sums of times and the times shown are rounded the same way. A step has no delay of its own: a keyframe's start delays its move. A first step that starts by itself plays after the slide's transition, except under a scroll. A step that repeats plays alone on its click, and a file that breaks that reads with a warning, without the repeat. A step after one that loops while waiting starts when that step's first pass ends, and the loop plays on under it. At `slides.<id>.steps[]`.

| key | required | values | category | description |
| --- | --- | --- | --- | --- |
| `id` | yes |  | file | The step's id, unique on its slide. |
| `name` |  |  | presentation | The step's name in the Animate list, on one line. |
| `start` |  | with, after | presentation | When the step starts: with the previous step, or after it ends. Left out, it waits for a click. A scroll plays the next slide's first step with it, whatever its start. |
| `duration` |  | 0 to 4294967296 seconds | motion | How long the step lasts. A later keyframe, cue, or entering paragraph extends it, and left out or 0, the step lasts as long as what it holds. |
| `repeat` |  | whole numbers, 2 to 64 | presentation | How many times the step plays before it completes. Left out, it plays once. |
| `wait-loop` |  | 0 to 4294967296 seconds | presentation | The time, in seconds into the step, that it loops back to while the presentation waits for the next click. It comes before the step's end. |
| `curves` |  |  | motion | The step's keyframes, by object and property, such as card.opacity. Each property has one or more. |
| `cues` |  |  | motion | Events at set times in the step: a paragraph appearing, a sound, a video, or an online video starting, or a clip playing a model's Action. |

### keyframe

| key | required | values | category | description |
| --- | --- | --- | --- | --- |
| `id` | yes |  | file | The keyframe's id, unique in its step among its keyframes and cues. |
| `start` |  | 0 to 4294967296 seconds | motion | When the move into the keyframe begins, in seconds into the step. It must come before time. Left out, it begins at the previous keyframe. |
| `time` | yes | 0 to 4294967296 seconds | motion | When the property reaches the value, in seconds into the step. |
| `value` | yes |  | motion | The value, written as the property is. `null` clears a property an object may leave out, so its text style or default shows. |
| `interpolation` |  | linear, ease-in, ease-out, ease-in-out, smooth, hold, anticipate, overshoot, anticipate-overshoot, bounce, elastic | motion | How the value reaches the keyframe: gradually on a curve, or at once with hold. It's a named curve, a named curve with its settings, a cubic Bézier, or a spring. Left out, linear. |
| `incoming` |  |  | motion | The longer move this keyframe interrupts. Up to this keyframe, the motion follows that move's curve. |
| `path` |  |  | motion | A curved motion path for the move into the keyframe. It goes on the x keyframe and also drives the matching y keyframe. |
| `loop` |  | repeat, ping-pong | motion | How the property continues past its last keyframe: playing its keyframes again, or back and forth. It may sit on any keyframe of the curve. The latest one that has it sets it. |

### interpolation

Named interpolations: how a value changes over a move, gradually on a curve or at once. Transitions take linear, ease-in, ease-out, and ease-in-out. A keyframe's or a text's interpolation may instead be a cubic Bézier: a JSON array [x1, y1, x2, y2] of its two handles, in the order CSS's cubic-bezier() takes them. x is time and y is value. Each handle's time is from 0 to 1. A Bézier that matches a named curve is written as that name. At a keyframe's, a transition's, and a text's `interpolation`.

| key | required | values | category | description |
| --- | --- | --- | --- | --- |
| `linear` |  |  | motion | Moves at a constant speed. |
| `ease-in` |  |  | motion | Starts slowly from the previous keyframe, as CSS's ease-in does. |
| `ease-out` |  |  | motion | Slows down as it reaches the keyframe, as CSS's ease-out does. |
| `ease-in-out` |  |  | motion | Starts slowly and ends slowly, as CSS's ease-in-out does. |
| `smooth` |  |  | motion | Starts and ends gently. It's milder than ease-in-out. |
| `hold` |  |  | motion | Keeps the previous value until the keyframe's time, then jumps. |
| `anticipate` |  |  | motion | Pulls back before it moves. |
| `overshoot` |  |  | motion | Passes the keyframe's value and settles back on it. |
| `anticipate-overshoot` |  |  | motion | Pulls back first, then passes the keyframe's value and settles back on it. |
| `bounce` |  |  | motion | Falls onto the keyframe's value and bounces off it three times, each lower, never passing it. Its bounciness is 0.5. |
| `elastic` |  |  | motion | Springs past the keyframe's value and swings into it, each swing smaller. |

| `back` |  | 0 or more | motion | How far `anticipate`, `overshoot`, or `anticipate-overshoot` pulls back or swings past, as Blender's Back. Left out, it's 1.70158. |
| `amount` | with curve spring | 0 to 1 | motion | How far a spring overshoots, 0 for none. |
| `amplitude` |  | 0 or more | motion | How large an elastic's swing is, as a multiple of the move. Left out, it's 1. |
| `period` |  | 0.000001 or more seconds | motion | How long one swing of an elastic lasts. Left out, it's 0.3 of the move into the keyframe, from where that move starts. |
| `bounciness` |  | 0 to 1 | motion | A bounce's rebound speed as a fraction of its landing speed, as Blender's Bounciness: 0 lands dead, 1 rebounds to its height each time. Left out, it's 0.5. |
| `response` |  | 0.000001 or more seconds | motion | How quickly a spring moves, as its period: a shorter one springs faster. Left out, the spring settles by the keyframe's time. |

### markdown

The Markdown that text, tables, and speaker notes use. Bold and italic follow CommonMark, except that a run of `*` between punctuation and a letter can both open and close. Lines indented by four spaces are a code block, which MarkdownPoint writes between fences. A backslash before punctuation keeps it as text. A character reference, such as `&amp;` or `&#169;`, reads as its character outside code. MarkdownPoint writes a backslash before an `&` that would start one. In a list item, a tab is written `&#9;`. Where a tab or four spaces open a paragraph, or spaces follow a list item's marker, the first is written `&#9;` or `&#32;`. Two lists in a row take different markers: `-` then `*`, or `1.` then `1)`. An address that isn't a link stays words. A span's attributes, `color` and `font-weight`, read in either order, each value bare or quoted, and MarkdownPoint writes color first, a hex quoted and a weight bare. A span with any other key, a key twice, or a value its key doesn't take stays as written, and none of it applies. A span with no attributes, `[words]{}`, is a group: its words are read apart and take nothing of their own. MarkdownPoint writes each run whose style changes inside a word in a group of its own where `*`, `==` and `~~` alone would read back as plain characters. Code takes no weight of its own. A word draws at bold's weight, else its own, else the weight its text style gives a mark it carries, else its block's. Headings stand at 2, 1.5, 1.17, 1, 0.83, and 0.67 times the text's size, at weight 700, or the text's where that's heavier, as bold is. A chart's table names its series in the header row, after the first cell, and its categories in the first column. Its other cells are numbers in Latin digits, read by the presentation's language, with its decimal mark and group mark as Unicode CLDR 48.2.0 gives them. A locale CLDR keeps no numbers for reads by CLDR's parent locales: pt-FR as pt-PT, and ru-Latn as root, as en-US does. A number may have a sign, and a prefix or a suffix, such as $ or %. It may open with the decimal mark. Its whole digits stand ungrouped, or grouped by the language's group mark or by a space, in the language's widths, but never by both: 1,234.5 in English, 1 234,5 in Swedish, and 12,34,567 in Hindi. A space there is a space, a no-break space, a narrow no-break space or a thin space (U+0020, U+00A0, U+202F or U+2009), all alike, and ' and ’ are alike too. A cell that holds no number by that rule has no value, so 1,23 has none in English, and 1,234 is 1.234 in Swedish. A label spells its value as its cell does: its sign, prefix, suffix, decimals and group mark. A value is a double, so leading zeros go, digits past 2^53 round, and at most 100 decimals are kept. A label's words are its cell's as written, never read as Markdown or a field. A pie or a donut draws the first series' positive values. A counter counts to the number in the first body row's second cell. A blank cell counts to 0, and a cell that holds no number shows its words and doesn't count. At text blocks, table cells, and speaker notes.
