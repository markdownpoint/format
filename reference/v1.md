# MarkdownPoint file format reference

This reference lists every key in the files and what it does.

A presentation is a folder with two files at its root, `slides.md` and `presentation.mdpoint`, by those names in any case. `slides.md` holds the sections, the slides' order and text, and the speaker notes, and `presentation.mdpoint` holds the theme, the slides' objects and animation, and the settings, as JSON. The folder's name is the presentation's. Another .mdpoint file at the root, or another .md file whose name starts with the word slides, such as a sync service's conflicted copy, keeps the presentation from opening. Its themes are under themes/, its other files under media/ and generated/, and its saved versions under versions/. A file or folder whose name starts with `.markdownpoint` is MarkdownPoint's own, and anything else in the folder is the author's.

A table's required column says when a record needs the key: yes, always, or the case in which it does, such as "with max". Its values column gives the words or the numbers the key takes, both ends included, and a range on a key that holds {x, y} holds for each of them. Every number is read to six decimal places, then checked against its range, so 1.0000004 is 1. A theme's `unit-scale` keeps 12 significant digits, and a byte count, an image's size in pixels, and a `parent-inverse` are read as written.

A canvas unit is one pixel of the slide at full size, and in 3D it stands for the theme's `unit-scale` in meters. An icon unit is a 24th of an icon's frame: Lucide draws each icon on a square 24 icon units wide, which stretches to fill the frame. A blur is its radius, twice the Gaussian's standard deviation, as CSS `box-shadow` measures it, so CSS `filter: blur(8px)` is a blur of 16. A color is a role in the theme's color scheme, such as accent, or a hex color in sRGB, written #RGB, #RGBA, #RRGGBB, or #RRGGBBAA, its alpha straight, not premultiplied.

An id is a lowercase letter, then lowercase letters and digits with single hyphens between them, such as title-card. Slides and compositions share one set of ids. A presentation's id, a save stamp, and a theme's id in its master are lowercase UUIDs. A theme's key, the name of its folder in themes/, and a layout's key, the name of its file, are ids every supported system can hold as a file name, and a layout's key isn't master or manifest. The names a theme gives its schemes, color roles, brand colors, and text styles are spelled as ids, and so is a property a binding names. A font family is a letter or a digit in any script, then letters, digits, spaces, dots, underscores, and hyphens.

A file path is relative to the presentation's or the theme's folder, with / between names. A name isn't empty, `.`, or `..`, doesn't start with a dot or end in a space or a dot, and holds no backslash, <, >, :, ", |, ?, *, #, or control character. CON, PRN, AUX, NUL, COM1 to COM9, LPT1 to LPT9, COM¹ to COM³, and LPT¹ to LPT³ name no file, in any case and with any extension. A path spells each name as its folder lists it, in Unicode's composed form (NFC), and no folder holds two names that are one under the full case folding of Unicode 17.0.0, as ß and SS are. A presentation's file is under media/ or generated/, but not a .json file under generated/, which records how an image was made: the author's files go under media/, and MarkdownPoint writes what it makes under generated/. A theme's file is anywhere in its folder but manifest.json, previews, and example at its root. An image's file ends in .png, .jpg, .jpeg, .gif, .webp, .svg, .avif, or .bmp, a video's in .mp4, .m4v, .mov, .webm, or .ogv, an audio file's in .mp3, .m4a, .wav, .ogg, or .flac, a model's in .glb, and an embedded font's in .eot, in any case. A file reached through a symbolic link or an alias is never one of the presentation's files.

A link is an http or https URL with a host, a mailto: or tel: address, or slide: and a slide's id. It holds no spaces or control characters, and a URL holds no backslash. A link to anything else, or to a slide that isn't there, is kept and does nothing.

No key takes code, and MarkdownPoint runs none from a presentation's folder or a theme: a text shows an HTML tag as plain text, and an SVG image runs none of its scripts. The one exception is a web video, whose YouTube or Vimeo player runs the provider's own scripts.

A key that names an object the slide lacks is passed over with a warning, and the rest of the slide plays: a parameter under `initial` or in a step, a cue, a constraint's target, a group's or a 3D object's parent, or a line end without a last position.

Every file states its format version in `markdownpoint`, a major and a minor in quotes: "1.0". Every key here is from version 1.0. MarkdownPoint 1.x opens any version 1.x file. A later minor only adds what an earlier MarkdownPoint can pass over, such as a key, a word, an object type, or a number past a range, which that MarkdownPoint draws as nothing or as its key's default and keeps as the file has it through its saves. A save never lowers a file's version, and a file of a newer major needs a newer MarkdownPoint. Up to its own minor, a JSON file holds only the keys this reference lists, each once: any other key is an error, most likely a typo.

## <a id="md-file"></a>The .md file

### frontmatter

The keys MarkdownPoint reads, each on one line as key: value. Other keys are kept as written. A notes app may add its own, such as tags, and the presentation still opens. At the frontmatter at the top.

| key | required | values | description |
| --- | --- | --- | --- |
| `markdownpoint` | yes |  | The format version, its major and minor in quotes: "1.0". |
| `id` | yes |  | The presentation's id, the same as the .mdpoint file's. |
| `footer` |  |  | The footer text, shown on every slide with a footer field. Unquoted, a space and `#` start a comment. |
| `save-id` |  |  | The same save stamp as the .mdpoint file's, which is the one read. |

### markers

The markers that divide the .md file into sections, slides, and their text. Spaces or tabs before or after a marker on its line don't change it. A layout's placeholder needs a text marker only once it has words: an empty one and none read alike. At a line of its own in the body.

| marker | required | values | description |
| --- | --- | --- | --- |
| `section` |  |  | `<!-- section: id -->` starts a section, by an id unique among sections. One level-1 heading after it is the section's name, without its marks, one space between its words. |
| `slide` |  |  | `<!-- slide: id -->` starts a slide, in presentation order, once for each slide. |
| `composition` |  |  | `<!-- composition: id -->` starts a composition's text, once for each composition. |
| `text` |  |  | `<!-- text: id -->` starts an object's text, and `<!-- text: <instance id>.<control id> -->` an instance's words for its composition's text control. Each id appears once in its slide or composition. |
| `control` |  |  | `<!-- control: id -->` starts the default text of a composition's text control, by the control's id, once in its block. |
| `notes` |  |  | `<!-- notes -->` starts the slide's speaker notes. |

**Sections.** A section's heading stands alone in its block. Once there is a section, every slide is in one: a slide before the first is an error.

### body

How the body is divided, and what is kept as written. Only a marker starts a slide, which runs to the next slide, section, or composition marker, or to the end of the file. A paragraph id in speaker notes is never shown, and no step can name it. At the body, between and inside the markers.

| form | required | values | description |
| --- | --- | --- | --- |
| `escape` |  |  | A backslash after `<!--`, as in `<!--\ notes -->`, keeps a line that looks like a marker in its block, and outside code it isn't shown. |
| `blank-line` |  |  | Blank lines only separate: any number of them part two blocks once, and those under a marker or before the next one stand for nothing, but in a code block left open, all but the last are code. |
| `comment` |  |  | An HTML comment in a text or notes block, but an `id`, is a note: kept, not shown. A comment line of a marker's word and at most one other word, in any case, is a misspelled marker: an error. |
| `unsupported` |  |  | Markdown that MarkdownPoint doesn't support, such as an image or an HTML tag, is kept as written and shown as plain text. |

### markdown

The Markdown that text, tables, and speaker notes use. At text blocks, table cells, and speaker notes.

| form | required | values | description |
| --- | --- | --- | --- |
| `paragraph` |  |  | Lines separated by a blank line are paragraphs; one of nothing but `<br>` holds a line break fewer than it has, so `<br>` alone is an empty paragraph. |
| `id` |  |  | `<!-- id: k3x9a2 -->` ending a block's last line, spaces and tabs aside, is its id, spelled as any id is: a split's first part keeps it, as does a join's first block, and a repeat reads as new. |
| `heading` |  |  | `# Heading` to `###### Heading` are headings, and so is a line underlined with `===` or `---`, at level 1 or 2. |
| `list` |  |  | Lines starting with `- `, `* `, or `+ ` are a bulleted list. Indent for deeper levels. A block between items ends it. |
| `numbered-list` |  | a first number from 0 to 999,999,999 | Lines starting with `1. ` or `1) ` are a numbered list. It starts at its first number and counts up. A block between items ends it. |
| `quote` |  |  | Lines starting with `> ` are a quote. |
| `code-block` |  | bash (sh, shell, zsh), c, cpp (c++, cc, cxx, h, h++, hh, hpp, hxx), csharp (c#, cs), css, diff (patch), go (golang), java (jsp), javascript (cjs, js, jsx, mjs), json (json5, jsonc), kotlin (kt, ktm, kts, ktx), markdown (md, mkd, mkdown), php, python (gyp, ipython, py), ruby (gemspec, irb, podspec, rb, thor), rust (rs), sql, swift, typescript (cts, mts, ts, tsx), xml (atom, html, plist, rss, svg, wsf, xhtml, xjb, xsd, xsl), yaml (yml) | Lines between fences of three or more backticks or tildes are a code block. Its language colors it as highlight.js 11.12.0 does. A marker inside it is code. One holding a marker must close. |
| `rule` |  |  | A line of `***`, `___`, or `---` is a horizontal rule, wherever it stands in its block. A `---` right under a paragraph's text is no rule: it makes that text a heading. |
| `table` |  |  | A table's or a chart's text is one Markdown table: a header row, a divider row, and body rows, `\|` between cells. A divider's colons align its column, and `\\|` is a pipe. A comment can't follow it. |
| `bold` |  |  | `**text**` or `__text__` is bold. |
| `italic` |  |  | `*text*` or `_text_` is italic. |
| `highlight` |  |  | `==text==` is highlighted. |
| `strikethrough` |  |  | `~~text~~` is struck through. |
| `code` |  |  | `` `text` `` is code. It takes a color and a link, and no other mark. |
| `link` |  |  | `[text](address "title")` links to a webpage, an email address, a phone number, or a slide as `slide:id`, its title optional. `<address>` links as itself. |
| `color` |  |  | `[text]{color=accent}` or `[text]{color="#2F7D4F"}` colors text with a color role or a hex color. |
| `font-weight` |  | 300, 400, 500, 600, 700, 900 | `[text]{font-weight=600}` gives text a weight of its own, under bold; with a color it's one span, `[text]{color=accent font-weight=600}`. |
| `field` |  | slide-number, slide-count, section-number, section-name, date, footer | `{{name}}` shows a value the presentation fills in, as Fields below gives each. |
| `line-break` |  |  | A backslash or two spaces at the end of a line break it within its paragraph. So does `<br>`, but not in a table cell. |

**Bold and italic** follow CommonMark, except that a run of `*` between punctuation and a letter can both open and close.

**Code blocks.** Lines indented by four spaces are a code block too. A fence's language name is read in any case. The words after a fence's language are its options, in braces, as Slidev writes them: `{lines:true}` numbers the lines, and any other option is kept as written.

**Escapes.** A backslash before punctuation keeps it as text. A character reference, such as `&amp;` or `&#169;`, reads as its character outside code. An address that isn't a link stays words.

**Spans.** A span's attributes, `color` and `font-weight`, read in either order, each value bare or quoted. A span with any other key, a key twice, or a value its key doesn't take applies none of it and stays as written. A span with no attributes, `[words]{}`, groups its words and gives them nothing. A word draws at bold's weight, else its own, else the weight its text style gives a mark it carries, else its block's.

**Headings** stand at 2, 1.5, 1.17, 1, 0.83, and 0.67 times the text's size, at weight 700, or the text's where that's heavier.

**Tables.** A table, or a chart's table, holds at most 5,000 cells. A chart's table names its series in the header row, after the first cell, and its categories in the first column. Its other cells are numbers in Latin digits, with the decimal mark and group mark of the presentation's `locale` as Unicode CLDR 48.2.0 gives them. Their whole digits stand ungrouped, or grouped in the language's widths by its group mark or by a space, never by both: 1,234.5 or 1 234.5 in English, 1 234,5 in Swedish, and 12,34,567 in Hindi. A space there is a space, a no-break space, a narrow no-break space, or a thin space. A number may have a sign, a prefix, or a suffix, such as $ or %, and a negative one may stand in parentheses or end with a minus, as (1,234.50) or 1 234,50 kr-. A parenthesis with no partner on the number's other side belongs to the prefix or suffix, and so does a minus after a colon, a comma, or a period, so 100:- is 100. A cell that holds no number has no value, so 1,23 has none in English, and 1,234 is 1.234 in Swedish. A label spells its value as its cell does. A pie or a donut draws the first series' positive values, and a counter counts to the number in the first body row's second cell, a blank cell to 0.

**Fields.** `slide-number` is the slide's number among the shown slides, counted from 1, and `slide-count` counts them: a skipped slide or a composition's own slide has no number, and its field shows nothing. So of the slides A, B, and C, with B skipped, C shows `{{slide-number}} of {{slide-count}}` as 2 of 2. `section-number` is the number of the slide's section, counted from 1, and `section-name` its name, both empty for a slide in no section. `footer` shows the frontmatter's footer. `date` shows the presentation's `date` as Unicode CLDR 48.2.0 writes a full year and a two-digit month and day in the presentation's `locale`, in the Gregorian calendar with Latin digits: 2026-03-04 in sv-SE and 03/04/2026 in en-US. A locale whose language CLDR doesn't name writes it as en-US does, and without a `date`, the field stays as written. A field's value goes in as text, never read as Markdown or a field.

## <a id="the-presentation"></a>The presentation

In the .mdpoint file and versions/<time>/version.json.

### presentation

The presentation: its theme, slides, and settings. At the root.

| key | required | values | description |
| --- | --- | --- | --- |
| `markdownpoint` | yes |  | The format version, its major and minor in quotes: "1.0". |
| `type` | yes | presentation | What the file is. |
| `id` | yes |  | The presentation's id, which the .md file repeats. |
| `theme` | yes |  | The key of the presentation's theme, the name of its folder in themes. Its master sets the slide size and `unit-scale`. |
| `slides` | yes |  | The slides, by id. The .md file has their order and text. |
| `background` |  |  | The background every slide shows, unless the slide sets its own. |
| `background-image-style` |  |  | The style a generated background image is made in when its background sets none of its own, as text, or `none` for no style. Left out, it's none. |
| `comments` |  |  | Comment threads, by id, each pinned to a slide or a composition. |
| `compositions` |  |  | Reusable animated scenes, by id. Slides show them as instances. |
| `countdown` |  | whole numbers, 1 to 4294967296 seconds | How long the talk should take, in seconds. The presenter's timer counts down from it. |
| `date` |  |  | The date the date field shows, as YYYY-MM-DD. It must be a real calendar date, from year 0001 on. |
| `default-text-style` |  | none or a record | The text style and color of a new text box, or none for no style. |
| `image-style` |  |  | The style a generated image object is made in when it sets none of its own, as text, or `none` for no style. Left out, it's none. A background's picture takes `background-image-style` instead. |
| `locale` |  |  | The presentation's language and region, as a BCP 47 language tag such as fr-CA: it writes the date field, reads the chart cells, and splits words to animate. Left out, it's en-US. |
| `save-id` |  |  | A save stamp: the id of a save, which MarkdownPoint writes while the presentation is shared for editing. Other tools keep it as it is. |
| `self-playing` |  |  | Settings for playing the presentation on its own, as at a kiosk. |
| `soundtrack` |  |  | Music that plays under the whole presentation. |
| `swatches` |  |  | The colors the author has saved for this presentation, as hex colors. |
| `transition` |  |  | The transition from every slide to the next, unless the slide sets its own. Left out, slides cross-dissolve over 0.5 seconds. |

**`locale`.** A theme's charts read their cells as en-US. The locale also picks the forms Chinese, Japanese, and Korean characters take.

### size

The size of a slide or a composition, in canvas units. At `compositions.<id>.size`; `size` in `master.json`.

| key | required | values | description |
| --- | --- | --- | --- |
| `width` | yes | whole numbers, 1 to 8192 canvas units | The width. |
| `height` | yes | whole numbers, 1 to 8192 canvas units | The height. |

### transition

A slide transition. Keys left out default to interpolation ease-in-out, match object, direction left, color black, and delay 0. At `transition`, `slides.<id>.transition`.

| key | required | values | description |
| --- | --- | --- | --- |
| `effect` | yes | none, cross-dissolve, carry-over, push, scroll, move-in, reveal, wipe, zoom, fade-through-color | Which transition plays, or none. |
| `color` |  |  | The color of a fade through color: a color role or a hex color. |
| `delay` |  | 0 to 4294967296 seconds | For a transition that starts by itself, how long it waits after the slide's last step ends. |
| `direction` |  | left, right, up, down | Which way a push, scroll, move in, reveal, or wipe travels across the screen. |
| `duration` | unless the effect is none | more than 0 and at most 4294967296 seconds | How long it takes. With effect `none`, it's left out. |
| `interpolation` |  | linear, ease-in, ease-out, ease-in-out | How the transition speeds up and slows down. Only `carry-over` and `scroll` take it. |
| `match` |  | object, word, character | What `carry-over` matches between two texts: whole objects, words, or characters. |
| `start` | with delay | automatically | When it starts. Left out, it starts on a click. `automatically` starts it after the slide's last step. |

**Scroll.** A scroll moves both slides along one strip. Each slide's 3D objects keep their place in its stacking order and are clipped at its edge, and a model or 3D text with the same id on both slides crosses between them whole. Neither slide's camera drifts during a scroll, and both do during any other transition.

| `fade-out` |  | 0 to 4294967296 seconds | How long it takes to fall to silence, linearly, before the file ends each time. Where the two fades overlap, the lower volume holds. |

### version

One saved version of the presentation: this file, beside copies of the presentation's two files as they were saved, in a folder of its own under versions/. At the root of `versions/<time>/version.json`, where <time> is when the version was saved, with its tail.

| key | required | values | description |
| --- | --- | --- | --- |
| `markdownpoint` | yes |  | The format version, its major and minor in quotes: "1.0". |
| `type` | yes | version | What the file is. |
| `number` | yes | whole numbers, 1 to 9.007199254740991 × 10¹⁵ | The number MarkdownPoint shows: one past the highest version's when it was saved. |
| `name` |  |  | The name the author gave it, on one line that isn't blank and has no control characters, or none when left out. |

**The folder.** A version's folder, `versions/<time>/`, is named by when it was saved, in UTC to the second with dots for colons, then a dash and a tail of four lowercase letters or digits, as `versions/2026-10-30T16.20.05Z-k3pz/`. Within one second, a later save's tail sorts after an earlier one's while a tail above it is free, so the folders' names sort in the order the versions were saved. A version names its theme by key, shows the theme as it is now, and uses the presentation's own media. Nothing under versions/ opens as a presentation of its own.

## <a id="slides"></a>Slides and compositions

In the .mdpoint file.

### slide

One slide's objects, look, and animation. Its text is in the .md file. At `slides.<slide id>`.

**The animated column.** `yes` means a step's keyframes move the key through the values between, `cut` that it changes at once at its keyframe, whatever the interpolation, and a list names the parts a step animates.

**Overrides.** A null that would leave a required key missing is ignored. On an inherited picture or video, an override's `file` makes it a picture or a video, as the file's type says, and `null` there leaves an empty picture. An override's key the object doesn't take, such as `cone-angle` on a light that a layout makes directional, a value another type takes but the object doesn't, and one that doesn't read over what the object inherits, are ignored with a warning, and stay in the file to apply once the object takes them. A key or a value no object takes, such as a misspelled key, and `type` in an override, are errors, and so is a value that doesn't read on an own object. In an override, `frame`, `position`, `icon-position`, `rotation`, `scale`, and `target` change only the parts given, and any other record or list replaces the inherited one whole. An object on a master or a layout can't be a composition instance or hold a generation, and its text can't hold a 3D text `model`.

**Groups.** Groups nest at most 200 deep. A group's rotation is the angle its members' box is measured at, not a turn of its members: they keep their own positions and turns, and a keyframe of the group's rotation turns them by how far its value differs from it. A group's members paint in order right after the group. With blend-mode `normal`, they blend only with each other. With `pass-through`, a group's default, as Figma's and Photoshop's Pass Through, they blend with what lies beneath the group, unless the group has a blur, tilts by a `rotation-x` or `rotation-y`, or stands in depth in a tilted group, which keeps their blending inside it or the tilted group. The group's wipe masks each member alike, and they still blend with what lies beneath it.

**Web videos.** A web video's `url` is the https address of a YouTube or Vimeo video, with no user name or password and no port but 443. YouTube's are youtube.com/watch?v=id, youtube.com/embed/id, /shorts/id and /live/id, youtu.be/id, and youtube-nocookie.com/embed/id, where the id is 11 letters, digits, underscores, or hyphens; a youtube.com address may start with www. or m., and youtu.be and youtube-nocookie.com with www. Vimeo's are vimeo.com/, www.vimeo.com/, or player.vimeo.com/video/ and the video's number, which has no leading zero, with an unlisted video's hash, letters and digits, after the number or as h, the two alike where both stand. A start time is whole seconds, or hours, minutes, and seconds such as 1m2s: t or start on YouTube, and t or #t= on Vimeo. Each of v, h, t, and start appears at most once.

**The 3D layer.** A slide's models, shadow catchers, floors, and texts with a 3D `model` draw together as one image, its 3D layer, which stands where the backmost of them stands in the slide's paint order, a hidden one included. Lights and the camera draw nothing there and stand anywhere in the order. The layer is lit in linear light, tone-mapped with Khronos PBR Neutral at an exposure of 1, and written in sRGB, the color space of the slide's flat colors: a directional light of intensity 1 lights a white surface facing it to white. A camera's lens is measured on a 36 mm film across the slide's longer side, as Blender's Sensor Fit Auto measures it. A World with no color lights the layer at its intensity, 0 unless given, with `environments/studio.hdr`, an equirectangular Radiance HDR file whose SHA-256 is ce14a3984f83a8d231cad84cddc9ede84c73743d6d7956daf209f62e1afd1282.

**Model files.** A model's file is binary glTF 2.0 or a later 2.x that holds everything it uses: its one buffer is its BIN chunk, and each image a texture draws is a PNG, a JPEG, or a WebP in that chunk or in a data: URI. It may use EXT_texture_webp, KHR_materials_anisotropy, KHR_materials_clearcoat, KHR_materials_dispersion, KHR_materials_emissive_strength, KHR_materials_ior, KHR_materials_iridescence, KHR_materials_sheen, KHR_materials_specular, KHR_materials_transmission, KHR_materials_unlit, KHR_materials_volume, KHR_mesh_quantization, KHR_texture_transform, and KHR_xmp_json_ld. A file that requires any other is refused, and so is one that uses KHR_draco_mesh_compression, EXT_meshopt_compression, KHR_meshopt_compression, KHR_texture_basisu, or EXT_mesh_gpu_instancing. Any other extension it uses is ignored, a model's own lights too. A skinned vertex moves with at most four joints, its `JOINTS_0` and `WEIGHTS_0`. Drawing reads no other set, and importing a model refuses a primitive with a second, `JOINTS_1`. A model's node trees are at most 256 nodes deep. Counting a mesh once for each node that draws it, its primitives number at most 65,536, copy at most 65,536 skin joints, and hold at most 1,048,576 morph weights, counting each target and each rest weight. Counting each primitive of its meshes once, its morph targets take at most 256 MiB: 16 bytes for each vertex and target, 32 with normals, and 48 with colors. Counting an image once for each sampler, its textures decode to at most 268,435,456 pixels.

**Materials and nodes.** A material named `color:` and a color role, such as `color:accent`, takes that role's color in the slide's scheme as its base color, opaque. A role the scheme lacks leaves the file's color, and a number Blender adds to a copied material's name, such as `.001`, is ignored. A node whose `extras.markdownpoint` holds `"cast-shadow": false` casts no shadows, and neither does anything under it. A key that names a node, such as `parent-node`, names any node of the file, a skin's joint among them, by the rule the cue record gives a clip's Action, with Node in place of Animation.

**Path data**, in a drawing, a text path, a mask, or a motion path, holds at most 1,048,576 characters and 8,192 points.

### text-model

A text's 3D model, in one of two forms: an `extrusion`, from which MarkdownPoint builds the words' letters into a model, or a GLB `file` a program built, with the `built-from` fingerprint of what it was built from. One unit of the model is one em of the text's size, and its origin stands on the first line's baseline at the left of the text's column. It moves, turns and scales with the text's frame, its depth by the square root of the text's two scales. A step's clips play the Actions of a GLB `file`, as they play a model's; an `extrusion` has none. At `objects[].model` of a text.

| key | required | values | description |
| --- | --- | --- | --- |
| `built-from` | with file |  | The fingerprint of what the GLB was built from, by the rule the reference gives. A rule this reader doesn't know reads as out of sync. |
| `extrusion` | unless it has file | 0 or more em | The depth and bevel MarkdownPoint builds the words' letters to, in ems. An empty record builds them to its defaults. |
| `file` | unless it has extrusion |  | The GLB a program built from the words, as a presentation's file path. |

**The model's letters.** A text's model holds its letters under one node, its scene's only root, which draws no mesh of its own. Each of that node's children is a letter, which it draws itself or through the nodes under it. A letter's `extras.markdownpoint.characters` lists the characters it draws, each as `[block, start, end]`: the block's index among the text's paragraphs and headings, empty ones included, code blocks, and kept Markdown in reading order, counting from 0, and the characters of that block's text from UTF-16 offset start up to but not including end, with its fields filled in and each hard break one character. Its `extras.markdownpoint.box` is the box the slide lays the letter out in, `[left, bottom, right, top]` in the model's units, y up. The node holding the letters lists the text's paragraphs in its `extras.markdownpoint.paragraphs`, each as `[paragraph, left, bottom, right, top]`: the paragraph's number among the text's paragraphs, headings, and list items in reading order, counting from 1, and the box it lays out in, a list item's with its nested list. A letter enters and exits with the pieces its first character is in, and one with no `characters` stays where it is. A model laid out otherwise enters and exits as one piece, about the center of its text's frame. In a model of the word Hi, the JSON holds this, besides its meshes and the rest glTF needs:

```json
{
  "scene": 0,
  "scenes": [{"nodes":[0]}],
  "nodes": [
    {"children":[1,2],"extras":{"markdownpoint":{"paragraphs":[[1,0,-0.21,0.97,0.88]]}}},
    {"mesh":0,"extras":{"markdownpoint":{"characters":[[0,0,1]],"box":[0,-0.21,0.73,0.88]}}},
    {"mesh":1,"extras":{"markdownpoint":{"characters":[[0,1,2]],"box":[0.73,-0.21,0.97,0.88]}}}
  ]
}
```

**`built-from`.** A text model's `built-from` is `text-model-`, its rule's number, `:sha256:`, and 64 lowercase hex digits. By rule 12, it is `text-model-12:sha256:` and the SHA-256 of its text's record: a JSON object written as RFC 8785's JSON Canonicalization Scheme writes it, its keys sorted by their UTF-16 code units, with no space, each number and string as ECMAScript writes it, in UTF-8. The record holds only what the presentation's folder states, each key and value as the files spell them, and leaves out a key with nothing to hold. An em is the text's size, and each length in ems is rounded to three decimal places.

- `content`: the text's words, as the .md file holds them.
- `fields`: each field the words show that has a value, by its name, with the value the slide fills in.
- `locale`: the presentation's `locale`, or en-US where it states none.
- `style`: the text's `font-family`, `italic`, `font-weight`, `color`, `align`, `text-direction`, `line-height`, `tracking`, `case`, `bullet-style`, `sub-bullet-style`, `paragraph-spacing`, `list-indent`, `column-count`, `column-gutter`, `tabular`, and `kerning`, as the text, its text style, and their defaults give them. `paragraph-spacing`, `list-indent`, and `column-gutter` are in ems, and `column-gutter` is left out in one column.
- `marks`: each mark the text style styles, by the mark's keys, with bold and a highlight never lighter than the text, as `marks` says.
- `width`: the frame's width in ems, unless the text's width grows to its words.
- `text-path`, `path-offset`, and `height`: for words along a path, the path, its offset, and the frame's height in ems.
- `column-height`: in more than one column, the frame's height less the text's top and bottom insets, in ems.
- `ligatures`: false where the text's characters travel apart, each shaped alone: its entrance or exit is by `character`, or a `carry-over` transition matching characters carries it.
- `size`: the text's size in canvas units, where a quote or a horizontal rule stands among its words, whose inset or line has a fixed size in canvas units, whatever the text's size.
- `fonts`: each font role a word draws with, a heading's and code's included, by its name, with the `family` the theme names for it and, where the theme carries its faces, the SHA-256 of each of its `files` in lowercase hex, in the order `font-files` lists them.
- `optical-sizes`: each such role whose family has an optical-size axis, by its name, with one list for each of its axes, the axes ordered by their least size, then their greatest, each once. A list holds each size the role's words are set at, once, from the smallest: the text's size, a heading's, and code's. Each is then held within the axis and rounded to six decimal places, so two sizes past the axis's end both stand at it. An embedded face's axis is its file's `opsz`, and a family whose faces have several lists each. A bundled family's is Inter 14 to 32, Source Serif 4 8 to 60, and Fraunces 9 to 144.

So the words "Ship **it**." in a theme whose display role is Inter, at 72 canvas units and weight 700 in a frame 900 wide, have the record `{"content":"Ship **it**.","fonts":{"display":{"family":"Inter"}},"locale":"en-US","marks":{"highlight":{"font-weight":700}},"optical-sizes":{"display":[[32]]},"style":{"align":"left","bullet-style":"disc","case":"none","color":"text","column-count":1,"font-family":"display","font-weight":700,"italic":false,"kerning":"metrics","line-height":1.05,"list-indent":1.25,"paragraph-spacing":0.5,"sub-bullet-style":"circle","tabular":false,"text-direction":"ltr","tracking":0},"width":12.5}` and the built-from `text-model-12:sha256:3b6ae8e4433f373da417fc4c2da0a58979b2601ee0f531935e45d47d5a194e79`.

**Pieces.** A piece is, by `based-on`, a paragraph, with the bullets nested under it; a word, as Unicode's word boundaries split the text in the presentation's `locale`, with the punctuation that touches it, the earlier word taking what touches two, so “Hello, world! (yes) e-mail” is five pieces; or a character, one grapheme cluster, counted as typed, before `case`. A space counts only with `spaces`, and a line break never does. Delivered by paragraph, a paragraph no cue names stands from the start, and a text with a `text-path` enters all at once.

**Turns.** Pieces start one interval apart in their order, and each moves for `spread` intervals. By word or character, each paragraph and heading that holds a piece takes a turn, in reading order, or in reverse with `backward`, and plays the order on its own: from its own middle, or by its own shuffle. By paragraph, the order runs over the paragraphs, and those that start together take one turn. With no pause, a turn starts one interval after the last piece of the turn before starts, and `pause` holds only between turns: for N pieces, `progress` runs evenly over N − 1 + `spread` intervals, and with a `pause` above 0, over `pause` + `spread` − 1 more before each turn but the first. Where an order runs over n pieces, `center-to-ends` and `ends-to-center` start the two pieces equally far from the middle together, their starts spread evenly over n − 1 intervals, and two pieces start one after the other.

## <a id="steps"></a>Steps and keyframes

In the .mdpoint file.

### step

One step: the moves, cuts, and media starts that a click or the previous step sets off. Its times, and its keyframes' and cues', are in seconds, rounded to six decimal places. At `slides.<id>.steps[]`.

| key | required | values | description |
| --- | --- | --- | --- |
| `id` | yes |  | The step's id, unique on its slide. |
| `cues` |  |  | Events at set times in the step: a paragraph appearing, an audio object, a video, or a web video starting, or a clip playing an Action of a model or a 3D text. |
| `curves` |  |  | The step's animation, by object and parameter, such as card.opacity. |
| `loop-from` |  | 0 to 4294967296 seconds | Seconds into the step that it loops back to while waiting for the next click: before the later of its `min-duration` and its keyframe and cue times, not counting a paragraph's entrance. |
| `min-duration` |  | 0 to 4294967296 seconds | The least time the step lasts, in seconds. A later keyframe, cue, or entering paragraph extends it, and left out or 0, the step lasts as long as what it holds. |
| `name` |  |  | The step's name in the Animate list, on one line that isn't blank and has no control characters. |
| `repeat-count` |  | whole numbers, 2 to 64 | How many times the step plays before it completes. Left out, it plays once. |
| `start` |  | with, after | When the step starts: with the previous step, or after it ends. On the first step, either starts it when the slide's transition ends, except under a scroll. Left out, it waits for a click. |

**Clicks.** A step has no delay of its own: a keyframe's start delays its move. A first step that starts by itself plays after the slide's transition, and a scroll plays the next slide's first step with it, whatever its start. A click plays when any of its steps does. A step that holds keyframes or cues, each keyframe naming an object the slide lacks or a hidden one (its own `visible` or a group's above it is false) and each cue such an object or a video, web video or audio that doesn't start on click, takes no click of its own and stays in the file. A step with no keyframes and no cues is a pause and takes its click. A step that repeats plays alone on its click, and a file that breaks that reads with a warning, without the repeat. A step after one that loops while waiting starts when that step's first pass ends, and the loop plays on under it.

### curve

One property's animation in a step: its keyframes and what happens after the last one. A position can also be keyed as one point: `frame.xy` and `translation.xy` hold {x, y}, and `position.xyz` holds {x, y, z}, each keyframe holding every part. A step keys a position as a point or by its parts, not both: a step that keys both reads with a warning, and the point plays. An initial value sets each part on its own. At `steps[].curves["<object>.<parameter>"]`.

| key | required | values | description |
| --- | --- | --- | --- |
| `keyframes` | yes |  | The keyframes, one or more. |
| `loop` | with loop-keyframe | repeat, ping-pong | How it loops after its last keyframe until the step ends: `repeat` replays from `loop-keyframe` to the last, and `ping-pong` plays that back and forth. Left out, it plays once. |
| `loop-keyframe` |  |  | The id of the keyframe the loop starts at, where its move begins if it has a `start`. Left out, or naming no keyframe of the curve, it is the first. It needs `loop`. |

### keyframe

One keyframe: a value a property reaches at a time. Two keyframes of one property at one time read with a warning, and the later id plays. A keyframe's `null` clears its property, so its text style or default shows. At `steps[].curves["<object>.<parameter>"].keyframes[]`.

| key | required | values | description |
| --- | --- | --- | --- |
| `id` | yes |  | The keyframe's id, unique in its step among its keyframes and cues. |
| `time` | yes | 0 to 4294967296 seconds | When the property reaches the value, in seconds into the step. |
| `value` | yes |  | The value, written as the property is. `null` clears a whole property, but never a part of one, a point, `visible`, `rotation`, `scale`, a constraint's strength, `shape-type`, `icon` or `geometry`. |
| `exponential-scale` |  |  | Whether a scale move changes by a steady ratio, so a zoom looks even; from, to, or across 0, it moves at an even pace. Only `scale`, `scale.x`, `scale.y`, `scale.z`, and `crop.scale` take it. |
| `interpolation` |  | linear, ease-in, ease-out, ease-in-out, smooth, hold, anticipate, overshoot, anticipate-overshoot, bounce, elastic, or a record | How the value reaches the keyframe: gradually on a curve, or at once with hold. It's a named curve, a named curve with its settings, a cubic Bézier, or a spring. Left out, linear. |
| `interrupted` |  |  | The longer move this keyframe interrupts. Up to this keyframe, the motion follows that move's curve. |
| `oscillate` |  |  | A wave added to the value from this keyframe to the next, or to the step's end. On a looping curve, the wave plays again each time around. |
| `path` |  |  | A curved motion path for the move into the keyframe. It goes on a point keyframe. |
| `start` |  | 0 to 4294967296 seconds | When the move into the keyframe begins, in seconds into the step. It must come before time. Left out, it begins at the previous keyframe. |

**How a value moves.** A color moves in sRGB, a role as the slide's scheme colors it, with premultiplied alpha, so a color fading out to a transparent one keeps its own color as it fades. A gradient moves into one of its own type with as many stops, a radial one into one of the same `shape`, and a linear one with a `line` into another with one: each stop into the stop at its place, and its angle, line, or center into theirs. Any other two paints, a color and a gradient among them, keep the first until the keyframe. Path data, a `geometry`, `mask`, or `text-path`, moves each point to the point at its place when the two paths' contours, paired in order, have as many points and are closed alike, and any other two paths still morph, MarkdownPoint pairing their points itself.

### keyframe-interrupted

The move a keyframe interrupts: where it was going and when it would have ended. At a keyframe's `interrupted`.

| key | required | values | description |
| --- | --- | --- | --- |
| `value` | yes |  | Where the move was going. |
| `end` | yes | 0 to 4294967296 seconds | When it would have ended, in seconds into the step, at or after the keyframe's time. |

### keyframe-path

A curved motion path for the move into a point keyframe, in the move's own frame: 0 0 is where the move starts and 1 0 where it ends, and y points a quarter turn clockwise from x, as SVG's does, so for a move to the right a negative y bends the path up the slide. At a keyframe's `path`.

| key | required | values | description |
| --- | --- | --- | --- |
| `geometry` | yes |  | The path, as SVG path data from the move's start, 0 0, to its end, 1 0. It is one open contour of 2 to 8,192 points, in at most 1,048,576 characters. |
| `orient` |  |  | Whether the object turns to face along the path. |

**Along the path.** The object moves along the path at the share of its length the interpolation gives, and past either end along the path's direction there. A 3D position's path bends its x and y, and its z moves straight. With `orient`, a flat object, a text with its model among them, turns with the path's tangent, and a model turns about its parent's y to face where it travels across x and z. No other 3D object turns.

### keyframe-oscillate

A wave added to a property's value. Only a property with a single number that animates smoothly can take one. `volume` never can. At a keyframe's `oscillate`.

| key | required | values | description |
| --- | --- | --- | --- |
| `amplitude` | yes | any number | How far the value swings either way, in the property's own unit. |
| `frequency` | yes | more than 0 cycles a second | How many full cycles each second. |
| `phase` |  | −8589934592 to 8589934592 degrees | Where in its cycle the wave starts, 360 degrees to a cycle. Left out, it's 0. |
| `seed` |  | whole numbers, 0 to 4294967294 | The noise seed: the same seed gives the same noise. Left out, it's 0. |
| `wave-shape` | with seed, as noise | sine, triangle, square, sawtooth, noise | The wave's shape. Left out, it's sine. |

**Waves.** At a phase of 0, a sine, a triangle, and a sawtooth start at 0 and rise, and a square starts at 1. Halfway through each cycle, a square falls to −1 and a sawtooth from 1 to −1. A noise wave wanders smoothly at random, through 0 at the start of each cycle, never repeating, and the same for the same seed.

### interpolation

Named interpolations: how a value changes over a move, gradually on a curve or at once. Transitions take linear, ease-in, ease-out, and ease-in-out. A keyframe's or a text's interpolation may instead be a curve with its settings, a cubic Bézier of its own among them. At a keyframe's, a transition's, and a text's `interpolation`.

| name | required | values | description |
| --- | --- | --- | --- |
| `anticipate` |  |  | Pulls back before it moves. |
| `anticipate-overshoot` |  |  | Pulls back first, then passes the keyframe's value and settles back on it. |
| `bounce` |  |  | Falls onto the keyframe's value and bounces off it three times, each lower, never passing it. Its bounciness is 0.5. |
| `ease-in` |  |  | Starts slowly from the previous keyframe, as CSS's ease-in does. |
| `ease-in-out` |  |  | Starts slowly and ends slowly, as CSS's ease-in-out does. |
| `ease-out` |  |  | Slows down as it reaches the keyframe, as CSS's ease-out does. |
| `elastic` |  |  | Springs past the keyframe's value and swings into it, each swing smaller. |
| `hold` |  |  | Keeps the previous value until the keyframe's time, then jumps. |
| `linear` |  |  | Moves at a constant speed. |
| `overshoot` |  |  | Passes the keyframe's value and settles back on it. |
| `smooth` |  |  | Starts and ends gently, over a shorter part of the move than ease-in-out. |

**The curves.** `ease-in`, `ease-out`, and `ease-in-out` are CSS's curves of those names. As CSS's cubic-bezier() writes them, `smooth` is (0.25, 0, 0.75, 1), and with b the `back`, 1.70158 unless given, `anticipate` is (0.333333, 0, 0.666667, −b ÷ 3) and `overshoot` (0.333333, (b + 3) ÷ 3, 0.666667, 1): Robert Penner's back in and back out. `anticipate-overshoot` is his back in and out, `elastic` his elastic out, and `bounce` his bounce out at a bounciness of 0.5, as Blender's Back, Elastic, and Bounce draw them.

### keyframe-interpolation

A curve with its settings: how far `anticipate`, `overshoot`, or `anticipate-overshoot` pulls back or swings past, an elastic's swing, a bounce's bounciness, a spring's amount, or a cubic Bézier's two handles, named as CSS's cubic-bezier() names its four numbers. A curve with no settings is written as just its name, and so is a cubic Bézier that a named curve draws. At a keyframe's or a text's `interpolation`, as a named curve with its settings.

| key | required | values | description |
| --- | --- | --- | --- |
| `type` | yes | anticipate, overshoot, anticipate-overshoot, elastic, bounce, spring, cubic-bezier | The curve. |
| `amount` | with type spring | 0 to 1 | How far a spring swings past its keyframe, from 0, not at all, to 1. |
| `amplitude` |  | 0 or more | How large an elastic's swing is, as a multiple of the move. Left out, it's 1. |
| `back` |  | 0 or more | How far `anticipate`, `overshoot`, or `anticipate-overshoot` pulls back or swings past, as Robert Penner's back curves take it. Left out, it's 1.70158. |
| `bounciness` |  | 0 to 1 | A bounce's rebound speed as a fraction of its landing speed: 0 lands dead, 1 rebounds to its height each time. Left out, it's 0.5. |
| `period` |  | more than 0 seconds | How long one swing of an elastic lasts. Left out, it's 0.3 of the move into the keyframe, from where that move starts. |
| `response` |  | more than 0 seconds | The spring's natural period. A shorter one springs faster. Left out, the spring settles by the keyframe's time. |
| `x1` | with type cubic-bezier | 0 to 1 | The time of a cubic Bézier's first handle, as a share of the move. |
| `x2` | with type cubic-bezier | 0 to 1 | The time of a cubic Bézier's second handle, as a share of the move. |
| `y1` | with type cubic-bezier | any number | The value of a cubic Bézier's first handle, as a share of the change. It may stand below 0 or above 1, which can carry the move past an end. |
| `y2` | with type cubic-bezier | any number | The value of a cubic Bézier's second handle, as a share of the change. It may stand below 0 or above 1, which can carry the move past an end. |

**Springs.** A spring's `response` is its natural period, in seconds, as SwiftUI's is: how long one swing would take with no damping. Its damping ratio d falls evenly from 1, critical, at an `amount` of 0 to 0.3 at 1. Damping lengthens each swing it shows to the response divided by √(1 − d²), about 1.05 times the response at an amount of 1. A Position constraint's spring reads the same.

### cue

An event at a set time in a step. A clip plays an Action of a model's or a 3D text's GLB `file`; a text built from an `extrusion` has none, so a clip on it plays nothing, with a warning. At `steps[].cues[]`.

| key | required | values | description |
| --- | --- | --- | --- |
| `id` | yes |  | The cue's id, unique in its step among its keyframes and cues. |
| `time` | yes | 0 to 4294967296 seconds | When it happens, in seconds into the step. |
| `type` | yes | text, audio, video, web-video, clip | What it starts: a paragraph appearing, an audio object, a video, or a web video playing, or a clip. A clip plays one of the Actions of a model or a 3D text, as a Motion Clip does in Cinema 4D. |
| `object` | yes |  | The id of the object it acts on: for a clip, a model or a 3D text. |
| `action` | with type clip |  | The name of the Action that a clip plays; an unnamed one is Animation 1, Animation 2, and on, in file order. |
| `blend-in` |  | 0 or more seconds | How long the clip takes to blend in fully over the model's current motion. Left out, it is fully blended in from its start. |
| `clip-scale` |  | more than 0 | How much longer a clip's Action plays than its file says, as Maya's Clip Scale: 2 is half speed, 0.5 double. Left out, it's 1. A model's clip with a stride ignores it. |
| `clip-trim` |  | 0 or more seconds | The part of the Action that plays, as a start and an end in seconds into the Action. |
| `loop` |  | repeat | `repeat` plays the Action again from its start each time it ends. Left out, it plays once. |
| `paragraph` | with type text |  | The id of the paragraph that appears, as `<!-- id: … -->` ends its last line; a reader warns of an id no paragraph of the text carries. |
| `stride` |  | more than 0 meters | How far the model travels per cycle of its Action, in the GLB's meters. The Action's timing then follows the model's travel. A 3D text's clip ignores it. |

**Action names.** A clip names an Action by its name in the file, matched exactly. An Action with no name, or an empty one, is Animation and its number in the file, from 1, as Animation 1. One whose name an earlier one has, or whose generated name is taken, takes the first of name 2, name 3, and on not yet taken, the names the file gives reserved first: Walk, Walk, Walk 2 read as Walk, Walk 3, Walk 2.

## <a id="schemas"></a>JSON Schemas

Each JSON file has a JSON Schema, draft-07, named by the kind the file states, in [schemas/v1.0](schemas/v1.0/). That folder states version 1.0. Each minor version's schemas are in a folder of their own, kept as that version published them. A schema's `$id` is https://markdownpoint.com/format/schemas/v1.0/ and its file name. Refer to a schema by its `$id`. Its `definitions` are its own and may change. A schema checks a file's keys, their values, and the keys a record needs. It refuses a key of a later minor version, which MarkdownPoint reads. MarkdownPoint also reads a number to six decimal places before checking it, where a schema checks the number as written. Its patterns are ECMA 262 regular expressions, as draft-07 names them, and use lookahead: a validator whose engine has no lookahead, as RE2 has none, can't compile them.

What a schema doesn't check, MarkdownPoint does:

[presentation.schema.json](schemas/v1.0/presentation.schema.json):

- A locale names each variant once.
- Every file a background or an object names is in the presentation's media or generated folder.
- A composition's id is not a slide's too. No composition contains itself, directly or through another. The instance that closes the loop draws nothing, with a warning. A composition's text has no `model`.
- A composition's controls have unique ids. A number control's minimum is below its maximum. Its default lies from its minimum to its maximum. A choice control's options have unique ids. Its default is one of their ids.
- The ids `camera` and `world` belong to the camera and the World alone.
- A slide's or a composition's objects have unique ids. An own object's id isn't one its overrides change.
- A 3D object's rotation in degrees has no w. In quaternion mode, it gives w, x, y, and z. A quaternion's length as written isn't 0, and MarkdownPoint divides each part as written by it before reading the part to six decimal places.
- A web video's address names a video.
- A path's `geometry`, an image's `mask`, and a text's `text-path` are well-formed SVG path data, starting with a move. An icon's `icon` names an icon in the bundled Lucide set. A video's or an audio object's `media-trim` ends after it starts. An object's constraints have unique ids.
- A text's enter or exit takes `spaces` only with based-on `character`. It takes a `seed` only with order `random`. An enter's `delivery` takes based-on `paragraph`. Its order, spread, pause, and progress then stand at their defaults.
- A video's file, a shape's `shape-type`, and an icon's `icon`, the name it draws, may be left out only where a composition's control binds them. A value written beside a binding is left out with a warning.
- An override's key and value apply only to an inherited object that takes them. Others wait with a warning.
- An override that makes a growing text box's frame.x or frame.y name another point gives that x or y. Without it, the change waits with a warning.
- An animated parameter names a property its object takes. A keyframe's value is one that property reads. A name or a value no object's property takes is refused, and one only its own object doesn't take is left out with a warning.
- `exponential-scale` goes only on a keyframe of `scale`, `scale.x`, `scale.y`, `scale.z`, or `crop.scale`. `oscillate` goes only on a parameter of one number that moves smoothly, and never on `volume`, which only fades. An `initial` value sets no point parameter, such as `frame.xy`, only its parts.
- A slide's or a composition's steps have unique ids. A step's keyframes and cues have unique ids together. A keyframe's move starts before its time. An interrupted move ends at or after the keyframe's time. Only a noise wave takes a seed.
- A step's loop-from comes before its end.
- A composition's steps take no cues. Nor do they take a loop-from. Either is passed over with a warning. Every pass counted, they last at most 4,294,967,296 seconds, or the composition reads with a warning.
- A motion path stands only on a point keyframe. It is one open contour from 0 0 to 1 0. A clip's trim ends after it starts.
- A comment's words are well-formed Unicode.

[master.schema.json](schemas/v1.0/master.schema.json):

- A font family's name starts with a letter or a digit of any script and holds only letters, digits, spaces, periods, underscores, and hyphens. No two `font-files` keys name one family, matched as `fonts` matches a family.
- A brand color a scheme names is one the brand has.
- The scheme named light is light, and the one named dark is dark.
- The words in `text` belong to the master's own text, table, chart, and shape objects.
- Guides have unique ids.
- Its objects follow the presentation's object checks.

[layout.schema.json](schemas/v1.0/layout.schema.json):

- The words in `text` belong to the layout's own text, table, chart, and shape objects.
- An image names a video only as a placeholder's sample. A placeholder names one file, not one per scheme.
- Its objects and overrides follow the presentation's object checks.

[theme-package.schema.json](schemas/v1.0/theme-package.schema.json):

- No two entries name the same file.

[version.schema.json](schemas/v1.0/version.schema.json):

- Nothing beyond its schema.

[style-library.schema.json](schemas/v1.0/style-library.schema.json):

- Nothing beyond its schema.

[image-generation.schema.json](schemas/v1.0/image-generation.schema.json):

- A prompt is in Unicode's composed form, NFC.
- An output holds no more pixels than an image can. It has the aspect ratio asked for.
