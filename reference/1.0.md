# MarkdownPoint file format reference

This reference lists every key in the files and what it does.

In each table, the required column says when a record needs the key. Yes means always. Otherwise the column names the case, such as "with max". The values column lists the words or numbers the key can be set to. A range includes both of its ends. On a key with an x and a y, a range applies to each of them.

## <a id="files"></a>Files

### <a id="presentation-folder"></a>The presentation's folder

A presentation is a folder with two files at its root: `slides.md` and `presentation.mdpoint`. Their names can be in any letter case. The folder's name is the presentation's name. The presentation doesn't open if its root has another .mdpoint file. It doesn't open either if its root has another .md file whose name starts with slides in any letter case and goes on with any character but a letter or a combining mark. Such a file can be `Slides 2.md`, `slides2.md`, or a sync service's conflicted copy.

- [`slides.md`](#slides-md): the sections, the slides' order and text, and the presenter notes.
- [`presentation.mdpoint`](#presentation-mdpoint): the theme, the slides' objects and animation, and the settings. It is JSON.
- media/: the author's files.
- generated/: the files MarkdownPoint makes, such as a text's 3D model.
- themes/: the presentation's [themes](#theme-folder).
- versions/: the presentation's [saved versions](#versions).

Files and folders whose names start with `.markdownpoint` belong to MarkdownPoint. Everything else in the folder belongs to the author.

### <a id="theme-folder"></a>A theme's folder

A theme is a folder in themes/. The folder is named after the theme's key. Its root has the theme's [master](#the-master) in master.json and a .json file for each [layout](#layouts). A layout's file is named after the layout's key.

### <a id="theme-package-file"></a>A theme package

A theme package is one .mdptheme file. The file is a ZIP archive of one folder. The folder is named after the theme's key, and it contains [manifest.json](#theme-package), the theme's JSON files, and the files they name. The folder has one master. A file or folder whose name starts with a dot is skipped at any depth and isn't installed. Finder's folder icon file is skipped the same way. That file's name is `Icon` followed by a carriage return (U+000D). manifest.json lists every one of the theme's files in the folder and only those. A package is refused whole when its folder lacks a listed file or has a file whose size or SHA-256 digest isn't the one listed. It is refused too when the folder has a file that isn't listed, except a skipped file, manifest.json, and the files in previews/ and example/.

The folder can also have a previews/ folder and an example/ folder. Their files aren't the theme's files, and manifest.json doesn't list them. In previews/, cover.jpg is a picture of the theme. In previews/slides/, 1.jpg is a picture of the first example slide, 2.jpg of the second, and so on. example/ has a presentation that a new presentation can start from. It can have only presentation.mdpoint, slides.md, and the media/ and generated/ folders.

The archive is a classic ZIP file (APPNOTE 6.3). Each entry is deflated or left uncompressed, and its name is in UTF-8. A writer sets general-purpose bit 11 and writes no data descriptor. A reader also accepts an entry without bit 11, a deflated entry with its level in bits 1 and 2, and an entry whose checksum and sizes follow its data in a data descriptor. The descriptor can start with its signature. When an entry without bit 11 has a name that isn't valid UTF-8, the name is in code page 437. The archive has no encryption, ZIP64 record, or symbolic link, and it isn't split into parts. A reader skips a `__MACOSX` folder at the archive's root. Finder's Compress command puts each file's Finder record there. Apart from what a reader skips, the root has only the theme's folder.

### <a id="paths"></a>File names and paths

A file path is relative to the presentation's folder or the theme's folder. It has / between names. A name can't be empty, `.`, or `..`. It can't start with a dot or end in a space or a dot. It can't contain a backslash, <, >, :, ", |, ?, *, #, or a control character. Everywhere in the format, a control character is one of U+0000 to U+001F or U+007F to U+009F. Blank text has only the white space that ECMAScript's `trim` removes. In any letter case and with or without an extension, a name can't be CON, PRN, AUX, NUL, COM1 to COM9, LPT1 to LPT9, COM¹ to COM³, or LPT¹ to LPT³. A path is in NFC. A path names each file as its folder lists it, and the two are compared in NFC. A name is at most 255 bytes in UTF-8. No folder has two names that are the same under Unicode's canonical caseless match. It uses the full case folding of Unicode 17.0.0. Under it, ß and SS are the same.

A presentation's files are under media/ or generated/. A theme's files can go anywhere in its folder except at its root under the package's three names: manifest.json, previews, and example. A name that matches one of them under the caseless match, such as Previews, is refused. A theme package spells all three in lowercase. An image file's name ends in .png, .jpg, .jpeg, .gif, .webp, .svg, .avif, or .bmp. A video file's name ends in .mp4, .m4v, .mov, .webm, or .ogv. An audio file's ends in .mp3, .m4a, .wav, .ogg, or .flac. A model's ends in .glb, and an embedded font's in .eot. The extension can be in any letter case. A file reached through a symbolic link or an alias is never one of the presentation's files.

### <a id="format-version"></a>The format version

Every file states its format version in `markdownpoint`. It is a major and a minor number in quotes, such as "1.0". Each number has at most nine digits and no leading zero. Every key in this reference is from version 1.0. MarkdownPoint 1.x opens any version 1.x file. A later minor version only adds what an earlier MarkdownPoint can skip, such as a key, a word, an object type, or a number outside a range. The earlier MarkdownPoint draws nothing for it or uses its key's default. A `shape-type` it doesn't know draws as a rectangle. In an override, it draws what the object inherits. When it can't read a keyframe's `time` or `value`, it skips the keyframe's whole curve. A word it can't read can decide which keys a record needs or how they are read. Such a word can be a text's `auto-size` when its frame leaves out a side, or a 3D object's `rotation-mode`. The earlier MarkdownPoint then draws nothing for the whole record and keeps it as written.

In a later minor version's .md file, a marker-shaped line starts a block when its word is neither `id` nor one of the earlier MarkdownPoint's markers. The earlier MarkdownPoint keeps the block as written, shows nothing for it, and ends it at the next marker. Each save writes the block back after the block it followed. In a file of the reading MarkdownPoint's own minor version or an earlier one, such a line is a note. A marker that a minor version adds is a marker only in a file of that version or later. A misspelling of it is an error only in those files. In an earlier version's file, either line is a note. A file in the layout MarkdownPoint writes is saved back to the same bytes.

A later minor version can widen a key's range. It can't raise these limits:

- 8,192 on each side of a slide
- a blur radius of 250 and a shadow size of 100 when the slide's shorter side is 1080 or less
- 25,000 cells in a table
- 8,192 points and 2,097,152 characters of path data
- 1,000,000 characters in the .md file's frontmatter and in each of its blocks
- 512 objects beyond a slide's own
- groups nested 200 deep
- lists and quotes nested 100 deep
- inline Markdown nested 100 deep
- a model file's limits
- 268,435,456 pixels in a generated image
- JSON nested 256 levels deep

A save writes the file's version or the saving MarkdownPoint's, whichever is later. A presentation's .mdpoint file and .md file are saved at the same version. That version is the latest of the two files' versions and the saving MarkdownPoint's own. A save never lowers a file's version. A file of a newer major version needs a newer MarkdownPoint.

A JSON file of a version MarkdownPoint knows has only the keys this reference lists, and no key twice. Any other key is an error. Outside an override, a key that only another kind of its record uses is an error too. For example, `direction` is an error on a `cross-dissolve` transition. Chart types and shape kinds are the exception. A chart can have a key that only another chart type uses, and a shape can have a key that only another shape kind uses. The chart or shape draws without that key. No version adds a key with a capital letter. So an unknown key with a capital letter is an error in a JSON file of any version. An `id` key in a keyframe or a cue and a `target` key in a curve are errors in any version too. A keyframe or a cue is already under its id, and a curve under its "object.parameter" key.

### <a id="ids"></a>Ids

An id such as title-card starts with a lowercase letter from a to z. The rest is a to z, 0 to 9, and single hyphens. It ends with a letter or a digit. Where ids are put in order, they are compared character by character. A hyphen comes before a digit, and a digit comes before a letter. So `k10` comes before `k9`. Three ids are lowercase UUIDs instead of ids like title-card. They are a presentation's id, a save's id, and a theme's id in its master. A theme's key and a layout's key are ids that every supported system can use as a file name. A theme's key is at most 255 characters and a layout's at most 250. A layout's key can't be master or manifest. The names a theme gives its schemes, color roles, brand colors, and text styles are spelled as ids. A JSON object's members have no order. The order the theme's layouts, schemes, text styles, and brand colors show in is set by the master's `layout-order`, `scheme-order`, `text-style-order`, and `brand.color-order`. Beyond the roles every scheme has, a scheme's other roles show in name order. A font family's name starts with a letter or a digit in any script. The rest is letters, combining marks, digits, spaces, dots, underscores, and hyphens. It doesn't end with a space. A `font-files` key is spelled the same way.

### <a id="colors"></a>Colors

A color is a role in the theme's color scheme, such as accent, or a hex color in sRGB. A hex color is written #RGB, #RGBA, #RRGGBB, or #RRGGBBAA. Its alpha is straight, not premultiplied. The colors of a light, the World, a shadow, and a fade through color have no alpha. Their hex colors are written #RGB or #RRGGBB. Where a key's color is drawn and names a role the slide's scheme lacks, it causes an `unknown-color-role` warning and draws as `text`. A fade through color then fades through black.

### <a id="units"></a>Units

A canvas unit is one pixel of the slide at full size. The default `font-size`, `inset`, `column-gutter`, `column-widths`, and `stroke-weight` of an object that leaves them out, an area light's `size`, and the render effects' `distance` are lengths for a 1920 × 1080 slide. Each draws at that length times the master's `default-scale`, and so do a quote's inset and a rule's line. An icon's `stroke-weight` is in icon units and draws as it is. In 3D, a canvas unit is the theme's `unit-scale` in meters. An icon unit is a 24th of the frame's width across and a 24th of its height down. Each icon is drawn on Lucide's square. The square is 24 icon units wide. It stretches to fill the frame. A blur is measured by its radius. CSS `box-shadow` uses the same radius. The radius is twice the Gaussian's standard deviation. CSS `filter: blur(8px)` is a blur of 16. An object's blur and shadow draw no wider than their slide allows. The limit is on their size before any scale is applied. A blur's radius draws at most 250 and a shadow's size at most 100 when the slide's shorter side is 1080 or less. The limits grow in proportion on a larger slide. They are 500 and 200 at 3840 × 2160. An object's blur or shadow past them is kept as written, draws at the limit, and causes an `effect-size-limit` warning. A background picture's shadow has the same limits. They don't apply to a text's drop shadow. A text's `tracking`, `text-stroke-weight`, and drop shadow are in ems of its `font-size`. A heading in the text uses the same lengths as the rest of its words. An entrance's or exit's look is the exception. Its `offset` and `blur` are in ems of each piece's own font size. On a shape, `tracking` and `text-stroke-weight` are in ems of its words' `font-size`, and its drop shadow is in canvas units. On a chart, `tracking` and `text-stroke-weight` are in ems of the size of the words they apply to. A mark's `tracking` is in ems of the size of its own words. Code's words are 0.92 times the size of the words around them. In a heading, code is 0.92 times the size of the heading's words.

A light draws no brighter than the GPU's 32-bit floats can hold. The intensity its shaders get is at most 1 × 10³⁰. For a directional light, that is its `intensity` times π. For a point or spot light, it is the light's watts over 4π and over the square of `unit-scale`. For an area light, it is the light's watts over π, over its area in square canvas units, and over the square of `unit-scale`. A brighter light is kept as written and draws at the limit.

### <a id="numbers"></a>Numbers

Every number is read as the IEEE 754 double nearest to it. ECMAScript's numbers are doubles too. The double is rounded to six decimal places the way ECMAScript's `Number(x.toFixed(6))` rounds it. `toFixed` rounds a half away from zero. A negative zero is read as 0. Then the number is checked against its range. 1.0000004 is read as 1. −0.0078125 is halfway between −0.007812 and −0.007813. It is read as −0.007813. The double nearest 0.1234565 is slightly under it. So 0.1234565 is read as 0.123456. A theme's `unit-scale` is checked against its range as written. Then it is rounded to 12 significant digits the way ECMAScript's `Number(x.toPrecision(12))` rounds it. A byte count, an image's size in pixels, and a `parent-inverse` are read exactly as written. A chart cell's number is read as the double nearest to it and isn't rounded to six places. The coordinates of each point and handle in path data are rounded to six decimal places once the path is absolute and its curves are cubic.

### <a id="points"></a>Points

A value of x and y has both parts, and a value of x, y, and z has all three. Such values include an `anchor-point`, a crop's `focal-point`, a group's `tilt`, a repeater's `position`, and a model's, a light's, or a shadow catcher's `position`. One with a part left out isn't valid. Only the camera's `position` and an area light's `size` can leave out parts. In an override, a key that changes only some of its parts gives only those parts.

### <a id="links"></a>Links

A link is an http or https URL with a host, a mailto: or tel: address, or slide: followed by a slide's id. http, https, mailto, and tel can be in any letter case, and slide: is lowercase. A link has no spaces or control characters. An http or https URL has no backslash. A link to anything else, or to a slide that isn't there, is still a link but does nothing. A link to a skipped slide does nothing in the show or in a PDF until the slide is shown again.

### <a id="code"></a>Code

MarkdownPoint runs no code from a presentation's folder or a theme. A text shows an HTML tag as plain text, and an SVG image's scripts don't run. The one exception is a web video. Its YouTube or Vimeo player runs the provider's own scripts.

## <a id="slides-md"></a>`slides.md`

#### frontmatter

MarkdownPoint reads these keys, each on one line as key: value. A value can be in single or double quotes, and a comment can follow it. Any other spelling that YAML reads as one of these keys, such as `"footer":`, is refused. One of these keys that appears twice is refused too. Other keys are kept as written. A notes app can add its own keys, such as tags, and the presentation still opens. The file's first line is `---`. A byte order mark before it is skipped. Each fence line is `---` followed by its line end. The frontmatter's lines end in LF or CRLF. MarkdownPoint writes `markdownpoint`, `id`, `save-id`, and `footer` in that order.

Where: the frontmatter at the top

| key | required | values | description |
| --- | --- | --- | --- |
| `markdownpoint` | yes |  | The file's format version in quotes, such as "1.0". Its major and minor numbers each have at most nine digits and no leading zero. |
| `id` | yes |  | The presentation's id. The .mdpoint file has the same id. |
| `footer` |  | one line with no control characters or line breaks | The footer text. Every slide with a footer field shows it. Without quotes, a space followed by `#` starts a comment. Quote a footer that YAML 1.2's core schema reads as null, a boolean, or a number. |
| `save-id` |  |  | The id of the save that last changed the file. A save of a presentation in a connected Dropbox account's folder writes a new id only when it changes the file's words or the file has no `save-id`. Other saves and other tools leave it unchanged. |

**`save-id`.** A save that writes both files writes the same `save-id` into both. A save that writes only the .mdpoint file puts the frontmatter's `save-id` in that file's `md-save-id`. While a sync service has delivered only one of a save's two files, the .md file's `save-id` can disagree with the one the .mdpoint file names for it. That isn't an error.

#### markers

Markers divide the .md file into sections, slides, and their text. A marker is the same with spaces or tabs before or after it, after its `<!--`, after its colon, or before its `-->`. Each marker ends with a line break, even at the end of the file. A marker between code fences is code. A top-level code block with a marker in it must be closed. Each of a slide's own texts has a text marker, even when its text is empty. A table or a chart has its Markdown table under its marker. A shape has a marker once it has words. When a slide's own text has no marker, its text is empty. When the slide's own table or chart has no marker or an empty one, its cells are empty. Each causes a `missing-text-block` warning. How many rows and columns such a table or chart has is under **Keys an object draws without** in the `object` record. A table or a chart is skipped with an `invalid-table` error when its marker's words aren't one valid table. What makes a table valid is in the `table` row and under **Tables** in the `markdown` record. A layout's placeholder gets no words from the layout. It needs a text marker only once it has words. Until then, its empty marker means the same as none. A text marker is ignored when no object on its slide accepts its words, and it causes an `ignored-text-block` warning. Of the objects a slide inherits, only a placeholder accepts words. No two text markers on a slide have the same id.

Where: a line of its own in the body

| marker | required | values | description |
| --- | --- | --- | --- |
| `section` |  |  | `<!-- section: id -->` starts a section. The section has the slides that follow, up to the next section marker. Its id is unique among sections. The level-1 heading after the marker is the section's name. |
| `slide` |  |  | `<!-- slide: id -->` starts a slide. Each slide has one, and the markers come in presentation order. |
| `text` |  |  | `<!-- text: id -->` starts an object's text. With no words under it, the block is empty. |
| `notes` |  |  | `<!-- notes -->` starts the presenter notes of its slide. |

**Sections.** A section's block has one level-1 heading and nothing else. The section's name is the heading's words as plain text. Marks, code, spans, and links give only their words, and an autolink gives its address. Anything else in the heading, such as a field, an image, a hard line break, or a comment, is an error. The name is read in Unicode's composed form (NFC) with one space between its words. The name has no control character. A heading with no words is an error. Once there is a section, every slide must be in one. A slide before the first section is an error.

#### body

How the body is divided, and what is kept as written. A comment line is marker-shaped when it is one word, or a word followed by a colon and an id or two ids joined by a dot. Such a word is a run of the letters a to z, or several runs joined by single hyphens. Spaces or tabs can go in such a line where a marker allows them. Only a marker starts a slide. The slide continues until the next slide or section marker, or the end of the file. A paragraph id in presenter notes is never shown, and no step can name it.

Where: the body, between and inside the markers

| form | required | values | description |
| --- | --- | --- | --- |
| `escape` |  |  | A marker-shaped line, or a line that looks like a misspelled marker, stays in its block when a backslash follows its `<!--`. An example is `<!--\ todo -->`. Outside code, MarkdownPoint escapes every such note and doesn't show the backslash. |
| `blank-line` |  |  | Blank lines only separate. Several blank lines in a row are the same as one. Under a marker or before the next one, they mean nothing. In a code block that's never closed, each is code, except a blank last line of the file. |
| `comment` |  |  | An HTML comment in a text or notes block is a note. It is kept but not shown. An `id` comment is the exception. |
| `unsupported` |  |  | Markdown that MarkdownPoint doesn't support is kept as written and shown as plain text. MarkdownPoint doesn't support images, footnotes, task-list boxes, bare addresses, or reference links. The only HTML tags it supports are `<br>`, `<sup>`, and `<sub>`. |

**Misspelled markers.** A comment line that starts with a marker's word in any letter case and has at most one other word is a misspelled marker. It is an error, even with a closing slash or words after `-->`. A comment that starts with such a line is a note when its first `-->` ends a later line and comes before the next `<!--`.

**Merge conflicts.** A merge conflict runs from a line that starts with seven `<` followed by a space to a later line that starts with seven `>` followed by a space. These are git's default conflict markers. Such a conflict is an error in the frontmatter and anywhere outside a fenced code block. Inside a fenced code block, the conflict's lines are code. A line of seven `=` alone is no conflict.

#### markdown

The Markdown that text, tables, and presenter notes use.

Where: text blocks, table cells, and presenter notes

| form | required | values | description |
| --- | --- | --- | --- |
| `paragraph` |  |  | A blank line separates paragraphs. A line ending inside a paragraph is a space. End the line with a backslash or two spaces to break it. |
| `id` |  |  | A paragraph's id ends its last line, as in `<!-- id: k3x9a2 -->`, or is alone on the next line. A list item's ends its first paragraph. When an id repeats, the later paragraph has none. |
| `heading` |  |  | `# Heading` to `###### Heading` are headings. A line underlined with `===` or `---` is a level-1 or level-2 heading. |
| `bulleted-list` |  |  | Lines starting with `- `, `* `, or `+ ` are a bulleted list. Indent for deeper levels. Any other paragraph between items ends it. |
| `numbered-list` |  | a first number from 0 to 999,999,999 | Lines starting with `1. ` or `1) ` are a numbered list. It starts at its first number and counts up. Any other paragraph between items ends it. |
| `quote` |  |  | Lines starting with `> ` are a quote. |
| `code-block` |  | bash (sh, shell, zsh), c, cpp (c++, cc, cxx, h, h++, hh, hpp, hxx), csharp (c#, cs), css, diff (patch), go (golang), java (jsp), javascript (cjs, js, jsx, mjs), json (json5, jsonc), kotlin (kt, ktm, kts, ktx), markdown (md, mkd, mkdown), php, python (gyp, ipython, py), ruby (gemspec, irb, podspec, rb, thor), rust (rs), sql, swift, typescript (cts, mts, ts, tsx), xml (atom, html, plist, rss, svg, wsf, xhtml, xjb, xsd, xsl), yaml (yml) | Lines between fences of three or more backticks or tildes are a code block. It is colored for its language by highlight.js 11.12.0. A marker in it is code. |

**Empty paragraphs.** A paragraph of only `<br>` tags has one line break fewer than it has tags. An empty paragraph is a line that starts with `<br>` and has only spaces or tabs after it.

**Paragraph ids.** When a paragraph is split, its first part has the id. When paragraphs are joined, the first one's id stays.

**Bold and italic** follow CommonMark except in one way. A run of `*` with punctuation on one side and any character but white space or punctuation on the other can both open and close.

**Highlight and strikethrough.** Two `=` or two `~` open where the next character isn't white space, whatever comes before them. The words they mark are at least one character long and end in one that isn't white space. The first two after such an end close them. Two inside brackets close nothing opened outside them. Two inside code, an HTML tag, an autolink, a picture, a span's braces, or a link's address or title close nothing at all. Neither does an escaped `=` or `~`. So `File format==.==` highlights the period.

**Superscript and subscript.** `<sup>` and `<sub>` can be in any letter case, and spaces and tabs can go before their `>`. Tags of the same name pair up as they nest. So in `<sup>a<sup>b</sup>c</sup>`, the inner tag closes at the first `</sup>` and the outer one at the second. A closing tag inside code, another tag, an autolink, a picture, a link, or a span closes nothing opened outside it. A `*`, `_`, `==`, or `~~` inside the tags closes nothing opened outside them either. When a `<sup>` is inside a `<sub>` or a `<sub>` inside a `<sup>`, the inner one counts. No word is both. Spaces at the start and end of the words between the tags aren't raised or lowered. A tag with attributes, one never closed, or a pair with only white space or nothing between them is HTML. It is kept as written.

**Code blocks.** Lines indented by four spaces or a tab are also a code block. A fence's language name can be in any letter case. Code in another language or in none shows uncolored. The fence's language name is kept as written. The words after the language are the fence's options. They are in braces as Slidev writes them. `{lines:true}` numbers the lines. Any other option is kept as written.

**Escapes.** A backslash before punctuation makes it plain text. Outside code, a character reference such as `&amp;` or `&#169;` is read as its character. An address written without `<` and `>` or a link's brackets stays plain text.

**Reference links.** A reference link such as `[text][label]` stays as written and shows as plain text in every 1.x version. A definition line such as `[label]: address` does too.

**Spans.** A span's attributes are `color`, `font-weight`, and `font-style`. They can come in any order. A key is a lowercase letter and then lowercase letters, digits, and hyphens. There is no space on either side of its `=`. A bare value is one or more characters with no white space, quote, or brace. Braces with anything else in them make no span. The brackets and braces then show as written, and the words keep their marks. Each value can be bare or in single or double quotes. A quoted value has no quote of its own kind, and a backslash in it is a backslash. A value stays on one line. A span's closing bracket pairs with its opening one. An escaped bracket or one in code doesn't count. A span can have any inline Markdown in it, even a link or another span. An inner span's color, weight, or font style replaces the outer one's. Spaces, tabs, or one line break can go between the attributes and inside the braces. A span with any other key, a repeated key, or a value its key doesn't accept stays as written in the file. MarkdownPoint skips that attribute and applies the others. When a key repeats, only its first counts. An attribute from a later minor version is skipped the same way. Inside another span, a value its key doesn't accept still replaces the outer span's value with none. A span with no attributes, `[words]{}`, groups its words and gives them no formatting. A bold word is drawn at bold's weight. Otherwise a word is drawn at its own weight. A word with no weight of its own and with a mark is drawn at its text style's weight for that mark. Any other word is drawn at its block's weight. A word in `*text*` is drawn italic. Otherwise a word with `font-style=normal` stands upright, and any other word is italic where its text's `font-style` is `italic`.

**Nesting.** Lists and quotes nest at most 100 deep. Inline Markdown, such as bold, a link, or a span, has the same limit. Deeper than that, a list item's bullet or number and a quote's `>` are plain text. Inside 100 levels of inline Markdown, the words are plain text as written. Notes and fields there are plain text too.

**Headings** are 2, 1.5, 1.17, 1, 0.83, and 0.67 times the text's size. Their weight is 700, or the text's weight where that's heavier. On a path, a heading has the text's size and weight.

**Tables.** In a text's or a shape's words, or in presenter notes, a table is Markdown that MarkdownPoint doesn't support. A body row can't have more cells than the header row. A table or a chart's table has at most 25,000 cells. They are counted as its rows times its columns. Two authors adding rows and columns at once can pass that. Such a table causes a `table-cell-limit` warning and draws only its first rows within 25,000 cells. No cell can be added to it until rows or columns are deleted. MarkdownPoint writes such a table's header row and divider row in full. It writes each body row up to its last cell with words, or as one empty cell when none has words. GFM reads the cells left out as empty. MarkdownPoint writes every other table's rows in full. Each cell is one line. Outside code, its words can't have a character reference such as `&#10;` that names a line feed or a carriage return. A `[words](address "title")` link can have one in its address or title. In a cell, `\|` is a pipe. One code span can't have a pipe after an odd run of backslashes. MarkdownPoint cuts such code before that pipe and puts every other piece in a `[…]{}` group. The pieces are read as one run of code.

**A chart's table.** It names its series in the header row, after the first cell. It names its categories in the first column. Its other cells are numbers in Latin digits. They are written the same way whatever the presentation's `locale`. A period marks decimals. The whole digits are ungrouped, or grouped by threes with commas or with spaces, never both. A number can be written 1500.3, 1,500.3, or 1 500.3. That space can be a space, a no-break space, a narrow no-break space, or a thin space. MarkdownPoint reads each spelling as the same number. The next save that writes the file writes it as 1500.3. A JSON number also marks its decimals with a period and groups no digits (RFC 8259). When a chart's table has more than 25,000 cells, its numbers are kept as written. A slide shows a chart's numbers in the decimal mark, group mark, and group widths that Unicode CLDR 48.2.0 sets for the presentation's `locale` in its latn numbering system. In Swedish, 1,500.3 shows as 1 500,3, and in Hindi, 1,500,000 shows as 15,00,000. A slide groups a number's whole digits when there are four or more. In English, 2026 shows as 2,026. A number can have a sign, a prefix, or a suffix, such as $ or %. A minus is a hyphen-minus or the minus sign U+2212. A prefix or a suffix has no digit 0 to 9. So CO2: 40 has no value. A period right after a letter, or after a mark such as a vowel sign on a letter, ends an abbreviation in the prefix. Rs.1,500 and रु.1,500 are both 1500. Any other period or comma at the end of the prefix leaves the cell without a value. So $,5 has no value. A negative number can be in parentheses, as in (1234.50), or end with a minus, as in 1234.50 kr-. A parenthesis with no partner on the number's other side belongs to the prefix or suffix. A minus after a colon, a comma, or a period belongs to the suffix too. 100:- is 100. A cell that contains no number has no value. So 1,23 and 1.234,5 have no value. A cell after the first column whose words have a digit 0 to 9 but no value causes a `chart-cell-no-value` warning. The warning names the first such cell. A cell has no value either when its number runs through an address. The address can be one that GFM links in the cell's words, such as `https://example.com/1,234`, `www.example.com/1,234`, or `user1@example.com`. It can also be an autolink, such as `<foo:1,234>`. A cell's number is read from its words once their Markdown is parsed. So `**40**` is 40, a link's words count unless they are its address, and a comment is left out. A field counts as written. So `{{slide-number}}` has no value. A pie or a donut draws the first series' positive values. A counter counts to the number in the second cell of the first body row, or to 0 if that cell is blank or isn't there.

**Fields.** `slide-number` is the slide's number among the shown slides, counted from 1. `slide-count` is the number of shown slides. On a skipped slide, `slide-number` shows nothing. With the slides A, B, and C, and B skipped, `{{slide-number}} of {{slide-count}}` on C shows 2 of 2. `section-number` is the number of the slide's section among the sections that have a shown slide, counted from 1. A section with no shown slide has no number, and the field shows nothing there. `section-name` is the section's name. Both are empty for a slide that isn't in a section. `footer` is the footer from the frontmatter. Without one, the field shows nothing. `date` is the presentation's `date` with a full year and a two-digit month and day. How the date is written is set by Unicode CLDR 48.2.0 for the presentation's `locale`. The date uses the Gregorian calendar and Latin digits. So March 4, 2026, is 2026-03-04 in sv-SE and 03/04/2026 in en-US. When CLDR doesn't have a locale's language, the date is written as in en-US. Without a `date`, the field stays as written. A field's value is inserted as text. It's never read as Markdown or as a field. In code and in a link's address, `{{name}}` stays as written.

## <a id="presentation-mdpoint"></a>`presentation.mdpoint`

A key that names an object the slide doesn't have is skipped with a warning, and the rest of the slide plays. Such a key can be a parameter under `initial` or in a step, a cue, a constraint's target, a group's or a 3D object's parent, or a line's end. A line with such an end isn't drawn, and neither is one attached to an object a line can't attach to. A 3D object's parent that isn't a model or a light, or is the object itself, is skipped with a warning too. A constraint's target that its constraint doesn't take is skipped the same way. A skipped parent takes its `parent-node` and `parent-inverse` with it. The object then stands in the slide's space at its own values.

#### transition

`cross-dissolve` crossfades to the next slide. `carry-over` moves each object with the same id on both slides. `push` moves both slides along its direction, `move-in` brings the next slide in over this one, and `reveal` moves this one off the next. `scroll` makes both slides one strip the view travels across. This slide stays as it was left, and the next slide's first click plays with the move. `wipe` uncovers the next slide behind a traveling edge. `zoom` grows the next slide in from the middle. `fade-through-color` fades this slide out to the color and the next one in from it. The defaults are interpolation ease-in-out, match object, direction left, color #000000, and delay 0.

| `color` |  |  | The color of a fade through color. It is a color role or a hex color without alpha, such as "#000000". A role's color comes from the scheme of the slide the transition leaves. A role's alpha is ignored. |

**Types.** With `cross-dissolve`, the next slide fades in over this one. With `carry-over`, an object with the same id and type on both slides moves to its place on the next slide when both show it. A duplicated slide keeps its objects' ids. When `match` is `object`, a text also needs the same words as shown before `case` changes them, markup aside. A `word` or `character` match morphs a text whose words changed. A text on a path or with a 3D model on either slide isn't morphed. It travels whole. A 3D object also needs the same parent and rotation mode on both slides. Everything else cross-dissolves. With `push`, the next slide pushes this one off. With `move-in`, the next slide moves in over this one. With `reveal`, this slide moves off and shows the next one. Which way they travel is set by `direction`. With `wipe`, an edge uncovers the next slide. With `zoom`, the next slide grows from the center. With `fade-through-color`, the slides fade through `color`.

**Scroll.** A scroll moves both slides along one strip. Each slide's 3D objects stay at their place in its stacking order and are clipped at its edge. The edge doesn't cut the shadow a model or 3D text casts. A model with the same id on both slides crosses between them whole when both draw it from the same file as the scroll sets out. A 3D text with the same id on both crosses whole when both draw it from the same model file then. For a text's `extrusion`, that file is the model MarkdownPoint builds from its letters. A change to what it is built from, such as its words, its font, its `depth`, or its `bevel`, makes it another file. A floor with the same id on both slides is one floor across both while both show it. Each spot of it takes a shadow once. Its position and opacity go from this slide's to the next slide's during the scroll. A shadow catcher with the same id on both is one catcher in the same way. Its position, the way it faces, its size, and its opacity go from this slide's to the next slide's. The way it faces comes from its `rotation` and its `orientation` together. The shadow color of either changes once the strip has moved halfway.

**An Action through a scroll.** A model or 3D text that crosses whole uses the next slide's pose from the moment the scroll sets out, and nothing of the pose it leaves blends in. The next slide's [first click](#step) plays along with the scroll. To keep an Action playing without a pause, start the same Action on that click at the second where the object leaves it. Give its cue the click's start and no `blend-in`. On a click, the scroll sets out from the end of the slide's last click, and each clip that plays once stands there at the end of its `clip-trim`, or at the Action's end without one. The transition's `delay` and the [self-playing](#self-playing) rules time a scroll that starts by itself.

**When the delays start.** `click-delay` and `slide-delay` start once the transition into the slide and every step of the click before them have reached their end. They start no earlier than when each video or audio object those steps started has played one pass while shown. One hidden for the rest of that click before then doesn't hold them.

When it still shows after the last step, `slide-delay` starts no earlier than one pass of it after the transition into the slide ended. Time it spent hidden isn't added. One that a click first shows starts then and counts as that click's. A slide that played a step and leaves by a scroll doesn't add `slide-delay`. A transition that starts by itself uses its own `delay` instead. That delay starts once the transition into the slide and the last click have reached their end. It doesn't wait for video or audio.

#### slide

**Reset slide to layout.** Reset slide to layout takes away the slide's `overrides`, its `scheme`, and the inherited ids its `objects` lists. It keeps an override of an object's content, such as its `file`. The reset takes an icon's `alt` away with its `icon` because the `alt` describes the glyph. It keeps a setting with no default, such as `enter`, whose parameters the slide's initial values or steps animate. It keeps the slide's words, `background`, `transition`, and `skipped` too.

**Inherited ids.** A slide's own object can't have an id the slide inherits from its layout or master. A theme can gain such an id after the slide is written. The object is then skipped: it isn't drawn, and an `inherited-id-collision` error names it. The rest of the slide draws. Giving the object another id shows it. Write the new id wherever the files name the object, such as its words' `<!-- text: id -->` marker in the .md file. A layout's own object under a master object's id is skipped the same way.

**Copies.** An object's animation is the curves, cues, and initial values that name its id. A copy of another object has none of the other's animation until it is written under the copy's own id.

**The animated column.** `yes` means a step's keyframes move the key through the values in between. `discrete` means the key changes at once at its keyframe. The interpolation doesn't change this. A list names the parts of the key that a step animates. A group keys `scale` whole.

**Overrides.** A null that would leave a required key missing is ignored. When an override gives an inherited image or video a `file`, the object becomes an image or a video. Which one depends on the file's type. A `null` file leaves an empty image, even on a video. Inherited keys that only the old type has are dropped. An override that sets `parent`, even to the same parent or to null, sets the object's `parent-node` and `parent-inverse` too: the ones it inherits are dropped. One that names a parent without them moves the object with the whole parent and no `parent-inverse`. An override's key that the object doesn't have, such as `cone-angle` on a light that is directional on its layout, is ignored with a warning. A value that only another type can have is ignored with a warning too. A value that isn't valid with what the object inherits is ignored the same way. When an override makes a text box grow along a side, the length it inherits there is dropped. Each stays in the file and applies once the object can have it. A key or a value that no object can have, such as a misspelled key, is an error. In a 1.0 file, `type` in an override is an error too. A later minor version may let an override take them. On an object that isn't an override, a value that isn't valid is an error. In an override, `frame`, `position`, `rotation`, `scale`, `point-of-interest`, `tilt`, `size`, `anchor-point`, `tail`, and `render-effects` change only the parts given. But `rotation` changes only the parts given when both it and the inherited rotation are in degrees. Otherwise it replaces the inherited one whole. An axis that a rotation in degrees leaves out is then 0. A part that an override leaves out of `anchor-point` is that part of the anchor the object would have without it. That anchor follows the override's other keys too, such as `auto-size`. Any other record or list replaces the inherited one whole. A part of a record set to null is an error. A web video's `poster` without its `url` is ignored with a warning. A `null` for the camera or the World is ignored with a warning too. Its text can't have a 3D text `model`. It can't have `prompt`, `image-style`, `transparent-background`, `restyle`, `restyled-from`, `source`, or `built-from` either.

**Keys an object draws without.** A video without a `file` shows an empty picture, a shape without a `shape-type` is a rectangle, and an icon without an `icon` shows no glyph. Each reads with a `missing-key` warning. A table or a chart whose words the .md file doesn't hold, its marker missing or empty, has empty cells instead, counting its header row. A table has a column for each length in its `column-widths` and a row for each in its `min-row-heights`. Without lengths in `column-widths`, it has 3 columns, and without lengths in `min-row-heights`, 3 rows. Past 25,000 cells, it has only its first rows within them. A chart has 3 columns and 3 rows. It reads with a `missing-text-block` warning.

**Groups.** Groups nest at most 200 deep. The outermost group is the first level. A group's box is what its members draw at rest, in the group's rotation: each member's frame after its own rotation and scale, a line's drawn path, and every copy a repeater inside the group makes. A member whose `visible` is false counts. A group's rotation is the angle at which its box is measured. It doesn't turn the members. Their own positions and rotations don't change. To move a group, add the same offset to the frame and free ends of each object under it, however deep. When a keyframe animates the group's rotation, the members turn by the difference between the keyframe's value and the group's rotation. A group's members paint in order right after the group. Where `objects` lists a member apart from its group, it still paints right after the group, among its members in the order listed, and causes a warning. With blend-mode `normal`, they blend only with each other. A group's default is `pass-through`. With it, the members blend with what is beneath the group. In Figma and Photoshop, this is Pass Through. The members' blending stays inside the group when the group has a blur or is tilted. The group's wipe masks each member alike, and they still blend with what is beneath it. A group fades as one picture. Where a member's blend mode reaches past the group, the group's opacity fades each branch on its own. A branch is a member, or a member group that fades as one picture.

**Broken groups.** A parent that isn't a group, or is the object itself, is dropped, and the object stands at the root. A text with a `model` loses its parent the same way. A group nested more than 200 deep stands at the root with its members. The levels under it count from it again. When parents make a loop, every link in it is dropped. The order of the objects doesn't matter. What hangs off the loop keeps its parent. Each of these causes a warning.

**An image's color.** An image's `color` is drawn only on an SVG image. The whole picture is drawn in that color. Each pixel's alpha is multiplied by the color's alpha. An opaque color leaves the alpha as it is. On an image whose file isn't an SVG, the `color` isn't drawn. It stays set and causes the warning `color-needs-svg`. A Mermaid diagram is colored another way. See **A diagram in two layers**, below.

**Adjustments.** An image's adjustments are applied to its sRGB values in this order: `exposure`, `contrast`, `saturation`, `temperature`, and `grayscale`. `exposure` is CSS's `brightness()` of 2 to the power of `exposure`. `contrast` is CSS's `contrast()` of 1 + `contrast`, and `saturation` is CSS's `saturate()` of 1 + `saturation`. With `temperature`, red is multiplied by 1 + `temperature` ÷ 4 and blue by 1 − `temperature` ÷ 4. `grayscale` is CSS's `grayscale()` of `grayscale`. At 0, each leaves the image unchanged. A video has only `grayscale`.

**Masks.** A mask is a path or a shape without text whose `use-as-mask` is true. A mask isn't painted. It clips the members after it in its group to its outline. That includes the members of groups among them. A later mask in the group starts a new range. A hidden mask clips nothing, but it still ends the range before it. A path's mask uses its `fill-rule`. A mask at the slide's root isn't painted and clips nothing. Its `use-as-mask` causes a warning. A shape with text can't be a mask. It is painted, and its `use-as-mask` is ignored with a warning.

**Outlines.** A line's and a path's `stroke` is centered on their line.

**Words on a path.** A text with a `text-path` sets its words on one line: its paragraphs, headings, and list items in reading order, one space apart. A line break is a space. Code blocks, rules, and list markers aren't shown. A heading has the text's size and weight. `line-height`, `paragraph-spacing`, `list-indent`, `bullet-styles`, `vertical-align`, `padding-top`, `padding-bottom`, `column-count`, `column-gutter`, `min-height`, and `auto-size` don't apply. They stay in the file and apply again once the text has no path. A text whose `auto-size` grows a side still can't animate its size or its text's layout on a path. `left` holds the text's start at the path's start, `center` its middle at the path's middle, and `right` its end at the path's end. The alignment is the text's `align`, else its text style's. Justified text, and text with neither, are held on their start side. Only the path's first contour carries the words. Any later one is ignored. A closed contour carries them round past its start. On an open one, a letter whose middle falls past either end isn't shown at rest. Only the letters shown at rest enter and exit. In flight they run on past either end in the path's direction there.

**A table's words.** A table takes every key of its text style but `bullet-styles`, `list-indent`, `paragraph-spacing`, `padding-top`, and `padding-bottom`.

**A shape's words.** On a shape with a fill, the default `color` is `text` where `text` has a higher WCAG contrast ratio than `background` against the fill at the text's first line. Otherwise it is `background`. A fill that isn't opaque is measured over `background`. That default is used instead of the text style's color.

**Capitalize.** With `capitalize`, a word that starts with a letter starts with that letter's capital. The rest of the word stays as typed. A letter starts a word unless a letter, a decimal digit, or a connector such as `_` comes right before it, past any combining mark. A letter number such as Ⅳ counts as a letter. A character of Unicode's MidLetter, MidNumLet, or Single_Quote word-break classes joins the letters on either side into one word. Those are characters such as a period, a colon, and an apostrophe. For example, "node.js", "don't", and "3d" are each one word, and "(hello)" shows as "(Hello)". In Turkish and Azeri, the capital of i is İ. In Dutch, a word's first ij is IJ. A letter whose capital has more than one character, such as ß, stays as typed. A letter of Georgian's Mkhedruli alphabet stays as typed too.

**Upper and lower case.** With `upper` or `lower`, a letter takes the case Unicode's full case mapping gives it in the presentation's `locale`. So a Greek capital drops its accent. An ι or υ after it that the accent kept apart then takes a diaeresis: "μάιος" shows as "ΜΑΪΟΣ". The capital of ß is SS. In Turkish and Azeri, the capital of i is İ and the small letter of I is ı. In capitals, a letter of Georgian's Mkhedruli alphabet stays as it is, and a Mtavruli letter shows as its Mkhedruli letter.

**Lines.** Where a curved line has no `bend`, it is −|dx × dy| ÷ (4 × (dx² + dy²)), or 0 where its ends meet. dx and dy are how far its end is from its start. So a line whose ends are level or plumb is straight. One on a diagonal bends most: by −1/8. A line that isn't curved still has its bend. The bend shows once the line is curved. A curved line is the quadratic Bézier curve through its bent middle. An elbow line starts along the axis on which its ends are farther apart, or across when they're as far apart on both.

**Charts.** Each `delivery` names its own way of growing. A chart's `by-element` grows its elements in the table's order within the chart's own `progress`, as a text's entrance moves its pieces: each starts one interval after the one before and grows for `spread` intervals. In a line or stacked-area chart, an element is a series. In any other chart, it is a category. A text's `by-paragraph` plays each paragraph on a cue of its own instead. A click for each element is a `progress` keyframe for each. No chart draws a value axis: a value shows as a number only in its value label. A value label is spelled as its cell spells its number. A value keeps as many whole digits as its cell writes where the cell starts with a zero: `007` counts through `003`. Where the cell writes no whole digit, a value below one has none: `.312` counts through `.156`. A counter draws no legend and no value labels, and it doesn't use `delivery` or `spread`. A key that a chart's type doesn't use does nothing. A counter's figure is its value times `progress`. Unless `digits` is `roll`, it keeps the cell's spelling and its number of decimal places, rounded the way ECMAScript's `toFixed` rounds it. With `roll`, the last wheel turns with every fraction of a count. Each wheel to its left turns to its next digit while the wheels after it pass from 9 to 0. A cell that holds no number shows its words at every count. A chart's `align` sets only a counter's figure. A pie or a donut uses its `category-colors`, and any other chart but a counter its `series-colors`. Each list keeps its colors when the chart's type changes. Where an entry of the list a chart uses is `null`, or the list ends before it, the chart uses the slide's `accent` and `text` colors in turn: `accent` at the first entry, `text` at the second, `accent` again at the third, and so on. Where `text` is the same color as `accent`, and `muted` isn't, `muted` takes the place of `text`. Each round after the first is drawn at a lower opacity: half, then a third, then a quarter, and so on. Each opacity is rounded to a whole percent.

**Web videos.** A web video's `url` is the https address of a YouTube or Vimeo video. It has no user name or password, and no port other than 443. YouTube addresses are youtube.com/watch?v=id, youtube.com/embed/id, youtube.com/shorts/id, youtube.com/live/id, youtu.be/id, and youtube-nocookie.com/embed/id. The id is 11 letters, digits, underscores, or hyphens. A youtube.com address can start with www. or m., and a youtu.be or youtube-nocookie.com address with www. Vimeo addresses are vimeo.com/, www.vimeo.com/, or player.vimeo.com/video/, followed by the video's number. The number has no leading zero. An unlisted video's hash is letters and digits. It comes after the number or as h. When an address has both, they are the same. A start time is whole seconds, or hours, minutes, and seconds such as 1m2s. YouTube uses t or start. Vimeo uses t in the query or among the parameters after #. A share link's #t=1m2s&share=copy starts the video at 1m2s. When an address has two start times, they are the same. Each of v, h, t, and start appears at most once in the query, and t at most once after #. A save writes the address in one of three forms and drops every other parameter: `https://www.youtube.com/watch?v=<id>&t=<seconds>`, `https://www.youtube-nocookie.com/embed/<id>?start=<seconds>`, and `https://vimeo.com/<number>/<hash>#t=<seconds>s`. The start is left out when it is 0, and the hash when the video has none.

**The 3D layer.** A slide's models, shadow catchers, floors, and texts with a 3D `model` are drawn together as one image: the slide's 3D layer. The layer is placed where the backmost of them is in the slide's stacking order. A hidden one counts too. Lights and the camera draw nothing in it, and they can be anywhere in the order. The layer is lit in linear light, tone-mapped with Khronos PBR Neutral at an exposure of 1, and written in sRGB. sRGB is the color space of the slide's flat colors. Before tone mapping, a directional light of intensity 1 lights a white surface that faces it to white. A point, spot, or area light falls off with the square of the distance in meters. A camera's lens is measured on a 36 mm sensor across the slide's longer side. It is the same as Blender's Sensor Fit Auto. The distance at which the slide shows at full size is at least 1 canvas unit. It sets the field of view and a camera's default z. The camera sees the 3D layer from where it stands and looks. No flat object is seen through it. The 3D layer draws nothing nearer to the camera than 1 canvas unit. A World with no color lights the layer at the World's intensity with the map its `environment` names, turned by its `environment-rotation`. Each map is the file `environments/<name>.hdr`, an equirectangular Radiance HDR file. The files' SHA-256 digests are `studio` 59d7d7a74eac180055a93181ff4b3561910267ed56f6fb7941f7abf643002e0d, `photo-studio` 0a7f508eebf19166d758f9e55a4f849c967b27cfa8c24d574819dfa9c76f1859, `loft` 9a088e09eefb8f37c67673fab949f5981a69dac9ba54d9a988b1373d6063c4ad, `sky` 559faa8ad19cd4f1f464f531f727a2d3f54143f5327ee5d6ebb7381a018f87da, and `sunset` 13835c240b8aee3d903fb54920c47bd966464fbbe489914fc35dedacd6ee261c.

**Model files.** A model's file is binary glTF 2.0, or a later 2.x, that contains everything it uses. Its one buffer is its BIN chunk. Each texture's image is a PNG, a JPEG, or a WebP, in that chunk or in a data: URI. It can use EXT_texture_webp, KHR_materials_anisotropy, KHR_materials_clearcoat, KHR_materials_dispersion, KHR_materials_emissive_strength, KHR_materials_ior, KHR_materials_iridescence, KHR_materials_sheen, KHR_materials_specular, KHR_materials_transmission, KHR_materials_unlit, KHR_materials_volume, KHR_mesh_quantization, KHR_texture_transform, and KHR_xmp_json_ld. A file that requires any other extension is refused. A file that uses KHR_draco_mesh_compression, EXT_meshopt_compression, KHR_meshopt_compression, KHR_texture_basisu, or EXT_mesh_gpu_instancing is refused too. Any other extension it uses is ignored. A model's own lights are ignored too. A skinned vertex moves with at most four joints. Its joints and their weights are in its `JOINTS_0` and `WEIGHTS_0`. No other set is read. A model's node trees are at most 256 nodes deep. A mesh counts once for each node that draws it. A model then has at most 65,536 primitives, 65,536 skin joint copies, and 1,048,576 morph weights. Each target and each rest weight is a morph weight. Its buffer views together fit in its BIN chunk. Views that share bytes each count in full. Its accessors' values together fit there too. Each accessor counts once: its count times the bytes of its components. A sparse accessor's values count in full. Each primitive of the model's meshes is counted once. The morph targets then use at most 256 MiB: 16 bytes for each vertex and target, 32 with normals, and 48 with colors. An animation's keys are laid out as glTF lays them out. Their times are floats. Their values are floats, or normalized 8-bit or 16-bit integers for a rotation or morph weights. Normalized values are written in full, not as a sparse accessor. No buffer view that holds keys has a stride. Normalized keys are counted once for each channel that names them. They then use at most 256 MiB: 4 bytes for each number. Each image is counted once for each sampler. The textures then decode to at most 268,435,456 pixels.

**Materials and nodes.** A material named `color:` followed by a color role, such as `color:accent`, uses that role's color in the slide's scheme as its base color factor. The role's alpha is ignored. The material keeps its own alpha and its base color texture. If the scheme doesn't have the role, the material uses the file's color. A number Blender adds to a copied material's name, such as `.001`, is ignored. A node whose `extras.markdownpoint` has `"cast-shadow": false` casts no shadows. Nothing under it casts shadows either. An animation whose `extras.markdownpoint` has `"loop": "repeat"` is an Action made to repeat. A clip of it repeats by its own `loop` or `stride`, never by the Action's. Every node of the file has a name, a skin's joints included. A name follows the rule the cue record gives for a clip's Action. An unnamed node is named Node and its number in the file, as in `Node 1` for the first. A key that names a node, such as `parent-node`, finds it only in the scene MarkdownPoint draws. That is the file's default scene, or its first scene when it names none. A `parent-node`, a `target-node`, or an Aim's `node` that names no node there causes a warning. An object whose `parent-node` names none moves with the whole model. A camera whose `target-node` names none follows the target's origin. An Aim whose `node` names none turns nothing.

**Meshy's tasks.** A model made with Meshy names the tasks that made it in `asset.extras.markdownpoint.meshy` beside its glTF `version`. `model` is the id of the task that made the model. `model-expires` is when Meshy deletes that task. `rig` is the id of the task that rigged the model. `rig-expires` is when Meshy deletes that one. Each id is Meshy's own string. Each time is a UTC timestamp to the millisecond, such as 2026-10-16T09:30:00.000Z. Any of the four can be left out. While its `model` task lasts, a model is rigged from that task and its file isn't sent. While its `rig` task lasts, a rigged model takes more Actions from it.

**Path data.** The path data of a path, a text path, a mask, or a motion path has at most 2,097,152 characters and 8,192 points. A point is where a contour starts or a segment ends. Each line and curve has one. A move has one too. A move has none when another move follows it at once, or when it ends a path that has other points. An arc has one for each of the fewest pieces of at most a quarter turn that it divides into. An arc that ends where it starts has none. An arc is read as one cubic Bézier curve for each of those pieces, and the pieces turn equally. On a circle, a piece that turns θ has handles 4 ÷ 3 × tan(θ ÷ 4) of the radius long. An ellipse's pieces are a unit circle's, scaled by its two radii and turned by its rotation. Once the path data is made absolute, each point and handle has finite coordinates. When a contour of more than two points closes, the points at its end that lie on its start aren't counted. A point a closing curve leaves from is counted, and two points always stay. The close draws that segment.

#### frame

It is in canvas units. Its x and y are from the top left of its slide. A table's and an audio object's frame has only x and y: their contents or an icon give them their size. **A growing text box.** When a text box's width grows with `auto-size`, its frame has no width. A text that follows a path or has more than one column still has one. When its height grows with `auto-size`, its frame has no height. A text that follows a path still has one. A box set to grow can't animate its size or its text's layout, even with a path or more than one column. The center of its frame is the point the text grows from. Without an `anchor-point`, the box turns and scales about that point. With one, the box grows from that point. Then it turns and scales about its anchor. When the width grows, the box's own `align` places it: a box set left is drawn to the right of the point, a centered box around it, and a box set right to its left. Justified text, and text with no `align` of its own, is drawn as if it were set on its start side. A text style's `align` aligns the lines inside the box and doesn't move it. When the height grows, the box is drawn down from the point. Where the box is drawn around that point depends on `auto-size`, `align`, `text-direction`, `column-count`, `text-path`, `rotation`, `scale`, and `anchor-point`. When an override changes `auto-size`, `align`, `text-direction`, `column-count`, or `text-path`, an x or y it leaves out is the one that puts its box where the inherited box is drawn. To find that x or y, the inherited box is drawn at its own `rotation` and `scale`. Along each side where the inherited box grows, it has the length of the override's box, or no length where the override's box grows too. The override's box is placed so that it is drawn in the same place at that `rotation` and `scale`. Its x and y are read with the override's keys. Then the override's box is turned and scaled by its own `rotation` and `scale` about the point it grows from, or about its `anchor-point` where it has one. So where both boxes grow along a side, the override's box grows from the point the inherited box grows from. An override that changes only `rotation`, `scale`, or `anchor-point` has the inherited x and y. An x or y the override gives is its own.

**Flip, scale, and rotation.** A flat object is drawn in its frame and mirrored inside it by `flip`. A picture is mirrored after its file's orientation and its `crop`. Then it is scaled along its own axes and turned by its `rotation`. It scales and turns about its anchor point.

Words are split at the word boundaries of ICU 78.2 for the presentation's `locale`: Unicode 17.0.0's rules, CLDR 48.0's tailorings for the locale, and ICU's dictionaries for scripts written without spaces. A word includes anything that touches it and isn't part of a word, such as punctuation or a symbol. What touches two words goes with the earlier word. A run of punctuation or symbols that touches no word is a piece of its own. So “Hello, world! (yes) e-mail” is five pieces. A character is one grapheme cluster. Characters are counted as shown, before `case` changes them. A field counts as its words. A mark or link inside a word doesn't split it. A space counts as a piece only with `character-and-space`, and a line break never does. Outside a piece, a quote's rule, a code block, a rule, and a block of kept Markdown are shown from the start. By word or by character, a list's markers are shown from the start too. Kept Markdown inside a paragraph is part of its words. An empty list item is a paragraph. With delivery `by-paragraph`, a paragraph that no cue shows is shown from the start. A text with a `text-path` shows all its paragraphs together on one line: its paragraph cues show nothing more, and with delivery `by-paragraph` it enters all at once. In a 1.0 file, a `delivery` beside another `based-on` is an error. A later minor version may add the pair. In a file of that version, MarkdownPoint passes over the whole `enter` and keeps it as written.

**Looks.** An entrance's or exit's look moves and blurs each piece in ems of its own font size. A piece whose letters are all one size uses that size. That size can be a heading's, code's, or code's in a heading. Any other piece uses the size of its paragraph, heading, or list item. A list item's size is the text's. On a path, the look's x is along the path in its direction and its y is across it, toward the letters' feet.

**Turns.** Pieces start one interval apart in their order. Each piece moves for `spread` intervals. With interpolation hold, a piece takes no time: it arrives or leaves as it starts. At `progress` 0, none has. By word or by character, each paragraph and heading that has a piece gets a turn. The turns go in reading order, or in reverse with `backward`. Each turn plays the order on its own: from its own middle or with its own shuffle. With no pause, a turn starts one interval after the last piece of the turn before it starts. By paragraph, the order runs over the paragraphs, and paragraphs that start together share one turn. `pause` applies only between turns. For N pieces, `progress` runs evenly over N − 1 + `spread` intervals. With a `pause` above 0, it runs over `pause` + `spread` − 1 more intervals before each turn except the first. With `center-to-ends` or `ends-to-center`, two pieces that are equally far from the middle start together. When the order runs over n pieces, their starts are spread evenly over n − 1 intervals. With only two pieces, `center-to-ends` starts the first and `ends-to-center` the second. The other starts one interval later.

**Pictures made from code.** An image with `source` shows a picture made from its code. A `source` holds code and what reads it, never a path. The picture it makes is the image's `file`. A program makes the picture only when an author asks it to. Reading, showing, or exporting a presentation never does. The image shows its `file`, whatever its code says. Its `built-from` says the `file` was made from that code. An image whose code has no `file`, or whose `built-from` isn't that code's, causes the warning `picture-out-of-date`. A reader warns the same way for a `built-from` whose rule it doesn't know. An earlier MarkdownPoint passes over a `source` whose `type` a later minor version added. It passes over the image's `built-from`, `prompt`, `image-style`, `transparent-background`, `restyle`, and `restyled-from` with it. The image shows its `file`, and no warning names the image.

**An image's `built-from`.** It is `markdownpoint/`, its `source`'s `type`, `/`, its rule's number, `:sha256:`, and 64 lowercase hex digits. Each type numbers its own rules. By rule 1 for `latex`, it is `markdownpoint/latex/1:sha256:` followed by the SHA-256 of a record that holds the `type` and `code` of the image's `source`. Each is as the file has it. The record is written in UTF-8 according to RFC 8785's JSON Canonicalization Scheme. Its keys are sorted, and it has no white space outside its strings, whose characters are the code's own. For example, the code `A = \pi r^2` has the record `{"code":"A = \\pi r^2","type":"latex"}` and the built-from `markdownpoint/latex/1:sha256:14682bdb4dd43a7047614d3ef7304735f7dd02b3ed9625b7302ee8b1ebfbc8ff`.

Changing the master's body font makes a diagram out of date because its labels are drawn in that font. For a diagram, the record has three keys: `type`, `code`, and `font`. `font` is the name of the master's body font. The `font` key is never written in the file. The name is spelled as the master's `fonts` spells it. When MarkdownPoint ships the font and the theme has no faces of its own for it, the name is spelled as MarkdownPoint spells it. For example, INTER becomes Inter. A diagram with labels in Inter has the record `{"code":"flowchart LR\n  A --> B","font":"Inter","type":"mermaid"}` and the built-from `markdownpoint/mermaid/1:sha256:a0858e5a8ca882e679d4eeedd89d13fb3764e3d12c272f75f7423d32686ff1f1`.

**A diagram in two layers.** When MarkdownPoint makes a `mermaid` image's picture, it writes one SVG file with two layers. Each layer is a group. One has the `id` `themed`, and the other has the `id` `author`. The file has a `style` element that contains `svg:has(#themed:target) #author{display:none} svg:has(#author:target) #themed{display:none}`. When the file's address ends in `#themed` or `#author`, that style hides the other layer. A reader that can't show one layer alone shows both.

The `themed` layer uses four colors. #000000 is drawn in the scheme's `text` color, #FF0000 in its `accent` color, and #FFFFFF in its `background` color. When the `accent` color is the same as the `text` color and the `muted` color isn't, #FF0000 is drawn in the `muted` color. For #0000FF, MarkdownPoint lays the `text` color at half opacity over the `background` color. It draws #0000FF in whichever of the `text` and `background` colors has more contrast with that mix. Every other color is a mix of these four and is drawn as the same mix of the scheme's colors. The alpha of each color stays the same. The `author` layer is drawn under the `themed` layer. It has the colors the Mermaid code sets. Words on them are black or white.

A diagram's `color` changes only the colors of its `themed` layer. #000000 and #FF0000 are drawn in that color. #FFFFFF is still drawn in the `background` color. For #0000FF, MarkdownPoint lays the `color` at half opacity over the `background` color. It draws #0000FF in whichever of the `color` and the `background` color has more contrast with that mix. A `color` with an alpha below 1 fades the whole picture. Both layers are drawn first and then faded together.

A `built-from` and a `restyled-from` say what the `file` beside them was made from. In an override, each counts only beside a `file` that override gives. An override that gives a `file` drops the ones the object inherits. One that gives either without a `file` is ignored with the warning `ignored-override-value`. A `null` still takes away the one the object inherits.

### <a id="3d"></a>3D

#### space-position

A point in the 3D space is in canvas units. The x axis runs right from the slide's left edge, the y axis runs up from its bottom edge, and the z axis runs toward the viewer. The slide is at z 0. The axes are right-handed. glTF and three.js use the same axes. After Effects' y and z axes run the other way. A parented object's position is in its parent's space.

Where: `objects[].position` of a model, a light, the camera, or a shadow catcher, `objects[].point-of-interest`

| key | required | values | description |
| --- | --- | --- | --- |
| `x` | except the camera's position | −1 × 10¹⁸ to 1 × 10¹⁸ canvas units | How far across. |
| `y` | except the camera's position | −1 × 10¹⁸ to 1 × 10¹⁸ canvas units | How far up. |
| `z` | except the camera's position | −1 × 10¹⁸ to 1 × 10¹⁸ canvas units | How far toward the viewer. |

**Parented objects.** A parented model, light, shadow catcher, or camera has its position, rotation, scale, and point of interest in its parent's space, through its `parent-inverse` if it has one. A parented shadow catcher's width and height are in its parent's space too. A parent's `visible` and `opacity` don't reach what it carries. The object's world matrix is its parent's world matrix, times its parent-inverse, times its own position, rotation, and scale. When `parent-node` names a node of the parent, that node's world matrix is used in place of the parent's. A node's space is in canvas units, the same as its model's. It has the node's origin, axes, and scale. The node's distance from its model counts in canvas units. The `parent-inverse` is the inverse of the parent's world transform, or its parent node's in canvas units, times the object's earlier space's transform. Each matrix acts on a column of x, y, z, and 1 to its right: `world = parent × parent-inverse × local`. Blender composes a Parent Inverse the same way. The object's own constraints apply after that. A loop made of parents alone drops every link in it, and each object in it stands on its own. Then an Aim whose target waits on the model it turns closes a loop. That Aim turns nothing, and the parents in that loop stay. Both cause a warning. A parented camera's position comes from that world matrix and so moves with its parent's scale. Its view turns with the matrix but is never scaled or sheared. A camera with a point of interest also banks with its parent.

**The camera.** The camera's position can leave out any part. A part left out takes its default: x half the slide's width, y half its height minus the camera's `lens-shift`, and z where the slide shows at full size. That z follows the focal length as it plays. A step that animates only the focal length keeps z 0 at full size. A parented camera's defaults are in its parent's space.

#### space-rotation

A 3D object turns about its origin in its space's axes. They are its parent's for a parented object, and otherwise x right, y up, and z toward the viewer. Its rotation is in degrees, or a quaternion in quaternion mode. An object's own rotation in degrees needs x, y, and z. In degrees, it turns in Cinema 4D's HPB order: by the heading about y, then by the pitch about its own x, then by the bank about its own z. In three.js, this is Euler order YXZ. A positive z turns it counterclockwise on the slide, a positive x tilts its top toward the viewer, and a positive y brings its left side forward. A quaternion is glTF's with w first. A Blender quaternion (w, x, y, z) exported to glTF with +Y up is (w, x, z, −y) here. A quaternion's parts are read to six decimal places, and its length doesn't change the rotation. Between two quaternion keyframes, the object turns the shorter way round.

| key | required | values | description |
| --- | --- | --- | --- |
| `x` | yes | −8589934592 to 8589934592 | The turn about x in degrees, or a quaternion's x. |
| `y` | yes | −8589934592 to 8589934592 | The turn about y in degrees, or a quaternion's y. |
| `z` | yes | −8589934592 to 8589934592 | The turn about z in degrees, or a quaternion's z. |
| `w` | with rotation-mode quaternion | −8589934592 to 8589934592 | A quaternion's w. It is used in quaternion mode only. |

**Degrees.** Each rotation turns counterclockwise as seen along its axis toward the origin. A flat object's `rotation` and a group's `tilt.x` turn the other way. The slide's y axis runs down. A step animates each axis's rotation on its own as `rotation.x`, `rotation.y`, or `rotation.z`. One keyframe can spin the object more than once. In its glTF file, a model faces +z. At zero rotation, it faces the viewer. At zero rotation, a light shines into the slide along its own −z, and the camera looks along its own −z. Both have their own y up.

**Quaternions.** A quaternion whose parts all read as 0 is refused. In quaternion mode, each keyframe of `<object>.rotation` is a whole quaternion. Between two keyframes, the object turns at the pace of the keyframe's interpolation. At exactly a half turn, it turns toward the keyframe's quaternion as written.

| `samples` |  | whole numbers, 1 to 256 | How many moments the 3D layer is drawn at while the shutter is open. The drawings are then averaged. Cinema 4D's Sub-Frame Motion Blur Samples work the same way. The default is 32. |
| `shutter` |  | 0 to 4294967296 frames | How long the shutter stays open in frames. At 0, there is no blur. The default is 0.5. It can be animated. |
| `shutter-position` |  | start, center, end | Where the frame's moment falls in the shutter's opening. The default is center. |

#### render-effects

The slide's two render effects. One is a fast estimate of the light that bounces between surfaces. The other is a fast estimate of the World's light that is blocked where surfaces meet. Both are set on the slide's camera. Motion blur is set there too. In Cinema 4D's Render Settings, the two effects are Global Illumination and Ambient Occlusion. The effects show wherever the 3D layer shows. Only surfaces in view bounce light. A shadow catcher or a floor bounces none. An override changes only the settings it gives. A setting it leaves out uses the inherited camera's value. To turn an effect off, an override gives it `false`.

Where: `objects[].render-effects`

| key | required | values | description |
| --- | --- | --- | --- |
| `ambient-occlusion` |  |  | Whether the World's light darkens where surfaces close in on each other. A shadow catcher or a floor then also darkens where an object rests on it. The default is false. |
| `distance` |  | more than 0 and at most 1 × 10¹⁸ canvas units | How far bounced light and shading reach from a surface in canvas units. The default is 400 times the master's `default-scale`. |
| `global-illumination` |  |  | Whether lit surfaces bounce their light onto what is near them. The default is false. |

#### text-model

With `extrusion`, MarkdownPoint builds the words' letters into a model. A text on a path can't have an extrusion. Its extrusion is left out as the file is read, and the warning `extrusion-with-text-path` says so. Its words draw flat. Each length is in ems of the text's size. The default depth is 0.2, and the default bevel is 0.02. With `file`, the model is a GLB that a program built, and `built-from` is the fingerprint of what it was built from: the words, the values of the fields they show, the presentation's `locale`, and the text's style and layout. A file is drawn only while its `built-from` matches what it would be built from now. A file that doesn't match draws its words flat until the model is built again. One unit of the model is one em of the text's size. Its origin is on the first line's baseline at the left of the text's column. For words on a path, its origin is the frame's top left. That is the path's 0 0, and the model's y points up from it. The model moves, turns, and scales with the text's frame. Its `z` sets how far it is in front of the slide. A text with a model can't be in a group. Its depth scales by the square root of the text's x scale times its y scale. A step's clips play the Actions of a GLB `file` the same way they play a model's. An extrusion has no Actions. Its letters are matte and lit only by the slide's lights and its World. With no light and the World's intensity at 0, its default, they draw black.

Where: `objects[].model` of a text

| key | required | values | description |
| --- | --- | --- | --- |
| `type` | yes | extrusion, file | Which kind of model it is. With `extrusion`, MarkdownPoint builds the words' letters into a model. With `file`, the model is a GLB that a program built. |
| `bevel` |  | 0 to 58321570 ems | How far the letters' edges are rounded in ems. At 0, they are sharp. |
| `built-from` | with type file |  | The fingerprint of what the GLB was built from. It is written as `markdownpoint/text-model/<rule>:sha256:<hex>`. Its rule is under **`built-from`** in the `text-model` record. A reader that doesn't know the rule treats the model as out of sync. |
| `depth` |  | 0 to 58321570 ems | How far the letters are extruded in ems. The bevels on the front and the back add `bevel` each. The letters' fronts are then `depth` + 2 × `bevel` from the slide. |
| `file` | with type file |  | The path to the model a program built from the words. It is a GLB's path relative to the presentation's folder. |

**Flat effects.** While a text's model draws, its `drop-shadow`, `text-stroke`, `text-stroke-weight`, and `blend-mode` don't apply. They stay in the file and apply again when the text draws flat.

**The model's letters.** A text's model has its letters under one node. That node is its scene's only root, and it draws no mesh of its own. Each child of that node is a letter. The child draws the letter itself or through the nodes under it. A letter's `extras.markdownpoint.characters` lists the characters it draws. Each is `[block, start, end]`. `block` is the block's index in reading order. The first block's index is 0. The blocks are the text's paragraphs and headings, its code blocks, and its kept Markdown. An empty paragraph or heading counts too. A paragraph in a list item or a quote is a block of its own. `start` and `end` are UTF-16 offsets in that block's text, and the letter draws the characters from `start` up to but not including `end`. That text is the block's words as shown, before `case` changes them. In it, the fields are filled in, and each hard break is one character. A letter's `extras.markdownpoint.box` is the box the letter is laid out in on the slide. It is `[left, bottom, right, top]` in the model's units. Y is up. The node with the letters lists the text's paragraphs in its `extras.markdownpoint.paragraphs`. Each is `[paragraph, left, bottom, right, top]`. `paragraph` is the paragraph's number in reading order among the text's paragraphs, headings, and list items. A nested list item has a number of its own. A list item's paragraphs count as one. An empty paragraph or heading has no number, and an empty list item has one. The first paragraph's number is 0. The four numbers after it are the box the paragraph is laid out in. A list item's box includes its nested list. A letter enters and exits with the pieces its first character is in. A letter with no `characters` stays where it is. A model laid out any other way enters and exits as one piece, about the center of its text's frame. In a model of the word Hi, the JSON has this, besides its meshes and the rest glTF needs:

```json
{
  "scene": 0,
  "scenes": [{"nodes":[0]}],
  "nodes": [
    {"children":[1,2],"extras":{"markdownpoint":{"paragraphs":[[0,0,-0.21,0.97,0.88]]}}},
    {"mesh":0,"extras":{"markdownpoint":{"characters":[[0,0,1]],"box":[0,-0.21,0.73,0.88]}}},
    {"mesh":1,"extras":{"markdownpoint":{"characters":[[0,1,2]],"box":[0.73,-0.21,0.97,0.88]}}}
  ]
}
```

**`built-from`.** A text model's `built-from` is `markdownpoint/text-model/`, its rule's number, `:sha256:`, and 64 lowercase hex digits. By rule 22, it is `markdownpoint/text-model/22:sha256:` followed by the SHA-256 of its text's record. The record is a JSON object written in UTF-8 according to RFC 8785's JSON Canonicalization Scheme. Its keys are sorted by their UTF-16 code units, and it has no spaces. Each number and string in it is written the way ECMAScript writes it. A negative zero is written 0. The record has only what the presentation's folder states. Each key and value except `content` and a font's family is spelled as a save writes it: a hex color as #RRGGBB in uppercase, or #RRGGBBAA where it isn't opaque; path data in absolute M, L, C, and Z commands; and the locale in its canonical form. A key with nothing in it is left out. An em is the text's size. Each length in ems is worked out in IEEE 754 double precision. ECMAScript's numbers are doubles too. A length in canvas units is first divided by the text's size. The length in ems is then multiplied by 1000, rounded to a whole number as ECMAScript's `Math.round` rounds it, and divided by 1000. `Math.round` rounds a half toward positive infinity.

- `content`: the text's words as the slide draws them. They're written in MarkdownPoint's standard spelling of Markdown. `mdpoint format` writes words this way too. A field stays as `{{name}}`. Each paragraph id is left out. A comment outside a block of HTML is left out too. Spaces beside a comment in a line stay. Markdown the slide shows as plain text, such as an image or an HTML tag in a line, is written as words of that text. A block of HTML stays as written. So a respelling of the words, a paragraph's new id, or a note on a line of its own leaves `content` as it was.
- `fields`: each field the words show that has a value. The key is the field's name, and the value is what MarkdownPoint fills in.
- `locale`: the presentation's `locale`, or en-US if the presentation has none.
- `style`: the text's `font-family`, `font-style`, `font-weight`, `color`, `align`, `text-direction`, `line-height`, `tracking`, `case`, `bullet-styles`, `paragraph-spacing`, `list-indent`, `column-count`, `column-gutter`, `number-spacing`, and `kerning`. They come from the text, its text style, and their defaults. `tracking`, `paragraph-spacing`, `list-indent`, and `column-gutter` are in ems. Here and in `marks`, a color role the scheme lacks is written as `text`. A text whose `column-count` is 1 has no `column-gutter`. A text whose color is a gradient has that gradient as its `color`, since its letters are painted with it. It is spelled as a save writes a gradient but for its stops. Each stop's `color` is the hex the slide paints it in: a role as the scheme's color for it, or as its `text` color where the scheme lacks it. Each stop has its `position`. A stop without one is placed as **Stops without a position** says. The nearest stops before and after it stand at positions a and b. The kth of n equal steps between them is at a + (b − a) × k ÷ n. That is worked out in double precision, multiplying before dividing. Such a text's style also has its `vertical-align`, and its `padding-top` and `padding-bottom` in ems, since the gradient spans the text box.
- `marks`: each key the text style's `marks` sets, under its mark. Where the text's `font-weight` is heavier than bold's or a highlight's weight, that mark has the text's `font-weight` here, whether the style sets the mark or not.
- `width`: the frame's width in ems, unless the frame has no width.
- `inset`: the text's `inset` in ems, when it's above 0 and the words aren't along a path.
- `text-path`, `path-offset`, and `height`: for words along a path, the path, its offset, and the frame's height in ems.
- `height`: for a text whose color is a gradient, the frame's height in ems. When the text's height grows to its words, its `min-height` stands for the frame's height, and the key is left out when it has none.
- `column-height`: where `column-count` is above 1, the frame's height less the text's `padding-top`, its `padding-bottom`, and twice its `inset`. When the text's height grows to its words, its `min-height` stands for the frame's height, and 0 when it has none. The key is left out unless the result is above 0. It is in ems.
- `ligatures`: false where the text's characters travel apart. Each is then shaped on its own. They travel apart when the text's entrance or exit is by `character` or `character-and-space`. A `carry-over` doesn't set them apart. It doesn't morph a text with a 3D model.
- `font-size`: the text's size in canvas units divided by its master's `default-scale`, when its words include a quote or a horizontal rule. A quote's inset and a rule's line are built-in lengths at that scale. The text's size doesn't change them.
- `fonts`: each font role the words use by its name. That includes code's role. Each has the `family` the theme names for it. A family MarkdownPoint ships, when the theme brings no faces of its own for it, is spelled as MarkdownPoint spells it: INTER is Inter. Any other family is spelled as the theme's `fonts` spells it, even where its `font-files` key spells it otherwise. Where the theme has its own faces for the family, it also has the SHA-256 of each of its `files` in lowercase hex. They are in the order `font-files` lists them. A file that isn't drawn, such as a missing or refused one, has an empty string.
- `optical-sizes`: each such role whose family has an optical-size axis by its name. It has one list for each of the family's axes. The axes are ordered by their least size, then by their greatest, and each is listed once. A list has each size the role's words are set at, once, from the smallest: the text's size, a heading's size, and code's size. Each size is worked out in double precision and limited to the axis's range. Then it is rounded to six decimal places the way ECMAScript's `Number(x.toFixed(6))` rounds it. So two sizes past the axis's end are both at that end. An embedded face's axis is its file's `opsz`. A family whose faces have several axes has a list for each. The bundled families' axes are Inter 14 to 32, Source Serif 4 8 to 60, and Fraunces 9 to 144.

For example, take the words "Ship **it**." at 72 canvas units and weight 700 in a frame 900 wide. The theme's display role is Inter. Their record is `{"content":"Ship **it**.","fonts":{"display":{"family":"Inter"}},"locale":"en-US","marks":{"highlight":{"font-weight":700}},"optical-sizes":{"display":[[32]]},"style":{"align":"left","bullet-styles":["disc","circle","square"],"case":"none","color":"text","column-count":1,"font-family":"display","font-style":"normal","font-weight":700,"kerning":"metrics","line-height":1.05,"list-indent":1.25,"number-spacing":"default","paragraph-spacing":0.5,"text-direction":"ltr","tracking":0},"width":12.5}`. Their built-from is `markdownpoint/text-model/22:sha256:10b8107c5d71d3dc8dbeb14647d4b8dcb2e4ad5497366b047d8a267dcd8a9695`.

Rounded this way, a `tracking` of −0.0625 is −0.062 in the record. With a text size of 72 canvas units, a frame 72.036 wide is 1.001 ems wide. A frame 900.036 wide is 12.5 ems wide. In double precision, 900.036 ÷ 72 is just under 12.5005. It rounds down.

### <a id="steps"></a>Steps and keyframes

#### step

One step: the keyframes and cues that a click or the previous step sets off. Its times and the times of its keyframes and cues are in seconds. They are rounded to six decimal places. Its `with-previous` and `after-previous` start work as PowerPoint's With Previous and After Previous. On the first step, either starts it as the slide's transition ends. A Scroll into the slide plays its first click with the move, whatever its start. A cue that starts a sound, a video, or a clip counts at its own time alone. The step doesn't wait for what it starts to play through.

Where: `slides.<id>.steps[]`

| key | required | values | description |
| --- | --- | --- | --- |
| `id` | yes |  | The step's id, unique on its slide. |
| `cues` |  |  | Events at set times in the step by id. They are ordered by their time, then by their id. Each shows a paragraph, starts an audio object, a video, or a web video, or plays a clip. |
| `curves` |  |  | The step's animation. Each curve is under an "object.parameter" key such as card.opacity. |
| `effects` |  |  | The step's effects by object id. Each id has one effect. An effect is an entrance, an exit, or an emphasis by name. An object's effect and its own keyframes don't go together in one step. The effect plays, and the keyframes cause a `clashing-curves` warning and don't play. |
| `loop` | with loop-start | repeat | With `repeat`, the step loops from `loop-start` to its end while it waits for a click. Without it, the step itself doesn't loop. |
| `loop-start` |  | 0 to 4294967296 seconds | The seconds into the step where `loop` starts. Without it, the loop starts at 0. At or past the step's end, it causes a warning and doesn't loop. |
| `min-duration` |  | 0 to 4294967296 seconds | The least time the step lasts in seconds. A later keyframe, cue, effect, entering paragraph, or repeated copy makes it longer. Without it, or at 0, the step lasts as long as what is in it. |
| `name` |  |  | The step's name. It is one line that isn't blank and has no control characters or line breaks. |
| `repeat-count` |  | whole numbers, 2 to 9.007199254740991 × 10¹⁵ | How many times the step plays before it completes. Without it, the step plays once. The step plays only as many times as fit in 4,294,967,296 seconds. A larger count causes a warning. |
| `start` |  | on-click, with-previous, after-previous | When the step starts. `on-click` starts it on a click of its own and is the default. `with-previous` starts it with the previous step. `after-previous` starts it after that step ends. A step that takes an object out of view can't start `with-previous` with that object's entrance. The editor offers `on-click` or `after-previous` there, and starts such an exit `after-previous` when a delete, a reorder, or an insertion would bring it there. The reader warns about a file that has one. |

**Clicks.** A step has no delay of its own. A keyframe's move begins at its `begin`. When two steps of one click animate one parameter, the earlier step's motion shows until the later step's first move begins. That move starts from where the earlier motion is then. A first keyframe at the value the parameter has as its step starts doesn't move until its time, and neither does one whose move heads for `null`. The move of one with `interrupted` or a `motion-path` begins as its step starts. A move that ends where it starts has no motion path. The object stays where it is. A `begin` at or before the previous keyframe, or on a key or keyframe that doesn't move, is [ignored](#keyframe). A first step that starts by itself plays after the slide's transition. With a scroll, the next slide's first click plays along with it. Its first step's `start` doesn't change that. A click plays when any of its steps plays. A step that has keyframes or cues has no click of its own when each of them is ignored with a warning, is on a hidden object, or is a cue for a video, web video, or audio whose `start-on` is `slide`. A step with no click of its own stays in the file. In a click that plays, it counts as one of the click's steps. There its keyframes and cues on hidden objects keep their time, and so do its cues for media that starts with the slide. An object is hidden when its own `visible` key, or that of a group above it, is false. An `initial` value doesn't count. Keyframes and cues on a hidden object play nothing. No step can show it. A step with no keyframes and no cues has its own click. A step with a `repeat-count` plays alone on its click. A file that breaks this is read with a warning, and the step doesn't repeat.

**A click's timing.** A step with `start: with-previous` starts when the step before it starts. One with `start: after-previous` starts when the step before it ends. When the step before it loops while it waits, an `after-previous` step starts when the loop's first pass ends. The loop plays on under it. A click ends when the last of its steps to end has ended. That isn't always the last step listed. A step with `repeat-count` plays its pass that many times. The instant one pass ends shows the next pass's start. The last pass's end shows the step's end state. A step's cues play on each pass. They don't play again while the step loops waiting for a click. The next click starts from each earlier step's end state. That is where each of its curves stands as the step ends. A curve's `loop` counts too. It isn't where the step's own `loop` is while it waits.

#### curve

One parameter's animation in a step: its keyframes and what happens after the last one. A position can also be keyed as one point. `frame.position` and `translation` have {x, y}, and `position` has {x, y, z}. Each of their keyframes has every part. A step keys a position either as a point or by its parts, not both. A step that keys both is read with a warning, and the point plays. An initial value sets each part on its own.

Where: `steps[].curves["<object>.<parameter>"]`

| key | required | values | description |
| --- | --- | --- | --- |
| `keyframes` | yes |  | The keyframes by id, one or more. They are ordered by their time, then by their id. |
| `loop` | with loop-keyframe | repeat, ping-pong | How it loops after its last keyframe until the step ends. With `repeat`, it replays from `loop-keyframe` to the last. With `ping-pong`, it plays that back and forth. Without a loop, it plays once. |
| `loop-keyframe` | with loop |  | The id of the keyframe the loop starts at. If the keyframe has a `begin`, the loop begins with its move. If it names no keyframe of the curve, the first is used. |

**Loops.** A curve that repeats is at its last keyframe at the moment it starts over. A loop from the last keyframe without a `begin` has nothing to replay. The curve then plays as if it had no loop.

**Initial values.** An initial value belongs to the steps that animate its parameter. Without them, it holds the parameter for the whole slide. An object it hides shows only where a step shows it again.

#### keyframe

One keyframe: a value a parameter reaches at a time. Its id is unique in its step among its keyframes and cues. Two keyframes of one parameter at one time are read with a warning, and the one with the later id plays. A `begin` at or before the previous keyframe is ignored. On the first keyframe, a `begin` of 0 is ignored. A `discrete` key and interpolation `hold` have no move. A `begin` on either is ignored. An ignored `begin` still must come before `time`. A keyframe whose value is `null` clears the whole parameter at its time. The parameter's text style or default then shows. It can't clear a part of a key, a point, `visible`, `rotation`, `scale`, a constraint's strength, `shape-type`, `icon`, or `geometry`. A `null` on a key its object can't be read without, such as a shadow catcher's `width` or a point light's `intensity`, causes an `ignored-animation-value` warning and is ignored. A slide's `initial` takes `null` by the same rules. A move toward `null` holds the value it starts from. An `exponential-scale` move works as After Effects' Exponential Scale.

Where: `steps[].curves["<object>.<parameter>"].keyframes.<keyframe id>`

| key | required | values | description |
| --- | --- | --- | --- |
| `time` | yes | 0 to 4294967296 seconds | When the parameter reaches the value. It is in seconds into the step. |
| `value` | yes |  | The value. It is written as the parameter is. It can be `null` to clear the whole parameter. It is the parameter's own value, not a change from the object's rest. |
| `begin` |  | 0 to 4294967296 seconds | When the keyframe's move begins. It is in seconds into the step. It must come before `time`. Without it, the move begins at the previous keyframe, or at 0 for the first keyframe. |
| `exponential-scale` |  |  | Whether a scale move changes by a steady ratio. A zoom then looks even. Its pace is even from or to 0, or across it. It applies only to `scale`, `scale.x`, `scale.y`, `scale.z`, and `crop.scale`. |
| `interpolation` |  | linear, ease-in, ease-out, ease-in-out, smooth, hold, anticipate, overshoot, anticipate-overshoot, bounce, elastic, or a record | How the value reaches the keyframe. It is a named curve, a named curve with its settings, a cubic Bézier, or a spring. With `hold`, the value jumps at the keyframe's time. The default is linear. |
| `interrupted` |  |  | The longer move this keyframe interrupts. |
| `motion-path` |  |  | A curved motion path for the keyframe's move. Only a point keyframe can have it. |

**How a value moves.** A color moves in sRGB with premultiplied alpha. So a color that fades out to a transparent one keeps its own color as it fades. A color role moves as the slide's scheme colors it. A gradient moves into a gradient of its own type with as many stops. A radial gradient also needs the same `shape`. A linear gradient with a `line` needs another with a `line`. Each stop moves into the stop at its place, and the angle, line, or center moves into the other gradient's. A table's `min-row-heights` moves row by row into a list as long. A move that starts from the table itself starts from one height for each of its rows: the row's minimum, or the height it stands at where it has none. Between lists of different lengths, the first shows until the keyframe. Between any other two paints, such as a color and a gradient, the first paint shows until the keyframe. Between an image's own colors or the World's environment map and a color, the first also shows until the keyframe. Each point of the path data in a `geometry`, `mask`, or `text-path` moves to the point at its place when the two paths' contours have as many points and are closed alike. The contours are paired in order. A curve's handles move to the handles at their place. A straight segment moves as a curve whose handles sit on its points. Any other two paths still morph, but the format doesn't set the shapes between them. The morph still starts exactly at one keyframe's path and ends exactly at the next one's. To set the shapes between two paths, give each pair of contours as many points, closed alike.

**Paste Animation.** Paste Animation restates each value for its target: a position moves by the offset between the two objects' rests, a turn by the difference between their turns, and a scale by the ratio of their scales.

#### keyframe-interrupted

The interrupted move goes from `begin` toward `interrupted.value`. Without the cut, it would arrive at `interrupted.time`. The keyframe's `interpolation`, `motion-path`, and `exponential-scale` shape it. An elastic's period and a spring's settling are measured over that move. At the keyframe's `time` the move is cut, and the parameter has the keyframe's own `value`.

Where: a keyframe's `interrupted`

| key | required | values | description |
| --- | --- | --- | --- |
| `value` | yes |  | Where the move was going. |
| `time` | yes | 0 to 4294967296 seconds | When the move would have reached `value`. It is in seconds into the step and at or after the keyframe's time. It doesn't make the step longer. |

#### keyframe-motion-path

The path is in the move's own coordinates. 0 0 is where the move starts, and 1 0 is where it ends. Seen on the slide, its y points 90 degrees clockwise from its x. SVG's y does the same. So for a move to the right, a negative y bends the path up the slide.

Where: a keyframe's `motion-path`

| key | required | values | description |
| --- | --- | --- | --- |
| `geometry` | yes |  | The path of the move in SVG path data. It runs from the move's start at 0 0 to its end at 1 0. It is one open contour of 2 to 8,192 points. It has at most 2,097,152 characters. |
| `orient` |  |  | Whether the object turns to face along the path. The default is false. |

**Along the path.** The object moves along the path at the pace of the keyframe's interpolation. The interpolation sets how much of the path's length the object has traveled. Past either end, it moves on in the path's direction at that end. A 3D position's path bends its x and y, and its z moves straight. With `orient`, a flat object and a text with its model turn with the path's tangent. They turn by its direction, clockwise from the slide's x. One that heads to the right isn't turned. A model turns about its parent's y to face where it travels across x and z. While it travels along y alone, it keeps facing the way it did. Each one's own `rotation` adds to that turn, and a model's own rotation turns it first. When the move ends, each keeps facing that way until its next move along a path with `orient`. No other 3D object turns. An object turns along one path at a time. When a `translation` path and a `frame.position` path that both have `orient` overlap in time, only the `frame.position` path turns it, and the file is read with a warning.

#### cue

An event at a set time in a step. Its id is unique in its step among its keyframes and cues. A `paragraph` cue shows a paragraph of a text or a shape. A `play` cue starts an audio object, a video, or a web video. A `clip` cue plays an Action of the GLB `file` of a model or a 3D text. A cue on an object of any other type is ignored. It causes an `ignored-animation` warning. A clip works as Cinema 4D's Motion Clip. A text built from an `extrusion` has no Actions. A clip on it plays nothing and causes a warning.

Where: `steps[].cues.<cue id>`

| key | required | values | description |
| --- | --- | --- | --- |
| `time` | yes | 0 to 4294967296 seconds | When it happens. It is in seconds into the step. |
| `type` | yes | paragraph, play, clip | What it does. |
| `object` | yes |  | The object it acts on: an object's id. |
| `action` | with type clip |  | The name of the Action that a clip plays. An unnamed Action is named Animation and its number in the file, as in `Animation 1` for the first. A clip naming an Action its object doesn't have plays nothing. It causes an `unknown-action` warning. |
| `blend-in` |  | 0 to 4294967296 seconds | How many seconds the clip takes to blend in fully over the model's current motion. Without it, or at 0, the clip is fully blended in from its start. |
| `clip-scale` |  | more than 0 | How much longer a clip's Action plays than its file says. 2 is half speed, and 0.5 is double. Maya's Clip Scale works the same way. The default is 1. It isn't used by a clip with a `stride`. |
| `clip-trim` |  | 0 to 4294967296 seconds | The part of the Action that plays. It is a start and an end in seconds. |
| `loop` |  | repeat | With `repeat`, the Action plays again from the start of its `clip-trim` each time it ends. Without it, it plays once, even an Action made to repeat. A model's `stride` times it by travel instead. |
| `paragraph` | with type paragraph |  | The id of the paragraph that appears. It is the id in the `<!-- id: … -->` at the end of the paragraph's last line or alone on the line after it. A list item's id ends its first paragraph. A reader warns when no paragraph of the text has the id. |
| `stride` |  | more than 0 and at most 1 × 10¹⁸ meters | How far the model travels per cycle of its Action in the GLB's meters. The Action's timing then follows the model's travel. A 3D text's clip with a `stride` is ignored. It causes an `ignored-animation` warning. |

**A nested item.** A list item that no cue names appears with the nearest item that it's nested under and that a cue names. One that a cue names appears at its cue or with the item it's nested under, whichever comes later.

**A clip's clock.** A clip's time starts at its cue and runs on the show's clock: through the rest of its step, the waits for a click and later clicks, until the slide ends. `time` and `blend-in` are in the slide's seconds. `clip-trim` is in the Action's seconds, and `clip-scale` turns the slide's seconds into the Action's. While the slide waits, a repeating clip plays a whole number of times over the wait and is sped up or slowed down as little as fits.

**A model's pose.** Before a model's first clip starts, it shows that clip's first trimmed pose. With a `blend-in` above 0, it shows its rest pose and blends from there. A clip that plays once holds its last trimmed pose. Each later clip changes only the node properties its Action animates. Other properties keep the earlier clips' results or the rest pose. In a step with a `repeat-count`, a clip blends in over its `blend-in` or one play of the step, whichever is shorter. So it is fully blended in when the step's next play starts it again.

**Action names.** A clip names an Action by its name in the file, matched exactly. An Action with no name, or an empty name, is named Animation and its number in the file, as in `Animation 1` for the first. An Action can have the same name as an earlier one, or a generated name that is already taken. It then gets the first of name 2, name 3, and so on that isn't taken yet. The names the file gives are reserved first. So Walk, Walk, Walk 2 are read as Walk, Walk 3, Walk 2.

#### step-effect

An object's effect in a step: an entrance, an exit, or an emphasis by name. It plays as keyframes from where the object stands as it starts. In a step that starts with or after another, that is where the earlier steps of its click have the object at its `delay`. When no initial value or earlier step keys a parameter that an entrance runs, or shows, hides, or reveals its object, the parameter has the entrance's starting value from the slide's start until the object enters. An exit leaves the object as it ends, and an emphasis returns the object to where it started. A `pieces` entrance or exit brings in or takes out a text's paragraphs, words, or characters in the look its `enter` or `exit` gives them. An effect on an object that can't animate what it keys causes an `ignored-animation` warning and plays nothing.

Where: `steps[].effects.<object id>`

| key | required | values | description |
| --- | --- | --- | --- |
| `type` | yes | enter, exit, emphasis | Which kind of effect it is. |
| `effect` | yes | appear, fade, rise, scale, blur, draw, wipe, grow, pieces, disappear, sink, pulse, bounce, blink, spin | Which effect it is. An entrance can `appear`, `fade`, `rise`, `scale`, `blur`, `draw` a stroke, `wipe`, `grow` a chart, or bring in a text's `pieces`. An exit can `disappear`, `fade`, `sink`, `scale`, `blur`, or take out a text's `pieces`. An emphasis can `pulse`, `bounce`, `blink`, or `spin`. |
| `duration` | yes | more than 0 and at most 4294967296 seconds | How long the effect lasts in seconds. The step lasts at least until the effect ends. |
| `delay` |  | 0 to 4294967296 seconds | How many seconds into the step the effect starts. Without it, the effect starts with the step. |

**What each effect plays.** `appear` sets `visible` to true as it starts, and `disappear` sets it to false. `fade` runs `opacity` from 0 to the object's own, or from where it stands to 0. `rise` runs `translation.y` 48 canvas units up to where it stands, and `sink` runs it 48 down. In 3D, the y axis runs up. `rise` runs a 3D object's `position.y` from 48 below where it stands to there, and `sink` runs it from there to 48 below. `scale` runs the object's scale from 90% of where it stands to there, or from there to 90%: its `scale.x` and `scale.y`, a model's three, a group's `scale`, or a shadow catcher's `width` and `height`. A framed object with none, such as a web video, has its frame scaled about its center. As an entrance, `blur` runs `blur` from 48 canvas units more than the object's own to its own. As an exit, it runs from the object's blur when the exit starts to 48 canvas units more. Its blurred end stops at the slide's blur limit. Rise, sink, scale, and blur also run `opacity` between the same ends as `fade` on an object that can fade. On one that can't fade but has `visible` and isn't a mask, such as a web video, they show it as an entrance starts and hide it as an exit ends. On one with neither, such as the camera, the move plays alone. An effect whose own parameter its object can't animate, such as a `blur` on a web video, plays nothing. `draw` runs a stroke's `trim.end` from its `trim.start` as the effect starts to the `trim.end` it is authored with. When those two match, it runs `trim.end` from 0 to 1 and sets a `trim.start` above 0 to 0. `wipe` runs `wipe.progress` from 0 to 1. `grow` runs a chart's `progress` from 0 to its own, or to 1 when its own is 0. A `pieces` effect runs `enter.progress` or `exit.progress` from 0 to 1. `pulse` runs the scale to 110% of where it stands at the effect's halfway point and back. `bounce` runs `translation.y` 24 canvas units up at its halfway point and back, or a 3D object's `position.y` as far. `blink` runs `opacity` to 0 at its halfway point and back. `spin` runs an object's `rotation` up 360 degrees, and a 3D object's `rotation.z` down 360 degrees. A 3D object whose `rotation-mode` is `quaternion` doesn't play `spin`. An entrance plays as if the exits since its object last entered hadn't played. A `rise` or a `scale` entrance ends where the object was when the first of those exits started. As the entrance starts, a parameter that those exits ran and the entrance doesn't run goes back to where it was then. A parameter the entrance runs follows the effect's own rule, and a `fade` still runs `opacity` to the object's own. When a key of a parameter falls between those exits and the entrance, the entrance plays that parameter from where the key leaves it. As an entrance starts, it also sets its object's `exit.progress` back to 0 from any value above 0. Each value an effect works out stays within its parameter's range.

**3D objects and masks.** The 3D objects here are a camera, a model, a light, a shadow catcher, a floor, and the World. A text drawn by its 3D `model` is a text here: it uses the same parameters as a flat text. On a mask, an effect that runs `opacity`, `blur`, a trim, or `wipe.progress` plays nothing and causes an `ignored-animation` warning. An effect that moves or scales a mask never fades it or changes its `visible`.

**How each eases.** An entrance eases out and an exit eases in. Their `opacity` eases the same way, but Fade In's runs on its own curve. An emphasis eases out to its halfway point and in back. In CSS's cubic-bezier() form, `fade` runs on (0.33, 1, 0.68, 1) as an entrance, `draw` on (0.65, 0, 0.35, 1), and `wipe` on (0.16, 1, 0.3, 1). `blink` eases in to its halfway point and out back, and `spin` runs on `ease-in-out`. `appear` and `disappear` cut at once, and a `pieces` effect runs on `linear`.

#### interpolation

Named interpolations: how a value changes over a move, gradually or at once. Transitions can use linear, ease-in, ease-out, and ease-in-out. A keyframe's or a text's interpolation can instead be a named curve with its settings. That includes a cubic Bézier of its own.

Where: a keyframe's, a transition's, and a text's `interpolation`

| name | required | values | description |
| --- | --- | --- | --- |
| `anticipate` |  |  | Pulls back before it moves. |
| `anticipate-overshoot` |  |  | Pulls back first, then passes the keyframe's value and settles back on it. |
| `bounce` |  |  | Falls onto the keyframe's value and bounces off it three times. Each bounce is lower. It never passes the value. Its bounciness is 0.5. |
| `ease-in` |  |  | Starts slowly from the previous keyframe. CSS's ease-in works the same way. |
| `ease-in-out` |  |  | Starts slowly and ends slowly. CSS's ease-in-out works the same way. |
| `ease-out` |  |  | Slows down as it reaches the keyframe. CSS's ease-out works the same way. |
| `elastic` |  |  | Springs past the keyframe's value and swings into it. Each swing is smaller. |
| `hold` |  |  | Keeps the previous value until the keyframe's time, then jumps. |
| `linear` |  |  | Moves at a constant speed. |
| `overshoot` |  |  | Passes the keyframe's value and settles back on it. |
| `smooth` |  |  | Starts and ends gently, over a shorter part of the move than ease-in-out. |

**The named curves.** `ease-in`, `ease-out`, and `ease-in-out` are CSS's easing functions of those names. In CSS's cubic-bezier() form, `smooth` is (0.25, 0, 0.75, 1). Let b be the `back`. Its default is 1.70158. Then `anticipate` is (0.333333, 0, 0.666667, −b ÷ 3), and `overshoot` is (0.333333, (b + 3) ÷ 3, 0.666667, 1). They are Robert Penner's back in and back out. `anticipate-overshoot` is his back in and out, `elastic` is his elastic out, and `bounce` is his bounce out at a bounciness of 0.5. Blender's Back, Elastic, and Bounce are the same curves. Below an amplitude of 1, they differ: Blender's Elastic and `elastic` shrink the swing, and Penner's keeps it at 1.

#### keyframe-interpolation

An interpolation's settings say how far `anticipate`, `overshoot`, or `anticipate-overshoot` pulls back or swings past. They can also give an elastic's swing, a bounce's bounciness, a spring's damping ratio, or a cubic Bézier's two handles. The handles' keys are named the way CSS's cubic-bezier() names its four numbers. A named curve with no settings is written as just its name. A cubic Bézier that is the same as a named curve is written as that named curve's name too.

Where: a keyframe's or a text's `interpolation` written as an interpolation with its settings

| key | required | values | description |
| --- | --- | --- | --- |
| `type` | yes | anticipate, overshoot, anticipate-overshoot, elastic, bounce, spring, cubic-bezier | The kind of interpolation. It is a named curve, a cubic Bézier, or a spring. |
| `amplitude` |  | 0 or more | The size of an elastic's swing in multiples of the move. The default is 1. |
| `back` |  | 0 to 1 × 10³⁰⁷ | How far `anticipate`, `overshoot`, or `anticipate-overshoot` pulls back or swings past. Robert Penner's back curves and Blender's Back use it the same way. The default is 1.70158. |
| `bounciness` |  | 0 to 1 | A bounce's rebound speed in fractions of its landing speed. At 0, it lands dead. At 1, it rebounds to its height each time. The default 0.5 is Blender's Bounce. |
| `damping-ratio` | with type spring | 0.3 to 1 | How strongly a spring is damped. At 1, it doesn't swing past its keyframe. With less damping, it swings farther. |
| `period` |  | more than 0 and at most 4294967296 seconds | How many seconds one swing of an elastic lasts. The default is 0.3 of the length of the move. A text's `enter` and `exit` don't use it. |
| `response` |  | more than 0 and at most 4294967296 seconds | The spring's natural period in seconds. A shorter one springs faster. Without it, the spring settles by the end of the move. A text's `enter` and `exit` don't use it. |
| `x1` | with type cubic-bezier | 0 to 1 | The time of a cubic Bézier's first handle in fractions of the move. |
| `x2` | with type cubic-bezier | 0 to 1 | The time of a cubic Bézier's second handle in fractions of the move. |
| `y1` | with type cubic-bezier | any number | The value of a cubic Bézier's first handle in fractions of the change. It can be below 0 or above 1. The move can then go past an end. It stops at the end of the parameter's range. |
| `y2` | with type cubic-bezier | any number | The value of a cubic Bézier's second handle in fractions of the change. It can be below 0 or above 1. The move can then go past an end. It stops at the end of the parameter's range. |

**Springs.** A spring's `response` is its natural period, in seconds: how long one swing would take with no damping. Its `damping-ratio` d is how strongly it is damped. SwiftUI's response and dampingRatio mean the same. A ratio of 1 is critical damping. With damping, each swing lasts the response divided by √(1 − d²). At a ratio of 0.3, that is about 1.05 times the response. A Position constraint's `response` and `damping-ratio` mean the same. A spring keyframe reaches its value at its time. The format doesn't set the motion between beyond its response and damping ratio. A SwiftUI spring keyframe with no duration lasts for its spring's settling duration.

#### fonts

Where: `fonts`

| key | required | values | description |

**Families.** Family names match by Unicode's canonical caseless match. It uses the full case folding of Unicode 17.0.0. For example, INTER is Inter, and Café is one name whether its é is one composed character or an e and a combining accent. In CSS's matching, those are two names. A theme can have its own faces for a bundled family too. Its slides then draw those faces wherever they draw that family. Each `font-files` key is matched to the families `fonts` names this way. A key that no role names is kept and reads with an `ignored-key` warning. Its faces aren't drawn.

**Fallbacks.** A character a role's family doesn't draw is drawn with the first of MarkdownPoint's fallback families that draws it. A role whose family is neither bundled nor in `font-files` draws all its text with them. They are tried in this order: Inter, Noto Emoji, Noto Sans JP, Noto Sans KR, Noto Sans SC, Noto Sans TC, Noto Sans Arabic, Noto Sans Devanagari, Noto Sans Thai, Noto Sans Hebrew, and Adobe NotDef. For `mono`, Source Code Pro comes before them. Noto Emoji draws emoji in one color: the text's. Noto Sans JP, Noto Sans KR, Noto Sans SC, and Noto Sans TC each draw the characters Chinese, Japanese, and Korean share in their own region's forms. The one for the presentation's `locale` comes first among them. The others keep their order. For Korean, it is Noto Sans KR. For any other locale, it is the family for the script its Chinese characters are written in: Noto Sans TC for traditional and Noto Sans SC for simplified. That script is the one the tag names. A tag that names none takes the one CLDR's likely subtags give for its language and region. It takes none when CLDR has no locale for its language. So `zh-TW` takes Noto Sans TC, `yue` takes Noto Sans TC, and `zh` takes Noto Sans SC. Chinese in any other script, such as `zh-Latn`, takes Noto Sans SC. Any other locale written in neither script takes Noto Sans JP. The last fallback, Adobe NotDef, draws any character as a box.

**Faces.** A face's weight is the range of its `fvar` table's `wght` axis, else its OS/2 table's `usWeightClass`. It is italic when its OS/2 table's `fsSelection` or its `head` table's `macStyle` sets the italic bit. OpenType defines these tables. Each character is drawn in the face that CSS Fonts Level 4's font matching chooses for the text's weight and style among the faces of the family that draws it. No face is slanted or made bolder to stand in for one the family lacks. So italic text stands upright in a family with no italic face.

**Embedded faces.** An .eot file has one face in Embedded OpenType. PowerPoint documents embed their fonts in this format. It is defined by a W3C Member Submission. The file is plain, or scrambled with the flag 0x10000000. It is never compressed with 0x4. The face's OS/2 table's `fsType` alone decides whether it is drawn. A face is drawn when it is installable or editable. It isn't drawn when it is restricted, preview and print, or bitmap only, when its table is version 3 or later and sets more than one of the restricted, preview and print, and editable bits, or when it has no OS/2 table. Before version 3, the least restrictive of those bits counts. A face that isn't drawn reads as `invalid-font`, and the theme still reads.

## <a id="schemas"></a>JSON Schemas

Each JSON file has a draft-07 JSON Schema in [schemas/1.0](schemas/1.0/). The schema is named for the `type` the file states. The folder is named for the version, 1.0. Each minor version's schemas are in a folder of their own. A published folder never changes. A schema's `$id` is https://markdownpoint.com/format/schemas/1.0/ followed by its file name. Refer to a schema by its `$id`. Its `definitions` are its own and may change. A schema checks a file's keys, their values, and the keys a record needs. It refuses what a later minor adds: a key, a word, an object type, or a number outside a range. MarkdownPoint passes over each and keeps it. MarkdownPoint also reads a number to six decimal places before checking it. A schema checks the number as written. The schemas' patterns are ECMA 262 regular expressions, the dialect draft-07 names, and they use lookahead. A validator whose engine has no lookahead, such as RE2, can't compile them.

MarkdownPoint also checks what a schema doesn't:

Every JSON file:

- A JSON object never has the same name twice. A file that does is refused.
- Objects and arrays nest at most 256 levels deep. The outermost one counts as the first level. A file nested 256 levels deep is read, and one nested 257 is refused.
- A file may start with a byte order mark. MarkdownPoint skips it.
- A file with a number too large for a double is refused.

[presentation.schema.json](schemas/1.0/presentation.schema.json):

- A locale names each variant once.
- A transition's `delay` goes only beside `start: automatically`.
- Every file a background or an object names is in the presentation's media or generated folder.
- A file path is in Unicode's composed form (NFC). Each of its names is at most 255 bytes in UTF-8.
- Only the camera and the World have the ids `camera` and `world`.
- A 3D object's parent is a model or a light, and not the object itself. Any other is skipped with a warning, its `parent-node` and `parent-inverse` with it. A constraint's target is one its constraint takes. Any other is skipped with a warning.
- A flat object's parent is a group, and not the object itself. A text with a `model` has none. Any other parent is dropped with a warning. Groups nest at most 200 deep. A deeper group stands at the root with its members and causes a warning. No object is its own parent through others. In groups and in 3D alike, every link of such a loop is dropped with a warning. No Aim's target waits on the model it turns. Such an Aim turns nothing and causes a warning. The parents in its loop stay.
- A shape with text, or a group that can't repeat, keeps its `repeater` and makes no copies. The repeater is ignored with a warning.
- A slide's objects have unique ids. None of its own objects has an id that its overrides change.
- A 3D object's rotation in degrees has no w. In quaternion mode, it has w, x, y, and z. A quaternion's parts don't all read as 0.
- A web video's address names a video.
- A path's `geometry`, an image's `mask`, and a text's `text-path` are well-formed SVG path data that starts with a move. Once the path data is made absolute, each point and handle has finite coordinates. A video's or an audio object's `media-trim` ends after it starts. An object's constraints have unique ids.
- A text's enter or exit has a `seed` only when `order` is `random`. An enter with a `delivery` has `based-on` set to `paragraph`. Its `order`, `spread`, `pause`, and `progress` are then at their defaults.
- An override's key and value apply only to an inherited object that can have them. Other overrides are kept but ignored, and cause a warning.
- An animated parameter is one its object has. A keyframe's value is a valid value of that parameter. A name or a value that isn't valid for any object's parameter is refused. One that is valid elsewhere but not on its own object is ignored with a warning.
- Only a keyframe of `scale`, `scale.x`, `scale.y`, `scale.z`, or `crop.scale` can have `exponential-scale`. An `initial` value can't set a point parameter, such as `frame.position`. It can set the point's parts.
- A slide's steps have unique ids. A step's keyframes and cues have unique ids among them all. A keyframe's move starts before its time. An interrupted move would have reached its value at or after the keyframe's time.
- Only a point keyframe can have a motion path. It is one open contour from 0 0 to 1 0. A clip's trim ends after it starts.
- Every string and key is well-formed Unicode. None holds an unpaired surrogate. A lone `\ud800` is one.

[master.schema.json](schemas/1.0/master.schema.json):

- A font family's name starts with a letter or a digit of any script. It has only letters, combining marks, digits, spaces, periods, underscores, and hyphens. It doesn't end with a space. A `font-files` key is spelled the same way. No two `font-files` keys name the same family. They are matched the same way `fonts` matches a family.
- A file path is in Unicode's composed form (NFC). Each of its names is at most 255 bytes in UTF-8.
- A brand color a scheme names is one the brand has.
- The scheme named light is light, and the one named dark is dark.
- The words in `text` belong to the master's own text, table, chart, and shape objects.
- Its objects pass the presentation's object checks.
- Every string and key is well-formed Unicode. None holds an unpaired surrogate. A lone `\ud800` is one.

[layout.schema.json](schemas/1.0/layout.schema.json):

- The words in `text` belong to the layout's own text, table, chart, and shape objects.
- A placeholder names one file, not one per scheme.
- Its objects and overrides pass the presentation's object checks.
- Every string and key is well-formed Unicode. None holds an unpaired surrogate. A lone `\ud800` is one.
