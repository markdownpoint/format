# MarkdownPoint file format reference

This reference lists every key in the files and what it does.

In each table, the required column says when a record needs the key. Yes means always. Otherwise it names the case, such as "with max". The values column lists the words or numbers the key can be set to. A range includes both of its ends. On a key with an x and a y, a range applies to each of them.

## <a id="files"></a>Files

### <a id="presentation-folder"></a>The presentation's folder

A presentation is a folder with two files at its root: `slides.md` and `presentation.mdpoint`. Their names can be in any letter case. The folder's name is the presentation's name. The presentation doesn't open if its root has another .mdpoint file, or another .md file whose name starts with slides in any letter case and goes on with anything but a letter or a combining mark, as in `Slides 2.md` or `slides2.md`. A sync service's conflicted copy is such a file.

- [`slides.md`](#slides-md): the sections, the slides' order and text, and the presenter notes.
- [`presentation.mdpoint`](#presentation-mdpoint): the theme, the slides' objects and animation, and the settings. It is JSON.
- media/: the author's files.
- generated/: the files MarkdownPoint makes, and the [.json files](#generated) that record how each image was made.
- themes/: the presentation's [themes](#theme-folder).
- versions/: the presentation's [saved versions](#versions).

Files and folders whose names start with `.markdownpoint` belong to MarkdownPoint. Everything else in the folder belongs to the author.

### <a id="theme-folder"></a>A theme's folder

A theme is a folder in themes/. The folder is named after the theme's key. Its root has the theme's [master](#the-master), master.json, and a .json file for each [layout](#layouts). A layout's file is named after the layout's key.

### <a id="theme-package-file"></a>A theme package

A theme package is one .mdptheme file. The file is a ZIP archive of one folder. The folder is named after the theme's key, and it contains [manifest.json](#theme-package), the theme's JSON files, and the files they name. manifest.json lists every one of the theme's files in the folder and only those. A package whose folder lacks a listed file, has an unlisted one, or has one of another size or SHA-256 is refused whole. Names starting with a dot, and Finder's folder icon file, are passed over at any depth and aren't installed. That file's name is `Icon` followed by a carriage return (U+000D). The folder holds one master. The archive is a classic ZIP file (APPNOTE 6.3). Each entry is deflated or left uncompressed, and its name is in UTF-8. A writer sets general-purpose bit 11. A reader also takes an entry without it, and a deflated entry with its level in bits 1 and 2. It has no encryption, data descriptor, ZIP64 record, or split. Its root holds the theme's folder alone. The archive has no symbolic links.

The folder can also have two folders that aren't the theme's files, and manifest.json lists neither. In previews/, cover.jpg is a picture of the theme. Its slides/ folder has a picture of each example slide in order: 1.jpg, 2.jpg, and so on. example/ has a presentation that a new presentation can start from. It can have only presentation.mdpoint, slides.md, and the media/ and generated/ folders.

### <a id="paths"></a>File names and paths

A file path is relative to the presentation's folder or the theme's folder. It has / between names. A name can't be empty, `.`, or `..`. It can't start with a dot or end in a space or a dot. It can't contain a backslash, <, >, :, ", |, ?, *, #, or a control character. Here and throughout this reference, a control character is one of U+0000 to U+001F and U+007F to U+009F. Blank text has only the white space ECMAScript's `trim` takes off. CON, PRN, AUX, NUL, COM1 to COM9, LPT1 to LPT9, COM¹ to COM³, and LPT¹ to LPT³ can't be file names in any letter case or with any extension. A path is in NFC. It names each file as its folder lists it, the two compared in NFC. A name is at most 255 bytes in UTF-8. No folder has two names that are the same under Unicode's canonical caseless match. It uses the full case folding of Unicode 17.0.0. Under it, ß and SS are the same.

A presentation's files are under media/ or generated/. A file under generated/ whose extension is .json in any letter case isn't one of them. A theme's files can go anywhere in its folder except at its root under the package's three names: manifest.json, previews, and example. A name that matches one of them under the caseless match, such as Previews, is refused, and a theme package spells all three in lowercase. An image file's name ends in .png, .jpg, .jpeg, .gif, .webp, .svg, .avif, or .bmp. A video's ends in .mp4, .m4v, .mov, .webm, or .ogv, an audio file's in .mp3, .m4a, .wav, .ogg, or .flac, a model's in .glb, and an embedded font's in .eot. The extension can be in any letter case. A file reached through a symbolic link or an alias is never one of the presentation's files.

### <a id="format-version"></a>The format version

Every file states its format version in `markdownpoint`. It is a major and a minor number in quotes, each of at most nine digits and written without a leading zero: "1.0". Every key in this reference is from version 1.0. MarkdownPoint 1.x opens any version 1.x file. A later minor version only adds what an earlier MarkdownPoint can skip, such as a key, a word, an object type, or a number outside a range. The earlier MarkdownPoint draws it as nothing or as its key's default. A `shape-type` it doesn't know draws as a rectangle. In an override, it draws what the object inherits. A keyframe whose `time` or `value` it can't read passes over its whole curve. A word it can't read can decide which keys a record needs or how they read: a text's `auto-size` when its frame leaves out a side, or a 3D object's `rotation-mode`. The earlier MarkdownPoint then passes over the whole record. It draws nothing for it and keeps it as written. In a later minor version's .md file, a marker-shaped line starts a block when its word is neither `id` nor one of the earlier MarkdownPoint's markers. It keeps the block as written, shows nothing for it, and ends it at the next marker. Each save writes the block back after the block it followed. In a file of its own minor or an earlier one, such a line is a note. A marker that a minor version adds is a marker only in a file of that version or later. A misspelling of it is an error only in those files. In an earlier version's file, either line is a note. A file in the layout MarkdownPoint writes saves back to its own bytes. A later minor version can widen a key's range. It can't raise these limits: 8,192 on each side of a slide, the widest blur and shadow a slide draws (250 and 100 when its shorter side is 1080 or less), 25,000 cells in a table, 8,192 points and 2,097,152 characters of path data, 512 objects beyond a slide's own, groups nested 200 deep, lists and quotes nested 100 deep, a model file's limits, 268,435,456 pixels in a generated image, and JSON nested 256 levels deep. A save writes the later of two versions: the one the file states and the saving MarkdownPoint's own. A presentation's .mdpoint file and .md file save at one version: the later of the two files' versions and the saving MarkdownPoint's own. A save never lowers a file's version. A file of a newer major version needs a newer MarkdownPoint. A JSON file of a version MarkdownPoint knows has only the keys this reference lists. Each key appears once. Any other key is an error, most likely a typo. Outside an override, a key that only another kind of its record takes, such as `direction` on a `cross-dissolve` transition, is an error too. A chart type or a shape kind isn't such a kind. No version adds a key with a capital letter. So an unknown key with a capital letter is an error in a JSON file of any version. An `id` key in a keyframe or a cue and a `target` key in a curve are errors in any version too. A keyframe or a cue is already under its id, and a curve under its "object.parameter" key.

### <a id="ids"></a>Ids

An id starts with a lowercase letter from a to z. The rest is a to z, 0 to 9, and single hyphens, such as title-card. It ends with a letter or a digit. Where ids are put in order, they are compared character by character. A hyphen comes before a digit, and a digit comes before a letter. So `k10` comes before `k9`. Slides and compositions share one set of ids. Four ids are lowercase UUIDs instead: a presentation's id, a save's id, a theme's id in its master, and an image generation's id. A theme's key and a layout's key are ids that every supported system can use as a file name. A theme's key is at most 255 characters and a layout's at most 250. A layout's key can't be master or manifest. The names a theme gives its schemes, color roles, brand colors, and text styles are spelled as ids. A JSON object's members have no order. A master's `layout-order`, `scheme-order`, `text-style-order`, and `brand.color-order` set the order the theme's layouts, schemes, text styles, and brand colors show in. A scheme's further roles show in name order. A binding names a key, or a number part of a record, such as `tilt.x`. Each name in it is spelled as an id. A font family's name starts with a letter or a digit in any script. The rest is letters, combining marks, digits, spaces, dots, underscores, and hyphens. It doesn't end with a space. A `font-files` key is spelled the same way.

### <a id="colors"></a>Colors

A color is a role in the theme's color scheme, such as accent, or a hex color in sRGB. A hex color is written #RGB, #RGBA, #RRGGBB, or #RRGGBBAA. Its alpha is straight, not premultiplied. A light's, the World's, a shadow's, and a fade through color's color has no alpha: a hex one is written #RGB or #RRGGBB. Where a color drawn from a key names a role the slide's scheme lacks, it causes an `unknown-color-role` warning and draws as `text`. A fade through color then fades through black.

### <a id="units"></a>Units

A canvas unit is one pixel of the slide at full size. In 3D, a canvas unit is the theme's `unit-scale` in meters. An icon unit is a 24th of the frame's width across and a 24th of its height down. Each icon is drawn on Lucide's square. The square is 24 icon units wide. It stretches to fill the frame. A blur is measured by its radius. CSS `box-shadow` uses the same radius. The radius is twice the Gaussian's standard deviation. CSS `filter: blur(8px)` is a blur of 16. An object's blur and shadow, before any scale paints them, draw no wider than their slide takes. A blur's radius draws at most 250 and a shadow's size at most 100 when the slide's shorter side is 1080 or less. The limits grow in proportion on a larger slide. They are 500 and 200 at 3840 × 2160. An object's blur or shadow past them is kept as written, draws at the limit, and causes the warning `effect-size-limit`. A background picture's shadow has the same limits. In a composition, they follow the composition's `size`. They don't apply to a text's drop shadow. A text's `tracking`, `text-stroke-weight`, and drop shadow are in ems of its `font-size`. A heading in the text uses the same lengths as the rest of its words. An entrance's or exit's look is the exception: its `offset` and `blur` are in ems of each piece's own font size. On a shape, `tracking` and `text-stroke-weight` are in ems of its words' `font-size`, and its drop shadow is in canvas units. On a chart, `tracking` and `text-stroke-weight` are in ems of the size of the words they apply to. A mark's `tracking` is in ems of the size of its own words. Code's words are 0.92 times the size of the words around them. In a heading, those are the heading's.

A light draws no brighter than the GPU's 32-bit floats hold. Its shaders take an intensity of at most 1 × 10³⁰. For a directional light, that is its `intensity` times π. For a point or spot light, it is its watts over 4π and over the square of `unit-scale`. For an area light, it is its watts over π, over its area in square canvas units, and over the square of `unit-scale`. A brighter light is kept as written and draws at that most.

### <a id="numbers"></a>Numbers

Every number is read as the IEEE 754 double nearest to it. ECMAScript's numbers are of this kind. The double is rounded to six decimal places the way ECMAScript's `Number(x.toFixed(6))` rounds it. `toFixed` rounds a half away from zero. A negative zero is read as 0. Then the number is checked against its range. 1.0000004 is read as 1. The half −0.0078125 is read as −0.007813. The double nearest 0.1234565 is just under it. So 0.1234565 is read as 0.123456. A theme's `unit-scale` is checked against its range as written. Then it is rounded to 12 significant digits the way ECMAScript's `Number(x.toPrecision(12))` rounds it. A byte count, an image's size in pixels, and a `parent-inverse` are read exactly as written. A chart cell is read as the double nearest to it and isn't rounded to six places. Each point and handle of path data is rounded to six decimal places once the path is absolute and its curves are cubic.

### <a id="points"></a>Points

A value of x and y, or of x, y, and z, has every part. That includes an `anchor-point`, a crop's `focal-point`, a group's `tilt`, an area light's `size`, a repeater's `position`, a model's, a light's, or a shadow catcher's `position`, and a drift's `offset`. One with a part left out isn't valid. Only the camera's `position` can leave out parts. In an override, the keys that change in part give only the parts they change.

### <a id="links"></a>Links

A link is an http or https URL with a host, a mailto: or tel: address, or slide: followed by a slide's id. http, https, mailto, and tel can be in any letter case, and slide: is lowercase. It has no spaces or control characters. An http or https URL has no backslash. A link to anything else, or to a slide that isn't there, is still a link but does nothing. A link to a skipped slide does nothing in the show or in a PDF until the slide is shown again.

### <a id="code"></a>Code

No key's value is code. MarkdownPoint runs no code from a presentation's folder or a theme. A text shows an HTML tag as plain text, and an SVG image runs none of its scripts. The one exception is a web video. Its YouTube or Vimeo player runs the provider's own scripts.

## <a id="slides-md"></a>`slides.md`

#### frontmatter

The keys MarkdownPoint reads, each on one line as key: value. A value can be in single or double quotes, and a comment can follow it. Any other spelling YAML reads as one of these keys, such as `"footer":`, is refused. One of these keys that appears twice is refused too. Other keys are kept as written. A notes app can add its own keys, such as tags, and the presentation still opens. The file's first line is `---`. A byte order mark before it is skipped. Each fence line is `---` and its line end. The frontmatter's lines end in LF or CRLF. MarkdownPoint writes `markdownpoint`, `id`, `save-id`, and `footer` in that order.

Where: the frontmatter at the top

| key | required | values | description |
| --- | --- | --- | --- |
| `markdownpoint` | yes |  | The format version. It is a major and a minor number in quotes, each of at most nine digits and written without a leading zero: "1.0". |
| `id` | yes |  | The presentation's id. The .mdpoint file has the same id. |
| `footer` |  | one line with no control characters or line breaks | The footer text. Every slide with a footer field shows it. Without quotes, a space followed by `#` starts a comment. Quote a footer that YAML 1.2's core schema reads as null, a boolean, or a number. |
| `save-id` |  |  | The id of the save that last wrote the file while people edited the presentation together. Other saves and other tools leave it unchanged. |

**`save-id`.** A save writes the same `save-id` into both files. The presentation's `save-id` is the .mdpoint file's. While a sync service has delivered only one of a save's two files, the frontmatter's `save-id` can differ from the .mdpoint file's. That isn't an error.

#### markers

The markers that divide the .md file into sections, slides, and their text. Spaces or tabs before or after a marker, after its `<!--`, after its colon, or before its `-->` don't change it. Each marker ends with a line break, even at the end of the file. A marker between code fences is code. A top-level code block that holds one must be closed. Each of a slide's own texts has a text marker, even when its text is empty. A table's or a chart's marker holds its table. A shape has one once it has words. Without its marker, a slide's own text has empty text. Without its marker, or with an empty one, its own table or chart has a new table's empty cells. Each causes a `missing-text-block` warning. A composition's own text, table, or chart does the same unless a control sets its words. A table or a chart is skipped with an `invalid-table` error where its marker's words aren't one table that **Tables** reads. A layout's placeholder takes no words from the layout. It needs a text marker only once it has words. Until then, its empty marker means the same as none. A text marker whose words nothing there takes, such as one for an inherited object that isn't a placeholder, is ignored and causes an `ignored-text-block` warning. A control marker that names no text control of its composition, or stands in a slide, is ignored and causes an `ignored-control-block` warning. A text marker's id appears once in its slide or composition.

Where: a line of its own in the body

| marker | required | values | description |
| --- | --- | --- | --- |
| `section` |  |  | `<!-- section: id -->` starts a section. It holds the slides after it, up to the next section marker. Its id is unique among sections. One level-1 heading after it is the section's name. |
| `slide` |  |  | `<!-- slide: id -->` starts a slide. Each slide has one, and the markers come in presentation order. |
| `composition` |  |  | `<!-- composition: id -->` starts a composition's text. Each composition has one. |
| `text` |  |  | `<!-- text: id -->` starts an object's text. `<!-- text: <instance id>.<control id> -->` starts an instance's words for a text control. Either one with no words under it is empty text. |
| `control` |  |  | `<!-- control: id -->` starts the default text of a composition's text control. The id is the control's, and it appears once in its block. Without it, that text is empty and causes a warning. |
| `notes` |  |  | `<!-- notes -->` starts the presenter notes of its slide or composition. A composition's notes show only while it is edited. An instance doesn't add them to its slide's notes. |

**Sections.** A section's block holds one level-1 heading and nothing else. The section's name is the heading's words as plain text: marks, code, spans, and links keep only their words, and an autolink gives its address. Anything else in the heading, such as a field, an image, a hard line break, or a comment, is an error. The name is read in Unicode's composed form (NFC) with one space between its words. It holds no control character. A heading with no words is an error. Once there is a section, every slide must be in one. A slide before the first section is an error.

#### body

How the body is divided, and what is kept as written. A comment line that is one word, or a word, a colon, and an id or two ids joined by a dot, is marker-shaped. Such a word is a run of the letters a to z, or several runs joined by single hyphens. Spaces or tabs can stand in it where they can in a marker. Only a marker starts a slide. The slide continues until the next slide, section, or composition marker, or the end of the file. A paragraph id in presenter notes is never shown, and no step can name it.

Where: the body, between and inside the markers

| form | required | values | description |
| --- | --- | --- | --- |
| `escape` |  |  | A marker-shaped line, or one that reads as a misspelled marker, stays in its block when a backslash follows its `<!--`: `<!--\ todo -->`. MarkdownPoint escapes every such note. Outside code, the backslash isn't shown. |
| `blank-line` |  |  | Blank lines only separate. Several blank lines in a row are the same as one. Under a marker or before the next one, they mean nothing. In a code block that's never closed, each is code, except a blank last line of the file. |
| `comment` |  |  | An HTML comment in a text or notes block is a note. It is kept but not shown. An `id` comment is the exception. |
| `unsupported` |  |  | Markdown that MarkdownPoint doesn't support is kept as written and shown as plain text: images, HTML tags other than `<br>`, footnotes, task-list boxes, bare addresses, and reference links. |

**Misspelled markers.** A comment line that starts with a marker's word in any letter case and has at most one other word is a misspelled marker. A closing slash, or words after `-->`, don't change this. It is an error. A comment that starts with such a line is a note to yourself when its first `-->` ends a later line and comes before the next `<!--`.

**Merge conflicts.** A merge conflict runs from a line that starts with seven `<` and a space to a later line that starts with seven `>` and a space. These are git's default markers. Such a conflict is an error in the frontmatter and anywhere outside a fenced code block. Inside one, its lines are code. A line of seven `=` alone is no conflict.

#### markdown

The Markdown that text, tables, and presenter notes use.

Where: text blocks, table cells, and presenter notes

| form | required | values | description |
| --- | --- | --- | --- |
| `paragraph` |  |  | A blank line separates paragraphs. A line ending inside a paragraph is a space. End the line with a backslash or two spaces to break it. |
| `id` |  |  | A paragraph's id ends its last line, as in `<!-- id: k3x9a2 -->`, or stands alone on the next. A list item's ends its first paragraph. When an id repeats, the later paragraph has none. |
| `heading` |  |  | `# Heading` to `###### Heading` are headings. A line underlined with `===` or `---` is a level-1 or level-2 heading. |
| `bulleted-list` |  |  | Lines starting with `- `, `* `, or `+ ` are a bulleted list. Indent for deeper levels. Any other paragraph between items ends it. |
| `numbered-list` |  | a first number from 0 to 999,999,999 | Lines starting with `1. ` or `1) ` are a numbered list. It starts at its first number and counts up. Any other paragraph between items ends it. |
| `quote` |  |  | Lines starting with `> ` are a quote. |
| `code-block` |  | bash (sh, shell, zsh), c, cpp (c++, cc, cxx, h, h++, hh, hpp, hxx), csharp (c#, cs), css, diff (patch), go (golang), java (jsp), javascript (cjs, js, jsx, mjs), json (json5, jsonc), kotlin (kt, ktm, kts, ktx), markdown (md, mkd, mkdown), php, python (gyp, ipython, py), ruby (gemspec, irb, podspec, rb, thor), rust (rs), sql, swift, typescript (cts, mts, ts, tsx), xml (atom, html, plist, rss, svg, wsf, xhtml, xjb, xsd, xsl), yaml (yml) | Lines between fences of three or more backticks or tildes are a code block. It is colored for its language by highlight.js 11.12.0. A marker in it is code. |
| `rule` |  |  | A line of `***`, `___`, or `---` is a horizontal rule anywhere in its block. A `---` directly under a paragraph's text isn't a rule. It makes that text a heading. |
| `table` |  |  | A table's or a chart's text is one Markdown table: a header row, a divider row, and body rows. `\|` goes between cells. No HTML comment can follow it. A divider's colons align columns. |
| `bold` |  |  | `**text**` or `__text__` is bold. |
| `italic` |  |  | `*text*` or `_text_` is italic. |
| `highlight` |  |  | `==text==` is highlighted. |
| `strikethrough` |  |  | `~~text~~` is struck through. One `~` is plain text. |
| `code` |  |  | `` `text` `` is code. It can have a color and a link, but no other mark and no weight of its own. |
| `link` |  |  | `[text](address "title")` links to a webpage, an email address, a phone number, or a slide as `slide:id`. The title is optional. `<address>` is a link that shows its address. |
| `color` |  |  | `[text]{color=accent}` or `[text]{color="#2F7D4F"}` colors text with a color role or a hex color. A role the scheme lacks causes an `unknown-color-role` warning and draws as `text`. |
| `font-weight` |  | 100, 200, 300, 400, 500, 600, 700, 800, 900 | `[text]{font-weight=600}` gives text its own weight, and bold overrides it. With a color, it's one span: `[text]{color=accent font-weight=600}`. |
| `field` |  | slide-number, slide-count, section-number, section-name, date, footer | `{{name}}` shows a value that MarkdownPoint fills in. Fields, below, describes each one. The name is a lowercase letter, then lowercase letters, digits, and hyphens. No space stands inside the braces. Anything else in double braces is plain text. A name that isn't a field shows as written in every minor. |
| `line-break` |  |  | A backslash or two spaces at the end of a line make a line break inside the paragraph. `<br>` makes one too, and it is the only one a table cell's line can hold. It can be in any letter case, and spaces, tabs, and one `/` can stand before its `>`, the `/` last: `<BR>`, `<br/>`, and `<br />` are line breaks too. |

**Empty paragraphs.** A paragraph of only `<br>` has one line break fewer than it has `<br>`. An empty paragraph is a line that starts with `<br>` and has only spaces or tabs after it.

**Paragraph ids.** When a paragraph is split, its first part has the id. When paragraphs are joined, the first one's id stays.

**Bold and italic** follow CommonMark except in one way. A run of `*` with punctuation on one side and any character but white space or punctuation on the other can both open and close.

**Highlight and strikethrough.** Two `=` or two `~` open where the next character isn't white space, whatever stands before them. The words they mark are at least one character long and end in one that isn't white space. The first two after such an end close them. Two inside code, an HTML tag, an autolink, brackets, a span's braces, or a link's or a picture's address close nothing. Neither does an escaped `=` or `~`. So `File format==.==` highlights the period.

**Code blocks.** Lines indented by four spaces or a tab are also a code block. A fence's language name can be in any letter case. Code in another language or in none shows uncolored. Its fence keeps the name. The words after the language are the fence's options. They are in braces as Slidev writes them. `{lines:true}` numbers the lines. Any other option is kept as written.

**Escapes.** A backslash before punctuation makes it plain text. Outside code, a character reference such as `&amp;` or `&#169;` is read as its character. An address written without `<` and `>` or a link's brackets stays plain text.

**Reference links.** A reference link such as `[text][label]` stays as written and shows as plain text in every 1.x version. A definition line such as `[label]: address` does too.

**Spans.** A span's attributes, `color` and `font-weight`, can come in either order. A key is a lowercase letter and then lowercase letters, digits, and hyphens. No space stands beside its `=`. A bare value is one or more characters with no white space, quote, or brace. Braces that hold anything else make no span. The brackets and braces then show as written, and the words keep their marks. Each value can be bare or in single or double quotes. A quoted value holds no quote of its kind, and a backslash in it is a backslash. A value stays on one line. A span's closing bracket pairs with its opening one. An escaped bracket or one in code doesn't count. A span can hold any inline Markdown, a link or another span included. An inner span's color or weight replaces the outer one's. Spaces, tabs, or one line break can stand between the attributes and inside the braces. A span with any other key, a repeated key, or a value its key doesn't accept stays as written in the file. MarkdownPoint skips that attribute and applies the others. When a key repeats, only its first counts. An attribute from a later minor version is skipped the same way. Inside another span, a value its key doesn't accept still replaces the outer span's value with none. A span with no attributes, `[words]{}`, groups its words and gives them no formatting. A bold word is drawn at bold's weight. Otherwise a word is drawn at its own weight. A word with no weight of its own and with a mark is drawn at its text style's weight for that mark. Any other word is drawn at its block's weight.

**Headings** are 2, 1.5, 1.17, 1, 0.83, and 0.67 times the text's size. Their weight is 700, or the text's weight where that's heavier. On a path, a heading has the text's size and weight.

**Tables.** In a text's or a shape's words, or in presenter notes, a table is Markdown that MarkdownPoint doesn't support. A table, or a chart's table, has at most 25,000 cells, counted as its rows times its columns. Two authors adding rows and columns at once can pass that. Such a table reads with a `table-cell-limit` warning and draws only its first rows within 25,000 cells. Words a control gives a table never do: **Bindings** says what it shows then. It takes no new cell until rows or columns are deleted. MarkdownPoint writes such a table's header row and delimiter row in full. It writes each body row up to its last cell with words, or as one empty cell when none has words. GFM reads the cells after them as empty. MarkdownPoint writes every other table's rows in full. Each cell is one line: outside code, no character reference in its words can name a line feed or a carriage return, such as `&#10;`. A `[words](address "title")` link may hold one in its address or title. In a cell, `\|` is a pipe. One code span can't hold a pipe after an odd run of backslashes. MarkdownPoint cuts such code before that pipe and puts every other piece in a `[…]{}` group. The pieces read as one run of code. A chart's table names its series in the header row, after the first cell. It names its categories in the first column. Its other cells are numbers in Latin digits. They use the decimal mark and group mark that Unicode CLDR 48.2.0 sets for the presentation's `locale` in its latn numbering system. The whole digits are ungrouped, or grouped in the language's widths by its group mark or by a space, never by both: 1,234.5 or 1 234.5 in English, 1 234,5 in Swedish, and 12,34,567 in Hindi. That space can be a space, a no-break space, a narrow no-break space, or a thin space. Where the group mark is an apostrophe, a right single quotation mark, U+2019, is the same mark. One number may mix the two. A number can have a sign, a prefix, or a suffix, such as $ or %. A minus is a hyphen-minus or the minus sign U+2212. A prefix or a suffix has no digit 0 to 9. So CO2: 40 has no value. A negative number can be in parentheses or end with a minus: (1,234.50) or 1 234,50 kr-. A parenthesis with no partner on the number's other side belongs to the prefix or suffix. A minus after a colon, a comma, or a period belongs to the suffix too. 100:- is 100. A cell that contains no number has no value. So 1,23 has no value in English, and 1,234 is 1.234 in Swedish. A number that runs through an address has no value either. The address can be one that GFM links in the cell's words, such as `https://example.com/1,234`, `www.example.com/1,234` or `user1@example.com`, or an autolink, such as `<foo:1,234>`. A cell's number is read from its words with their Markdown read. So `**40**` is 40, a link's words count unless they are its address, and a comment is left out. A field keeps its spelling: `{{slide-number}}` has no value. A pie or a donut draws the first series' positive values. A counter counts to the number in the second cell of the first body row, or to 0 if that cell is blank or isn't there.

**Fields.** `slide-number` is the slide's number among the shown slides, counted from 1. `slide-count` is the number of shown slides. A skipped slide has no number, and the field shows nothing there. With the slides A, B, and C, and B skipped, `{{slide-number}} of {{slide-count}}` on C shows 2 of 2. A composition's own canvas has no slide number and is in no section. In an instance, a composition's fields show the values of the slide the instance is on. `section-number` is the number of the slide's section among the sections that hold a shown slide, counted from 1. A section with no shown slide has no number, and the field shows nothing there. `section-name` is the section's name. Both are empty for a slide that isn't in a section. `footer` is the footer from the frontmatter. Without one, the field shows nothing. `date` is the presentation's `date` with a full year and a two-digit month and day. Their form is set by Unicode CLDR 48.2.0 for the presentation's `locale`. It uses the Gregorian calendar and Latin digits: 2026-03-04 in sv-SE and 03/04/2026 in en-US. When CLDR doesn't have a locale's language, the date is written as in en-US. Without a `date`, the field stays as written. A field's value is inserted as text. It's never read as Markdown or as a field. In code and in a link's address, `{{name}}` stays as written.

## <a id="presentation-mdpoint"></a>`presentation.mdpoint`

A key that names an object the slide doesn't have is skipped with a warning, and the rest of the slide plays. Such a key can be a parameter under `initial` or in a step, a cue, a constraint's target, a group's or a 3D object's parent, or a line's end. A line with such an end isn't drawn, and neither is one attached to an object a line can't attach to. A 3D object's parent that isn't a model or a light, or is the object itself, is skipped with a warning too. A constraint's target that its constraint doesn't take is skipped the same way. A skipped parent takes its `parent-node` and `parent-inverse` with it. The object then stands in the slide's space at its own values.

#### transition

A slide transition. `cross-dissolve` crossfades to the next slide. `carry-over` moves each object with the same id on both slides. `push` moves both slides along its direction, `move-in` brings the next slide in over this one, and `reveal` moves this one off the next. `scroll` makes both slides one strip the view travels across. This slide stays as it was left, and the next slide's first click plays with the move. `wipe` uncovers the next slide behind a traveling edge. `zoom` grows the next slide in from the middle. `fade-through-color` fades this slide out to the color and the next one in from it. The defaults are interpolation ease-in-out, match object, direction left, color #000000, and delay 0.

Where: `transition`, `slides.<id>.transition`

| key | required | values | description |
| --- | --- | --- | --- |
| `type` | yes | none, cross-dissolve, carry-over, push, scroll, move-in, reveal, wipe, zoom, fade-through-color | Which transition plays, or none. |
| `color` |  |  | The color of a fade through color: a color role, or a hex color written #RGB or #RRGGBB. A role takes its color from the scheme of the slide it leaves, and its alpha is ignored. |
| `delay` |  | 0 to 4294967296 seconds | How long a transition that starts by itself waits after the slide's last step ends. It goes only beside `start: automatically`. Keynote's Delay works the same way. |
| `direction` |  | left, right, up, down | Which way a push, scroll, move in, reveal, or wipe travels across the screen. |
| `duration` | unless the type is none | more than 0 and at most 4294967296 seconds | How long it takes. It's left out when the type is `none`. |
| `interpolation` |  | linear, ease-in, ease-out, ease-in-out | How the transition speeds up and slows down. Only `carry-over` and `scroll` have it. |
| `match` |  | object, word, character | What `carry-over` matches between two texts: objects, words, or characters. Keynote's Magic Move matches them the same way. |
| `start` | with delay | on-click, automatically | When it starts: on a click, or by itself after the slide's last step. The default is `on-click`. Keynote's Start Transition Automatically works the same way. |

**Types.** With `cross-dissolve`, the next slide fades in over this one. With `carry-over`, an object with the same id and type on both slides moves to its place on the next slide when both show it. A duplicated slide keeps its objects' ids. When `match` is `object`, a text also needs the same words as shown before `case` changes them, markup aside. A `word` or `character` match morphs a text whose words changed. A text on a path or with a 3D model on either slide isn't morphed. It travels whole. A 3D object also needs the same parent and rotation mode on both slides. Everything else cross-dissolves. With `push`, the next slide pushes this one off. With `move-in`, the next slide moves in over this one. With `reveal`, this slide moves off and shows the next one. Which way they travel is set by `direction`. With `wipe`, an edge uncovers the next slide. With `zoom`, the next slide grows from the center. With `fade-through-color`, the slides fade through `color`.

**Scroll.** A scroll moves both slides along one strip. Each slide's 3D objects stay at their place in its stacking order and are clipped at its edge. A model or 3D text with the same id on both slides crosses between them whole.

**When the delays start.** `click-delay` and `slide-delay` start once the transition into the slide and every step of the click before them have reached their end. They start no earlier than when each video or audio object those steps started has played one pass while shown. One hidden for the rest of that click before then doesn't hold them.

**When a slide moves on.** A video or audio object with `start-on: slide` that starts as the slide appears holds only the slide's leaving. When it still shows after the last step, `slide-delay` starts no earlier than one pass of it after the slide appeared. Time it spent hidden isn't added. One that a click first shows starts then and counts as that click's. A slide that played a step and leaves by a scroll doesn't add `slide-delay`. A transition that starts by itself uses its own `delay` instead. That delay starts once the transition into the slide and the last click have reached their end. It doesn't wait for video or audio.

Like a group, an instance fades and blurs as one picture and fades each branch on its own where a group would. A mask at the composition's root isn't painted and clips nothing. ### <a id="objects"></a>Objects

#### object

One object on a slide, a composition, a layout, or a master. Its keys depend on its type. A chart type or a shape kind in parentheses, as in chart (counter) or shape (star), is the one that uses the key. Every chart or shape can hold it, and another kind ignores it. Light types in parentheses, as in light (spot, point), are the only ones that take the key. An override needs none of the required keys. The object it changes already has them. In an override, a key set to null removes what the object inherits for that key. The key's default then shows.

**Copies.** An object's animation is the curves, cues, and initial values that name its id. A copy of another object has none of the other's animation until it is written under the copy's own id.

**The animated column.** `yes` means a step's keyframes move the key through the values in between. `discrete` means the key changes at once at its keyframe. The interpolation doesn't change this. A list names the parts of the key that a step animates. An instance and a group key `scale` whole.

**Overrides.** A null that would leave a required key missing is ignored. When an override gives an inherited image or video a `file`, the object becomes an image or a video. Which one depends on the file's type. A `null` file leaves an empty image, even on a video. Inherited keys that only the old type has are dropped. An override's key that the object doesn't have, such as `cone-angle` on a light that is directional on its layout, is ignored with a warning. A value that only another type can have is ignored with a warning too. A value that isn't valid with what the object inherits is ignored the same way. When an override makes a text box grow along a side, the length it inherits there is dropped. Each stays in the file and applies once the object can have it. A key or a value that no object can have, such as a misspelled key, is an error. In a 1.0 file, `type`, `composition`, or `bindings` in an override is an error too. A later minor version may let an override take them. On an object that isn't an override, a value that isn't valid is an error. In an override, `frame`, `position`, `rotation`, `scale`, `point-of-interest`, `tilt`, `size`, `anchor-point`, and `tail` change only the parts given. But `rotation` changes only the parts given when both it and the inherited rotation are in degrees. Otherwise it replaces the inherited one whole. An axis that a rotation in degrees leaves out is then 0. A part that an override leaves out of `anchor-point` is that part of the anchor the object would have without it. That anchor follows the override's other keys too, such as `auto-size`. Any other record or list replaces the inherited one whole. A part of a record set to null is an error. A web video's `poster` without its `url` is ignored with a warning. A `null` for the camera or the World is ignored with a warning too. An object on a master or a layout can't be a composition instance or have bindings. Its text can't have a 3D text `model`. It can't have `prompt`, `image-style`, `transparent-background`, `restyle`, or `generation` either.

**Keys an object draws without.** A video without a `file` shows an empty picture, a shape without a `shape-type` is a rectangle, and an icon without an `icon` shows no glyph. Each reads with a `missing-key` warning unless a binding names the key. A table or a chart whose words the .md file doesn't hold, its marker missing or empty, has a new table's words instead: 3 columns and 3 rows of empty cells, counting its header row. It reads with a `missing-text-block` warning.

**Bindings.** A binding names a number part of a record as a curve does: one the animated column lists, such as `tilt.x`. A part of a record with no default, such as `repeater.rotation`, binds only where the object has that record. The control must be of a type that can set what it binds. A number control sets a number key or a number part of a record. No control binds an object's `frame`, `rotation`, or `scale`, or a line's `start` or `end`. Such a binding is ignored with a warning. A color control sets a key whose value is a color. A boolean control sets a key that is true or false and is animated as discrete, or a table's `header-row` or `header-column`. A choice control sets a key that takes each of its options' ids and is animated as discrete. A media control sets `file`. `text` binds the object's words in the .md file. A text control sets a text's, a shape's, a table's, or a chart's words. A number control can set a text's or a shape's words too. A number control's value becomes words the way ECMAScript writes the number. A key that a binding sets has no value or keyframes of its own. A binding to a control that can't set it, or that the composition doesn't have, sets nothing. The key then has its own value and keyframes. For `text`, these are its own words in the .md file. A bound part still has its value in its record. A table or a chart takes bound words only where they're one table within the cell budget. It never shows the first rows of more. It shows an instance's words where they're such a table, else the control's default. Where the default isn't such a table, the binding reads with an `invalid-binding` warning and sets nothing.

**Control values.** Where `control-values` holds a value its control or a key it sets doesn't take, it reads with an `invalid-control-value` warning. A number past the control's range is taken at the nearer end of the range. A value of another kind than the control's, or a choice that isn't one of its options, is taken as the control's default. Each key the control sets then takes what it's given where it can. A key that can't, such as a star's `point-count` at 5.5, draws as if the instance gave no value. Where the control's default can't be taken, the binding reads with an `invalid-binding` warning. It then sets nothing. A media control's path is taken as written. Where it's empty or names a file of a type the control's objects don't show, they show no file. A value for a control the composition doesn't have reads with an `unknown-control` warning and changes nothing. A value that isn't a number, true or false, or a string, such as `null`, is an error. A file outside media/ and generated/ is an error too. A path not in NFC or with a name over 255 bytes in UTF-8 is an error as well. An instance's words for a text control are under its `<!-- text: <instance id>.<control id> -->` block in the .md file. Where a table or a chart they set can't take them, they read with an `invalid-control-value` warning at that block, and it shows what **Bindings** says. Where the block is, any value for the control in `control-values` is an error. Where it isn't, words there are an error, and a number, true, or false there is a value of another kind.

**Groups.** Groups nest at most 200 deep. The outermost group is the first level. A group's box is what its members draw at rest, in the group's rotation: each member's frame after its own rotation and scale, a line's drawn path, and every copy a repeater inside the group makes. A member whose `visible` is false counts, unless it is inside a group with an auto layout. A member that ignores the group's auto layout doesn't count. A group's rotation is the angle at which its box is measured. It doesn't turn the members. Their own positions and rotations don't change. To move a group, add the same offset to the frame and free ends of each object under it, however deep. In a group with `auto-layout`, the group's frame takes the offset in place of the members its layout places. A member with `ignore-auto-layout` still takes it. When a keyframe animates the group's rotation, the members turn by the difference between the keyframe's value and the group's rotation. A group's members paint in order right after the group. Where `objects` lists a member apart from its group, it still paints right after the group, among its members in the order listed, and causes a warning. With blend-mode `normal`, they blend only with each other. A group's default is `pass-through`. With it, the members blend with what is beneath the group. In Figma and Photoshop, this is Pass Through. The members' blending stays inside the group when the group has a blur or a `tilt`. When the group is placed in depth in a tilted group, their blending stays inside the tilted group. The group's wipe masks each member alike, and they still blend with what is beneath it. A group fades as one picture. Where a member's blend mode reaches past the group, or the group is placed in depth in a tilted group, the group's opacity fades each branch on its own. A branch is a member, or a member group that fades as one picture. A member of a tilted group whose `z` isn't 0 or is animated is placed in depth. The groups between it and the tilted group, and the groups inside it, are placed in depth too. A group's `z` moves its members with it. A tilted group inside another tilted group is placed in depth too. A tilted group's members stack by their depth in front of its plane, nearest in front. Members at the same depth keep their order in `objects`.

**Broken groups.** A parent that isn't a group, or is the object itself, is dropped, and the object stands at the root. A text with a `model` loses its parent the same way. A group nested more than 200 deep stands at the root with its members. The levels under it count from it again. When parents make a loop, every link in it is dropped. The order of the objects doesn't matter. What hangs off the loop keeps its parent. Each of these causes a warning.

**An image's color.** An image's `color` draws only on an SVG image. On an image whose file isn't an SVG, it is kept, isn't drawn, and causes the warning `color-needs-svg`.

**Masks.** A mask is a path or a shape without text whose `use-as-mask` is true. A mask isn't painted. It clips the members after it in its group to its outline. That includes the members of groups among them. A later mask in the group starts a new range. A hidden mask clips nothing, but it still ends the range before it. A path's mask uses its `fill-rule`. A mask at the slide's root or at a composition's root isn't painted and clips nothing. Its `use-as-mask` causes a warning. A shape with text can't be a mask. It is painted, and its `use-as-mask` is ignored with a warning.

**Outlines.** A line's and a path's `stroke` is centered on their line.

**Words on a path.** A text with a `text-path` sets its words on one line: its paragraphs, headings, and list items in reading order, one space apart. A line break is a space. Code blocks, rules, and list markers aren't shown. A heading has the text's size and weight. `line-height`, `paragraph-spacing`, `list-indent`, `bullet-styles`, `vertical-align`, `padding-top`, `padding-bottom`, `column-count`, `column-gutter`, `min-height`, and `auto-size` don't apply. They stay in the file and apply again once the text has no path. A text whose `auto-size` grows a side still can't animate its size or its text's layout on a path. `left` holds the text's start at the path's start, `center` its middle at the path's middle, and `right` its end at the path's end. Justified text and text with no `align` are held on their start side. Only the path's first contour carries the words. Any later one is ignored. A closed contour carries them round past its start. On an open one, a letter whose middle falls past either end isn't shown at rest. Only the letters shown at rest enter and exit. In flight they run on past either end in the path's direction there.

**A table's words.** A table takes every key of its text style but `bullet-styles`, `list-indent`, `paragraph-spacing`, `padding-top`, and `padding-bottom`.

**A shape's words.** On a shape with a fill, the default `color` is `text` where `text` has a higher WCAG contrast ratio than `background` against the fill at the text's first line. Otherwise it is `background`. A fill that isn't opaque is measured over `background`. That default is used instead of the text style's color.

**Capitalize.** With `capitalize`, a word that starts with a letter starts with that letter's capital. The rest of the word stays as typed. A letter starts a word unless a letter, a decimal digit, or a connector such as `_` comes right before it, past any combining mark. A letter number such as Ⅳ counts as a letter. A character of Unicode's MidLetter, MidNumLet, or Single_Quote word-break classes joins the letters on either side into one word. Those are characters such as a period, a colon, and an apostrophe. For example, "node.js", "don't", and "3d" are each one word, and "(hello)" shows as "(Hello)". In Turkish and Azeri, the capital of i is İ. In Dutch, a word's first ij is IJ. A letter whose capital has more than one character, such as ß, stays as typed. A letter of Georgian's Mkhedruli alphabet stays as typed too.

**Upper and lower case.** With `upper` or `lower`, a letter takes the case Unicode's full case mapping gives it in the presentation's `locale`. So a Greek capital drops its accent. An ι or υ after it that the accent kept apart then takes a diaeresis: "μάιος" shows as "ΜΑΪΟΣ". The capital of ß is SS. In Turkish and Azeri, the capital of i is İ and the small letter of I is ı. In capitals, a letter of Georgian's Mkhedruli alphabet stays as it is, and a Mtavruli letter shows as its Mkhedruli letter.

**Lines.** Where a curved line has no `bend`, it is −|dx × dy| ÷ (4 × (dx² + dy²)), or 0 where its ends meet. dx and dy are how far its end is from its start. So a line whose ends are level or plumb is straight. One on a diagonal bends most: by −1/8. A line that isn't curved still has its bend. The bend shows once the line is curved. A curved line is the quadratic Bézier curve through its bent middle. An elbow line starts along the axis on which its ends are farther apart, or across when they're as far apart on both.

**Charts.** Each `delivery` names its own way of growing. A chart's `by-element` grows its elements in the table's order within the chart's own `progress`, as a text's entrance moves its pieces: each starts one interval after the one before and grows for `spread` intervals. In a line or stacked-area chart, an element is a series. In any other chart, it is a category. A text's `by-paragraph` plays each paragraph on a cue of its own instead. A click for each element is a `progress` keyframe for each. No chart draws a value axis: a value shows as a number only in its value label. A value label is spelled as its cell spells its number. A counter draws no legend and no value labels, and it doesn't use `delivery` or `spread`. A key that a chart's type doesn't use does nothing. A counter's figure is its value times `progress`. Unless `digits` is `roll`, it keeps the cell's spelling and its number of decimal places, rounded the way ECMAScript's `toFixed` rounds it. With `roll`, the last wheel turns with every fraction of a count. Each wheel to its left turns to its next digit while the wheels after it pass from 9 to 0. A cell that holds no number shows its words at every count. A chart's `align` sets only a counter's figure. A pie or a donut uses its `category-colors`, and any other chart but a counter its `series-colors`. Each list keeps its colors when the chart's type changes. Where an entry of the list a chart uses is `null`, or the list ends before it, the chart uses the slide's `accent` and `text` colors in turn: `accent` at the first entry, `text` at the second, `accent` again at the third, and so on. Where `text` is the same color as `accent`, and `muted` isn't, `muted` takes the place of `text`. Each round after the first is drawn at a lower opacity: half, then a third, then a quarter, and so on. Each opacity is rounded to a whole percent.

**Web videos.** A web video's `url` is the https address of a YouTube or Vimeo video. It has no user name or password, and no port other than 443. YouTube addresses are youtube.com/watch?v=id, youtube.com/embed/id, youtube.com/shorts/id, youtube.com/live/id, youtu.be/id, and youtube-nocookie.com/embed/id. The id is 11 letters, digits, underscores, or hyphens. A youtube.com address can start with www. or m., and a youtu.be or youtube-nocookie.com address with www. Vimeo addresses are vimeo.com/, www.vimeo.com/, or player.vimeo.com/video/, followed by the video's number. The number has no leading zero. An unlisted video's hash is letters and digits. It comes after the number or as h. When an address has both, they are the same. A start time is whole seconds, or hours, minutes, and seconds such as 1m2s. YouTube uses t or start. Vimeo uses t in the query or among the parameters after #. A share link's #t=1m2s&share=copy starts the video at 1m2s. When an address has two start times, they are the same. Each of v, h, t, and start appears at most once in the query, and t at most once after #. A save writes the address in one of three forms and drops every other parameter: `https://www.youtube.com/watch?v=<id>&t=<seconds>`, `https://www.youtube-nocookie.com/embed/<id>?start=<seconds>`, and `https://vimeo.com/<number>/<hash>#t=<seconds>s`. The start is left out when it is 0, and the hash when the video has none.

**The 3D layer.** A slide's models, shadow catchers, floors, and texts with a 3D `model` are drawn together as one image: the slide's 3D layer. The layer is placed where the backmost of them is in the slide's stacking order. A hidden one counts too. Lights and the camera draw nothing in it, and they can be anywhere in the order. The layer is lit in linear light, tone-mapped with Khronos PBR Neutral at an exposure of 1, and written in sRGB. sRGB is the color space of the slide's flat colors. Before tone mapping, a directional light of intensity 1 lights a white surface that faces it to white. A point, spot, or area light falls off with the square of the distance in meters. A camera's lens is measured on a 36 mm sensor across the slide's longer side. It is the same as Blender's Sensor Fit Auto. The distance at which the slide shows at full size is at least 1 canvas unit. It sets the field of view, a camera's default z, and a tilted group's perspective. The camera sees the 3D layer and every tilted group from where it stands and looks. No other flat object is seen through it. The 3D layer draws nothing nearer to the camera than 1 canvas unit. A World with no color lights the layer at the World's intensity with `environments/studio.hdr`. That file is an equirectangular Radiance HDR file whose SHA-256 is ce14a3984f83a8d231cad84cddc9ede84c73743d6d7956daf209f62e1afd1282.

**Model files.** A model's file is binary glTF 2.0, or a later 2.x, that contains everything it uses. Its one buffer is its BIN chunk. Each texture's image is a PNG, a JPEG, or a WebP, in that chunk or in a data: URI. It can use EXT_texture_webp, KHR_materials_anisotropy, KHR_materials_clearcoat, KHR_materials_dispersion, KHR_materials_emissive_strength, KHR_materials_ior, KHR_materials_iridescence, KHR_materials_sheen, KHR_materials_specular, KHR_materials_transmission, KHR_materials_unlit, KHR_materials_volume, KHR_mesh_quantization, KHR_texture_transform, and KHR_xmp_json_ld. A file that requires any other extension is refused. A file that uses KHR_draco_mesh_compression, EXT_meshopt_compression, KHR_meshopt_compression, KHR_texture_basisu, or EXT_mesh_gpu_instancing is refused too. Any other extension it uses is ignored. A model's own lights are ignored too. A skinned vertex moves with at most four joints. Its joints and their weights are in its `JOINTS_0` and `WEIGHTS_0`. No other set is read. A model's node trees are at most 256 nodes deep. A mesh counts once for each node that draws it. A model then has at most 65,536 primitives, 65,536 skin joint copies, and 1,048,576 morph weights. Each target and each rest weight is a morph weight. Its buffer views together fit in its BIN chunk. Views that share bytes each count in full. Its accessors' values together fit there too. Each accessor counts once: its count times the bytes of its components. A sparse accessor's values count in full. Each primitive of the model's meshes is counted once. The morph targets then use at most 256 MiB: 16 bytes for each vertex and target, 32 with normals, and 48 with colors. An animation's keys are laid out as glTF lays them out. Their times are floats. Their values are floats, or normalized 8-bit or 16-bit integers for a rotation or morph weights. Normalized values are written in full, not as a sparse accessor. No buffer view that holds keys has a stride. Normalized keys are counted once for each channel that names them. They then use at most 256 MiB: 4 bytes for each number. Each image is counted once for each sampler. The textures then decode to at most 268,435,456 pixels.

**Materials and nodes.** A material named `color:` followed by a color role, such as `color:accent`, uses that role's color in the slide's scheme as its base color factor. The role's alpha is ignored. The material keeps its own alpha and its base color texture. If the scheme doesn't have the role, the material uses the file's color. A number Blender adds to a copied material's name, such as `.001`, is ignored. A node whose `extras.markdownpoint` has `"cast-shadow": false` casts no shadows. Nothing under it casts shadows either. An animation whose `extras.markdownpoint` has `"loop": "repeat"` is an Action made to repeat. A clip of it repeats by its own `loop` or `stride`, never by the Action's. Every node of the file has a name, a skin's joints included. A name follows the rule the cue record gives for a clip's Action. An unnamed node is named Node and its number in the file, as in `Node 1` for the first. A key that names a node, such as `parent-node`, finds it only in the scene MarkdownPoint draws. That is the file's default scene, or its first scene when it names none. A `parent-node`, a `target-node`, or an Aim's `node` that names no node there causes a warning. An object whose `parent-node` names none moves with the whole model. A camera whose `target-node` names none follows the target's origin. An Aim whose `node` names none turns nothing.

**Meshy's tasks.** A model made with Meshy names the tasks that made it in `asset.extras.markdownpoint.meshy` beside its glTF `version`. `model` is the id of the task that made the model. `model-expires` is when Meshy deletes that task. `rig` is the id of the task that rigged the model. `rig-expires` is when Meshy deletes that one. Each id is Meshy's own string. Each time is a UTC timestamp to the millisecond, such as 2026-10-16T09:30:00.000Z. Any of the four can be left out. While its `model` task lasts, a model is rigged from that task and its file isn't sent. While its `rig` task lasts, a rigged model takes more Actions from it.

**Path data.** The path data of a path, a text path, a mask, or a motion path has at most 2,097,152 characters and 8,192 points. A point is where a contour starts or a segment ends. Each line and curve has one. A move has one too. A move has none when another move follows it at once, or when it ends a path that has other points. An arc has one for each of the fewest pieces of at most a quarter turn that it divides into. An arc that ends where it starts has none. An arc is read as one cubic Bézier curve for each of those pieces, and the pieces turn equally. On a circle, a piece that turns θ has handles 4 ÷ 3 × tan(θ ÷ 4) of the radius long. An ellipse's pieces are a unit circle's, scaled by its two radii and turned by its rotation. Each point and handle, once made absolute, is a finite number. When a contour of more than two points closes, the points at its end that lie on its start aren't counted. A point a closing curve leaves from is counted, and two points always stay. The close draws that segment.

### <a id="placement"></a>Placement

#### frame

An object's position and size in canvas units from the top left of its slide or composition. A table's, an audio object's, and a group's frame has only x and y: their contents, an icon, or members give them their size. A text box's frame leaves out each side that grows to fit its text. An audio object's frame is the top left of its icon. The icon shows only while editing. It has the same size at any zoom. A group has a frame only with `auto-layout`. Its frame is the position of the auto layout's run: the box its members' frames make, unturned and unscaled, placed one after another. The `reference-point` of the group's auto layout says which point of the run that is: the top left in the group's rotation, or the center or end along the layout's direction.

Where: `objects[].frame`

| key | required | values | description |
| --- | --- | --- | --- |
| `x` | yes | −65536 to 65536 canvas units | How far across the left edge is. When a text box's width grows, it is the point the text is aligned to. For a group, it is the point its auto layout's `reference-point` names. |
| `y` | yes | −65536 to 65536 canvas units | How far down the top edge is. When a text box's height grows, its default `anchor-point` is on its top edge. For a group, it is the point its auto layout's `reference-point` names. |
| `width` | except a table's, an audio object's, a group's, or a text box's whose width grows to fit text in one column that follows no path | more than 0 and at most 65536 canvas units | The width. |
| `height` | except a table's, an audio object's, a group's, or a text box's whose height grows to fit text that follows no path | more than 0 and at most 65536 canvas units | The height. |

**A growing text box.** When a text box's width grows with `auto-size`, its frame has no width. A text that follows a path or has more than one column still has one. When its height grows with `auto-size`, its frame has no height. A text that follows a path still has one. A box set to grow can't animate its size or its text's layout, even with a path or more than one column. The center of its frame is the point the text grows from. Without an `anchor-point`, the box turns and scales about that point. With one, the box grows from that point. Then it turns and scales about its anchor. So a turned or scaled box moves as its text grows. When the width grows, a box set left is drawn to the right of the point, a centered box around it, and a box set right to its left. Justified text, and text with no `align`, is drawn as if it were set on its start side. When the height grows, the box is drawn down from the point. Where the box is drawn around that point depends on `auto-size`, `align`, `text-direction`, `column-count`, `text-path`, `rotation`, `scale`, and `anchor-point`. An override can change one of them, or make the box grow or stop growing. An x or y it leaves out is then the one that puts its box in the inherited box's place. To find it, the inherited box is drawn at a length along each side it grows along: the length of the override's box where that box doesn't grow along the side, and no length where it does. That frame's x and y are then read with the override's keys. So where both boxes grow along a side, the override's box grows from the point the inherited box grows from. An x or y the override gives is its own.

**Flip, scale, and rotation.** A flat object is drawn in its frame and mirrored inside it by `flip`. A picture is mirrored after its file's orientation and its `crop`. Then it is scaled along its own axes and turned by its `rotation`. It scales and turns about its anchor point.

#### point

A point. Its unit depends on where it is. The x and y of a line's start or end are in canvas units from the top left of its slide or composition. Each is from −33,554,431.984375 to 33,554,431.984375. An end that met its object past that range is written at the nearest point in it. Each axis is kept to the range on its own. The x and y of a comment's position are in canvas units. Each is from −65,536 to 65,536. A text's drop shadow offset is in ems of the text's font size. It is from −33,554,431 to 33,554,431 on each axis. Any other drop shadow offset is in canvas units. It is from −33,554,431.984375 to 33,554,431.984375 on each axis.

| `y` | yes |  | How far down. |

#### tilt

**Depth.** A member of a tilted group whose `z` isn't 0 or is animated is placed in depth. The groups between it and the tilted group, and the groups inside it, are placed in depth too. A group's `z` moves its members with it. A tilted group inside another tilted group is placed in depth too. A tilted group's members stack by their depth in front of its plane, nearest in front. Members at the same depth keep their order in `objects`.

**3D.** A tilted group can share a slide with a model or a text with a 3D `model`. Each is drawn as it would be alone. The group isn't placed in depth among the 3D layer's objects. It is drawn at its place in the slide's stacking order.

#### auto-layout

How a group places its members one after another. The defaults are direction vertical, gap 0, align start, and reference-point start. Members are placed in their order in the `objects` list. Members whose `visible` is false, members with `ignore-auto-layout`, and lines attached to an object are skipped. A mask takes a slot like any other member. A step or an initial value that hides or shows a member doesn't move the others. The run goes down or across in the group's rotation, and no member turns with it. A member's repeater copies take no room in it. Any other line takes the box of its two ends, and a member group the box its own members take.

**Timing.** A step that animates a repeated object lasts at least until that object's last staggered keyframe plus (copies − 1) × `stagger` + `stagger-randomness`. That is the latest a copy's animation can end. Each copy's own wait is drawn from the seed. So the last copy can end before the step does. A repeated group adds this time for its own repeater to its members'. Keyframes of the object's own `repeater` aren't staggered: they lay out all its copies at once. Only the repeated groups the object is in add their time to them.

**What repeats.** A turned object's copies are placed along its own axes. Their position, anchor point, and position randomness turn with its rotation. A group can repeat only when each of its members can repeat or is a line with no end attached to an object outside the group. A shape with text, or a group that can't repeat, keeps its `repeater` and makes no copies. The repeater is ignored with a warning.

**Copies not drawn.** A copy isn't drawn when its size or corners would pass 33,554,431.984375 canvas units, or when its shorter side would be less than a millionth of a canvas unit. Each copy is judged on its own at the size it plays at.

**How many.** A slide's repeated objects, instances, and charts make at most 512 objects beyond the slide's own. Each copy but the original counts as one object. The objects it contains count too. A shape with text and a group that can't repeat count nothing. An instance counts its composition's objects and one more for the group that contains them. A chart a repeater or an instance copies counts the parts it would draw if every cell had a number. A slide's own chart counts nothing: the limit on a table's cells bounds it. They are counted from back to front. One that would pass the limit makes nothing and causes a warning. Later ones that fit still make their objects.

### <a id="text"></a>Text enter and exit

#### enter

Text that enters piece by piece. `based-on` sets whether a piece is a paragraph, a word, or a character. The defaults are interpolation linear, fade 1, order forward, spread 1, pause 0, and progress 1. With delivery `by-paragraph`, it works as PowerPoint's By Paragraph.

Where: `objects[].enter`

| key | required | values | description |
| --- | --- | --- | --- |
| `based-on` | yes | paragraph, word, character, character-and-space | What counts as one piece. With `character-and-space`, each space is a piece too. After Effects' Characters is `character-and-space`, and its Characters Excluding Spaces is `character`. |
| `delivery` | with duration | by-paragraph | `by-paragraph`: each paragraph enters on the step whose paragraph cue names it. It needs based-on `paragraph` and no seed. Order, spread, pause, and progress must be at their defaults. |
| `duration` | with delivery | more than 0 and at most 4294967296 seconds | How long each paragraph takes to enter in seconds. With interpolation hold, it is still required but isn't used. A step that has only paragraphs' cues lasts as long as they take. |
| `fade` |  | more than 0 and at most 1 | The fraction of each piece's entrance its fade lasts. The fade starts with the move and follows the piece's interpolation. |
| `from` |  |  | How each piece looks as it starts to enter: opacity, offset, scale, rotation, and blur. |
| `interpolation` |  | linear, ease-in, ease-out, ease-in-out, smooth, hold, anticipate, overshoot, anticipate-overshoot, bounce, elastic, or a record | How each piece moves into place: gradually, or at once with hold. A text's spring has no `response`, and its elastic has no `period`. |
| `order` | with seed | forward, backward, center-to-ends, ends-to-center, random | The order the pieces enter in. With a seed, it must be `random`. |
| `pause` |  | 0 or more intervals | How many intervals the text waits between turns. `enter` says how they count. |
| `progress` |  | 0 to 1 | How far the text has entered. It is animated by steps. It isn't animated when the entrance has a `delivery`. |
| `seed` |  | whole numbers, 0 to 4294967294 | The seed for a random order: the same seed gives the same order. The default is 0. |
| `spread` |  | 1 or more intervals | How many intervals each piece moves for. In forward, backward, or random order, this many pieces move at once. |

**Pieces.** With `based-on: paragraph`, a piece is a paragraph, a heading, or a top-level list item with its marker and the items nested under it. A cue can still name a nested item by its id. Words are split at the word boundaries of ICU 78.2 for the presentation's `locale`: Unicode 17.0.0's rules, CLDR 48.0's tailorings for the locale, and ICU's dictionaries for scripts written without spaces. A word includes anything that touches it and isn't part of a word, such as punctuation or a symbol. What touches two words goes with the earlier word. A run of punctuation or symbols that touches no word is a piece of its own. So “Hello, world! (yes) e-mail” is five pieces. A character is one grapheme cluster. Characters are counted as shown, before `case` changes them. A field counts as its words. A mark or link inside a word doesn't split it. A space counts as a piece only with `character-and-space`, and a line break never does. Outside a piece, a quote's rule, a code block, a rule, and a block of kept Markdown are shown from the start. By word or by character, a list's markers are shown from the start too. Kept Markdown inside a paragraph is part of its words. An empty list item is a paragraph. With delivery `by-paragraph`, a paragraph that no cue shows is shown from the start. A text with a `text-path` shows all its paragraphs together on one line: its paragraph cues show nothing more, and with delivery `by-paragraph` it enters all at once. In a 1.0 file, a `delivery` beside another `based-on` is an error. A later minor version may add the pair. In a file of that version, MarkdownPoint passes over the whole `enter` and keeps it as written.

**Looks.** An entrance's or exit's look moves and blurs each piece in ems of its own font size. A heading's piece uses the heading's size, a piece wholly in code uses code's, and any other uses its paragraph's. On a path, the look's x is along the path in its direction and its y is across it, toward the letters' feet.

**Turns.** Pieces start one interval apart in their order. Each piece moves for `spread` intervals. With interpolation hold, a piece takes no time: it arrives or leaves as it starts. At `progress` 0, none has. By word or by character, each paragraph and heading that has a piece gets a turn. The turns go in reading order, or in reverse with `backward`. Each turn plays the order on its own: from its own middle or with its own shuffle. With no pause, a turn starts one interval after the last piece of the turn before it starts. By paragraph, the order runs over the paragraphs, and paragraphs that start together share one turn. `pause` applies only between turns. For N pieces, `progress` runs evenly over N − 1 + `spread` intervals. With a `pause` above 0, it runs over `pause` + `spread` − 1 more intervals before each turn except the first. With `center-to-ends` or `ends-to-center`, two pieces that are equally far from the middle start together. When the order runs over n pieces, their starts are spread evenly over n − 1 intervals. With only two pieces, `center-to-ends` starts the first and `ends-to-center` the second. The other starts one interval later.

### <a id="3d"></a>3D

#### space-position

A point in the 3D space in canvas units. The x axis runs right from the slide's left edge, the y axis runs up from its bottom edge, and the z axis runs toward the viewer. The slide is at z 0. The axes are right-handed. glTF and three.js use the same axes. After Effects' y and z axes run the other way. A parented object's position is in its parent's space.

Where: `objects[].position` of a model, a light, the camera, or a shadow catcher, `objects[].point-of-interest`

| key | required | values | description |
| --- | --- | --- | --- |
| `x` | except the camera's position | −1 × 10¹⁸ to 1 × 10¹⁸ canvas units | How far across. |
| `y` | except the camera's position | −1 × 10¹⁸ to 1 × 10¹⁸ canvas units | How far up. |
| `z` | except the camera's position | −1 × 10¹⁸ to 1 × 10¹⁸ canvas units | How far toward the viewer. |

**Parented objects.** A parented model, light, shadow catcher, or camera has its position, rotation, scale, and point of interest in its parent's space, through its `parent-inverse` if it has one. A parented shadow catcher's width and height are in its parent's space too. A parent's `visible` and `opacity` don't reach what it carries. The object's world matrix is its parent's world matrix, times its parent-inverse, times its own position, rotation, and scale. When `parent-node` names a node of the parent, that node's world matrix is used in place of the parent's. A node's space is in canvas units, the same as its model's. It has the node's origin, axes, and scale. The node's distance from its model counts in canvas units. The `parent-inverse` is the inverse of the parent's world transform, or its parent node's in canvas units, times the object's earlier space's transform. Each matrix acts on a column of x, y, z, and 1 to its right: `world = parent × parent-inverse × local`. Blender composes a Parent Inverse the same way. The object's own constraints apply after that. A loop made of parents alone drops every link in it, and each object in it stands on its own. Then an Aim whose target waits on the model it turns closes a loop. That Aim turns nothing, and the parents in that loop stay. Both cause a warning. A parented camera's position comes from that world matrix and so moves with its parent's scale. Its view turns with the matrix but is never scaled or sheared. A camera with a point of interest also banks with its parent.

**The camera.** The camera's position can leave out any part. A part left out takes its default: x half the slide's width, y half its height, and z where the slide shows at full size. That z follows the focal length as it plays. A step that animates only the focal length keeps z 0 at full size. A parented camera's defaults are in its parent's space.

#### space-rotation

A 3D object's rotation about its origin, in its space's axes: its parent's for a parented object, otherwise x right, y up, and z toward the viewer. It is in degrees, or a quaternion in quaternion mode. An object's own rotation in degrees needs x, y, and z. In degrees, it turns in Cinema 4D's HPB order: by the heading about y, then by the pitch about its own x, then by the bank about its own z. In three.js, this is Euler order YXZ. A positive z turns it counterclockwise on the slide, a positive x tilts its top toward the viewer, and a positive y brings its left side forward. A quaternion is glTF's with w first. A Blender quaternion (w, x, y, z) exported to glTF with +Y up is (w, x, z, −y) here. A quaternion's parts are read to six decimal places, and its length doesn't change the rotation. Between two quaternion keyframes, the object turns the shorter way round.

**Degrees.** Each rotation turns counterclockwise as seen along its axis toward the origin. A flat object's `rotation` and a group's `tilt.x` turn the other way. The slide's y axis runs down. A step animates each axis's rotation on its own as `rotation.x`, `rotation.y`, or `rotation.z`. One keyframe can spin the object more than once. In its glTF file, a model faces +z. At zero rotation, it faces the viewer. At zero rotation, a light shines into the slide along its own −z, and the camera looks along its own −z. Both have their own y up.

**Quaternions.** A quaternion whose parts all read as 0 is refused. In quaternion mode, each keyframe of `<object>.rotation` is a whole quaternion. Between two keyframes, the object turns at the pace of the keyframe's interpolation. At exactly a half turn, it turns toward the keyframe's quaternion as written.

#### text-model

A text's 3D model. Its `type` is `extrusion` or `file`. With `extrusion`, MarkdownPoint builds the words' letters into a model. A text on a path can't have an extrusion. Its extrusion is left out as the file is read, and the warning `extrusion-with-text-path` says so. Its words draw flat. Each length is in ems of the text's size. The default depth is 0.2, and the default bevel is 0.02. With `file`, the model is a GLB that a program built, and `built-from` is the fingerprint of what it was built from: the words, the values of the fields they show, the presentation's `locale`, and the text's style and layout. Once any of them changes, the words draw flat until the model is built again. One unit of the model is one em of the text's size. Its origin is on the first line's baseline at the left of the text's column. For words on a path, its origin is the frame's top left. That is the path's 0 0, and the model's y points up from it. The model moves, turns, and scales with the text's frame. Its `z` sets how far it is in front of the slide. The text is never in a group or a composition. Its depth scales by the square root of the text's x scale times its y scale. A step's clips play the Actions of a GLB `file` the same way they play a model's. An extrusion has no Actions. Its letters are matte and lit only by the slide's lights and its World. With no light and the World's intensity at 0, its default, they draw black.

Where: `objects[].model` of a text

| key | required | values | description |
| --- | --- | --- | --- |
| `type` | yes | extrusion, file | Which model it is: `extrusion` for the words' letters built by MarkdownPoint, or `file` for a GLB a program built. |
| `bevel` |  | 0 to 58321570 ems | How far the letters' edges are rounded in ems. At 0, they are sharp. |
| `built-from` | with type file |  | The fingerprint of what the GLB was built from. The reference gives the rule. A reader that doesn't know the rule treats the model as out of sync. |
| `depth` |  | 0 to 58321570 ems | How far the letters are extruded in ems. The bevels on the front and the back add `bevel` each. The letters' fronts are then `depth` + 2 × `bevel` from the slide. |
| `file` | with type file |  | The path in the presentation's folder of the GLB a program built from the words. |

**Flat effects.** While a text's model draws, its `drop-shadow`, `text-stroke`, `text-stroke-weight`, and `blend-mode` don't apply. They stay in the file and apply again when the text draws flat.

**The model's letters.** A text's model has its letters under one node. That node is its scene's only root, and it draws no mesh of its own. Each child of that node is a letter. The child draws the letter itself or through the nodes under it. A letter's `extras.markdownpoint.characters` lists the characters it draws. Each is `[block, start, end]`. `block` is the block's index in reading order. The first block's index is 0. The blocks are the text's paragraphs and headings, its code blocks, and its kept Markdown. An empty paragraph or heading counts too. A paragraph in a list item or a quote is a block of its own. `start` and `end` are UTF-16 offsets in that block's text, and the letter draws the characters from `start` up to but not including `end`. That text is the block's words as shown, before `case` changes them. In it, the fields are filled in, and each hard break is one character. A letter's `extras.markdownpoint.box` is the box the letter is laid out in on the slide. It is `[left, bottom, right, top]` in the model's units. Y is up. The node with the letters lists the text's paragraphs in its `extras.markdownpoint.paragraphs`. Each is `[paragraph, left, bottom, right, top]`. `paragraph` is the paragraph's number in reading order among the text's paragraphs, headings, and list items. A nested list item has a number of its own. A list item's paragraphs count as one. An empty paragraph or heading has no number, and an empty list item has one. The first paragraph's number is 0. The four numbers after it are the box the paragraph is laid out in. A list item's box includes its nested list. A letter enters and exits with the pieces its first character is in. A letter with no `characters` stays where it is. A model laid out any other way enters and exits as one piece, about the center of its text's frame. In a model of the word Hi, the JSON has this, besides its meshes and the rest glTF needs:

```json
{
  "scene": 0,
  "scenes": [{"nodes":[0]}],
  "nodes": [
    {"children":[1,2],"extras":{"markdownpoint":{"paragraphs":[[0,0,-0.21,0.97,0.88]]}}},
    {"mesh":0,"extras":{"markdownpoint":{"characters":[[0,0,1]],"box":[0,-0.21,0.73,0.88]}}},
    {"mesh":1,"extras":{"markdownpoint":{"characters":[[0,1,2]],"box":[0.73,-0.21,0.97,0.88]}}}
  ]
}
```

**`built-from`.** A text model's `built-from` is `markdownpoint/text-model/`, its rule's number, `:sha256:`, and 64 lowercase hex digits. By rule 21, it is `markdownpoint/text-model/21:sha256:` followed by the SHA-256 of its text's record. The record is a JSON object written in UTF-8 according to RFC 8785's JSON Canonicalization Scheme. Its keys are sorted by their UTF-16 code units, and it has no spaces. Each number and string in it is written the way ECMAScript writes it. A negative zero is written 0. The record has only what the presentation's folder states. Each key and value except `content` and a font's family is spelled as a save writes it: a hex color as #RRGGBB in uppercase, or #RRGGBBAA where it isn't opaque; path data in absolute M, L, C, and Z commands; and the locale in its canonical form. A key with nothing in it is left out. An em is the text's size. Each length in ems is worked out in IEEE 754 double precision. ECMAScript's numbers are of this kind. A length in canvas units is first divided by the text's size. The length in ems is then multiplied by 1000, rounded to a whole number as ECMAScript's `Math.round` rounds it, and divided by 1000. `Math.round` rounds a half toward positive infinity.

- `content`: the text's words as the slide draws them. They're written in MarkdownPoint's standard spelling of Markdown. `mdpoint format` writes words this way too. A field stays as `{{name}}`. Each paragraph id is left out. A comment outside a block of HTML is left out too. Spaces beside a comment in a line stay. Markdown the slide shows as plain text, such as an image or an HTML tag in a line, is written as words of that text. A block of HTML stays as written. So a respelling of the words, a paragraph's new id, or a note on a line of its own leaves `content` as it was.
- `fields`: each field the words show that has a value. The key is the field's name, and the value is what MarkdownPoint fills in.
- `locale`: the presentation's `locale`, or en-US if the presentation has none.
- `style`: the text's `font-family`, `font-style`, `font-weight`, `color`, `align`, `text-direction`, `line-height`, `tracking`, `case`, `bullet-styles`, `paragraph-spacing`, `list-indent`, `column-count`, `column-gutter`, `number-spacing`, and `kerning`. They come from the text, its text style, and their defaults. `tracking`, `paragraph-spacing`, `list-indent`, and `column-gutter` are in ems. Here and in `marks`, a color role the scheme lacks is written as `text`. A text whose color is a gradient has its text style's color here, or `text` when the style sets none. A text whose `column-count` is 1 has no `column-gutter`.
- `marks`: each key the text style's `marks` sets, under its mark. Where the text's `font-weight` is heavier than bold's or a highlight's weight, that mark has the text's `font-weight` here, whether the style sets the mark or not.
- `width`: the frame's width in ems, unless the text's width grows to its words and the text isn't on a path.
- `text-path`, `path-offset`, and `height`: for words along a path, the path, its offset, and the frame's height in ems.
- `column-height`: where `column-count` is above 1, the frame's height less the text's `padding-top` and `padding-bottom`. When the text's height grows to its words, its `min-height` stands for the frame's height, and 0 when it has none. The key is left out unless the result is above 0. It is in ems.
- `ligatures`: false where the text's characters travel apart. Each is then shaped on its own. They travel apart when the text's entrance or exit is by `character` or `character-and-space`. A `carry-over` doesn't set them apart. It doesn't morph a text with a 3D model.
- `font-size`: the text's size in canvas units, when its words include a quote or a horizontal rule. A quote's inset and a rule's line have a fixed size in canvas units. The text's size doesn't change them.
- `fonts`: each font role the words use by its name. That includes code's role. Each has the `family` the theme names for it. A family MarkdownPoint ships, when the theme brings no faces of its own for it, is spelled as MarkdownPoint spells it: INTER is Inter. Any other family is spelled as the theme's `fonts` spells it, even where its `font-files` key spells it otherwise. Where the theme has its own faces for the family, it also has the SHA-256 of each of its `files` in lowercase hex. They are in the order `font-files` lists them. A file that isn't drawn, such as a missing or refused one, has an empty string.
- `optical-sizes`: each such role whose family has an optical-size axis by its name. It has one list for each of the family's axes. The axes are ordered by their least size, then by their greatest, and each is listed once. A list has each size the role's words are set at, once, from the smallest: the text's size, a heading's size, and code's size. Each size is worked out in double precision and limited to the axis's range. Then it is rounded to six decimal places the way ECMAScript's `Number(x.toFixed(6))` rounds it. So two sizes past the axis's end are both at that end. An embedded face's axis is its file's `opsz`. A family whose faces have several axes has a list for each. The bundled families' axes are Inter 14 to 32, Source Serif 4 8 to 60, and Fraunces 9 to 144.

For example, take the words "Ship **it**." at 72 canvas units and weight 700 in a frame 900 wide. The theme's display role is Inter. Their record is `{"content":"Ship **it**.","fonts":{"display":{"family":"Inter"}},"locale":"en-US","marks":{"highlight":{"font-weight":700}},"optical-sizes":{"display":[[32]]},"style":{"align":"left","bullet-styles":["disc","circle","square"],"case":"none","color":"text","column-count":1,"font-family":"display","font-style":"normal","font-weight":700,"kerning":"metrics","line-height":1.05,"list-indent":1.25,"number-spacing":"default","paragraph-spacing":0.5,"text-direction":"ltr","tracking":0},"width":12.5}`. Their built-from is `markdownpoint/text-model/21:sha256:10b8107c5d71d3dc8dbeb14647d4b8dcb2e4ad5497366b047d8a267dcd8a9695`.

Rounded this way, a `tracking` of −0.0625 is −0.062 in the record. With a text size of 72 canvas units, a frame 72.036 wide is 1.001 ems wide. A frame 900.036 wide is 12.5 ems wide. In double precision, 900.036 ÷ 72 is just under 12.5005. It rounds down.

### <a id="steps"></a>Steps and keyframes

#### step

One step: the keyframes and cues that a click or the previous step sets off. Its times and the times of its keyframes and cues are in seconds. They are rounded to six decimal places. Its `with-previous` and `after-previous` start work as PowerPoint's With Previous and After Previous. On the first step, either starts it as the slide's transition ends. A Scroll into the slide plays its first click with the move, whatever its start. A cue that starts a sound, a video, or a clip counts at its own time alone. The step doesn't wait for what it starts to play through. The Animate tab's Add Action gives a clip's step the Action's length as its `min-duration`.

Where: `slides.<id>.steps[]`, `compositions.<id>.steps[]`

| key | required | values | description |
| --- | --- | --- | --- |
| `id` | yes |  | The step's id, unique on its slide or composition. |
| `cues` |  |  | Events at set times in the step by id. They are read by their time, then by their id. Each shows a paragraph, starts an audio object, a video, or a web video, or plays a clip. |
| `curves` |  |  | The step's animation. Each curve is under an "object.parameter" key such as card.opacity. |
| `loop` | with loop-start | repeat | With `repeat`, the step loops from `loop-start` to its end while it waits for a click. Without it, the step plays once. |
| `loop-start` |  | 0 to 4294967296 seconds | The seconds into the step where `loop` starts. Without it, the loop starts at 0. At or past the later of its `min-duration` and its last keyframe or cue, it causes a warning and doesn't loop. |
| `min-duration` |  | 0 to 4294967296 seconds | The least time the step lasts in seconds. A later keyframe, cue, entering paragraph, or repeated copy makes it longer. Without it, or at 0, the step lasts as long as what is in it. |
| `name` |  |  | The step's name: one line that isn't blank and has no control characters or line breaks. |
| `repeat-count` |  | whole numbers, 2 to 9.007199254740991 × 10¹⁵ | How many times the step plays before it completes. Without it, the step plays once. The step plays only as many times as fit in 4,294,967,296 seconds. A larger count causes a warning. |
| `start` |  | on-click, with-previous, after-previous | When the step starts. `on-click` starts it on a click of its own and is the default. `with-previous` starts it with the previous step. `after-previous` starts it after that step ends. |

**Clicks.** A step has no delay of its own. A keyframe's move begins at its `begin`. When two steps of one click animate one parameter, the earlier step's motion shows until the later step's first move begins. That move starts from where the earlier motion is then. A first keyframe at the value the parameter has as its step starts doesn't move until its time. The move of one with `interrupted` or a `motion-path` begins as its step starts. A move that ends where it starts has no motion path. The object stays where it is. A `begin` at or before the previous keyframe, or on a key or keyframe that doesn't move, is [ignored](#keyframe). A first step that starts by itself plays after the slide's transition. With a scroll, the next slide's first click plays along with it. Its first step's `start` doesn't change that. A click plays when any of its steps plays. A step that has keyframes or cues has no click of its own when each keyframe names an object the slide doesn't have or a hidden object, and each cue names such an object or a video, web video, or audio whose `start-on` is `slide`. Such a step stays in the file. An object is hidden when its own `visible` key, or that of a group above it, is false. An `initial` value doesn't count. Keyframes and cues on a hidden object play nothing. No step can show it. A step with no keyframes and no cues has its own click. A step with a `repeat-count` plays alone on its click. A file that breaks this is read with a warning, and the step doesn't repeat.

**A click's timing.** A step with `start: with-previous` starts when the step before it starts. One with `start: after-previous` starts when the step before it ends. When the step before it loops while it waits, an `after-previous` step starts when the loop's first pass ends. The loop plays on under it. A click ends when the last of its steps to end has ended. That isn't always the last step listed. A step with `repeat-count` plays its pass that many times. The instant one pass ends shows the next pass's start. The last pass's end shows the step's end state. A step's cues play on each pass. They don't play again while the step loops waiting for a click. The next click starts from each earlier step's end state. That is where each of its curves stands as the step ends. A curve's `loop` and a keyframe's `oscillate` count too. It isn't where the step's own `loop` is while it waits.

#### curve

One parameter's animation in a step: its keyframes and what happens after the last one. A position can also be keyed as one point. `frame.position` and `translation` have {x, y}, and `position` has {x, y, z}. Each of their keyframes has every part. A step keys a position either as a point or by its parts, not both. A step that keys both is read with a warning, and the point plays. An initial value sets each part on its own.

Where: `steps[].curves["<object>.<parameter>"]`

| key | required | values | description |
| --- | --- | --- | --- |
| `keyframes` | yes |  | The keyframes by id, one or more. They are read by their time, then by their id. |
| `loop` | with loop-keyframe | repeat, ping-pong | How it loops after its last keyframe until the step ends. With `repeat`, it replays from `loop-keyframe` to the last. With `ping-pong`, it plays that back and forth. Without it, it plays once. |
| `loop-keyframe` | with loop |  | The id of the keyframe the loop starts at. If the keyframe has a `begin`, the loop begins with its move. If it names no keyframe of the curve, the first is used. |

**Loops.** A curve that repeats is at its last keyframe at the moment it starts over. A loop from the last keyframe without a `begin` has nothing to replay. The curve then plays as if it had no loop.

**Initial values.** An initial value belongs to the steps that animate its parameter. Without them, it holds the parameter for the whole slide or composition. An object it hides shows only where a step shows it again.

#### keyframe

One keyframe: a value a parameter reaches at a time. Its id is unique in its step among its keyframes and cues. Two keyframes of one parameter at one time are read with a warning, and the one with the later id plays. A `begin` at or before the previous keyframe is ignored. On the first keyframe, a `begin` of 0 is ignored. A `discrete` key and interpolation `hold` have no move. A `begin` on either is ignored. An ignored `begin` still must come before `time`. A keyframe whose value is `null` clears the whole parameter at its time. The parameter's text style or default then shows. It can't clear a part of a key, a point, `visible`, `rotation`, `scale`, a constraint's strength, `shape-type`, `icon`, or `geometry`. A `null` on a key its object can't be read without, such as a shadow catcher's `width` or a point light's `intensity`, causes an `ignored-animation-value` warning and is ignored. A slide's or a composition's `initial` takes `null` by the same rules. An `exponential-scale` move works as After Effects' Exponential Scale.

Where: `steps[].curves["<object>.<parameter>"].keyframes.<keyframe id>`

| key | required | values | description |
| --- | --- | --- | --- |
| `time` | yes | 0 to 4294967296 seconds | When the parameter reaches the value. It is in seconds into the step. |
| `value` | yes |  | The value. It is written as the parameter is. It can be `null` to clear the whole parameter. It is the parameter's own value, not a change from the object's rest. |
| `begin` |  | 0 to 4294967296 seconds | When the keyframe's move begins. It is in seconds into the step. It must come before `time`. Without it, the move begins at the previous keyframe, or at 0 for the first keyframe. |
| `exponential-scale` |  |  | Whether a scale move changes by a steady ratio. A zoom then looks even. Its pace is even from or to 0, or across it. It applies only to `scale`, `scale.x`, `scale.y`, `scale.z`, and `crop.scale`. |
| `interpolation` |  | linear, ease-in, ease-out, ease-in-out, smooth, hold, anticipate, overshoot, anticipate-overshoot, bounce, elastic, or a record | How the value reaches the keyframe: gradually, or at once with hold. It is a named curve, a named curve with its settings, a cubic Bézier, or a spring. The default is linear. |
| `interrupted` |  |  | The longer move this keyframe interrupts. Up to the keyframe's time, the motion follows that move toward its `value`. Then the parameter has the keyframe's own `value`. |
| `motion-path` |  |  | A curved motion path for the keyframe's move. Only a point keyframe can have it. |
| `oscillate` |  |  | A wave added to the value from this keyframe to the next, or to the step's end. On a looping curve, the wave plays again each time around. |

**How a value moves.** A color moves in sRGB with premultiplied alpha. So a color that fades out to a transparent one keeps its own color as it fades. A color role moves as the slide's scheme colors it. A gradient moves into a gradient of its own type with as many stops. A radial gradient also needs the same `shape`. A linear gradient with a `line` needs another with a `line`. Each stop moves into the stop at its place, and the angle, line, or center moves into the other gradient's. A table's `min-row-heights` moves row by row into a list as long. A move that starts from the table itself starts from one height for each of its rows: the row's minimum, or the height it stands at where it has none. Between lists of different lengths, the first shows until the keyframe. Between any other two paints, such as a color and a gradient, the first paint shows until the keyframe. Between an image's own colors or the World's studio environment and a color, the first also shows until the keyframe. Each point of the path data in a `geometry`, `mask`, or `text-path` moves to the point at its place when the two paths' contours have as many points and are closed alike. The contours are paired in order. A curve's handles move to the handles at their place. A straight segment moves as a curve whose handles sit on its points. Any other two paths still morph, but the format doesn't set the shapes between them. The morph still starts exactly at one keyframe's path and ends exactly at the next one's. To set the shapes between two paths, give each pair of contours as many points, closed alike.

**Paste Animation.** Paste Animation restates each value for its target: a position moves by the offset between the two objects' rests, a turn by the difference between their turns, and a scale by the ratio of their scales.

#### keyframe-interrupted

The move a keyframe interrupts: where it was going and when it would have reached it. The keyframe's `interpolation`, `motion-path`, and `exponential-scale` shape the interrupted move: from `begin` to `interrupted.time`, and toward `interrupted.value`. An elastic's period and a spring's settling are measured over that move. At the keyframe's `time` the move is cut, and the parameter has the keyframe's own `value`.

Where: a keyframe's `interrupted`

| key | required | values | description |
| --- | --- | --- | --- |
| `value` | yes |  | Where the move was going. |
| `time` | yes | 0 to 4294967296 seconds | When the move would have reached `value`. It is in seconds into the step and at or after the keyframe's time. It doesn't make the step longer. |

#### keyframe-motion-path

A curved motion path for a point keyframe's move in the move's own coordinates. 0 0 is where the move starts, and 1 0 is where it ends. Seen on the slide, its y points 90 degrees clockwise from its x. SVG's y does the same. So for a move to the right, a negative y bends the path up the slide.

Where: a keyframe's `motion-path`

| key | required | values | description |
| --- | --- | --- | --- |
| `geometry` | yes |  | The path: SVG path data from the move's start at 0 0 to its end at 1 0. It is one open contour of 2 to 8,192 points. It has at most 2,097,152 characters. |
| `orient` |  |  | Whether the object turns to face along the path. The default is false. |

**Along the path.** The object moves along the path at the pace of the keyframe's interpolation. The interpolation sets how much of the path's length the object has traveled. Past either end, it moves on in the path's direction at that end. A 3D position's path bends its x and y, and its z moves straight. With `orient`, a flat object and a text with its model turn with the path's tangent. They turn by its direction, clockwise from the slide's x. One that heads to the right isn't turned. A model turns about its parent's y to face where it travels across x and z. While it travels along y alone, it keeps facing the way it did. Each one's own `rotation` adds to that turn, and a model's own rotation turns it first. When the move ends, each keeps facing that way until its next move along a path with `orient`. No other 3D object turns. An object turns along one path at a time. When a `translation` path and a `frame.position` path that both have `orient` overlap in time, only the `frame.position` path turns it, and the file is read with a warning.

#### keyframe-oscillate

A wave added to a parameter's value. Only a parameter with a single number that animates smoothly can have one. `volume` never can.

Where: a keyframe's `oscillate`

| key | required | values | description |
| --- | --- | --- | --- |
| `amplitude` | yes | any number | How far the value swings either way in the parameter's own unit. The value stops at the end of the parameter's range. |
| `frequency` | yes | more than 0 and at most 4294967296 cycles a second | How many full cycles each second. A noise wave wanders at that rate. After Effects' wiggle() frequency works the same way. |
| `phase` |  | −8589934592 to 8589934592 degrees | Where in its cycle the wave starts. A cycle is 360 degrees. The default is 0. |
| `seed` |  | whole numbers, 0 to 4294967294 | The noise seed. A seed picks one wave. The default is 0. Motion's Random Seed works the same way. |
| `wave-shape` | with seed | sine, triangle, square, sawtooth, noise | The wave's shape. With a seed, it must be `noise`. The default is sine. |

**Waves.** At a phase of 0, a sine, a triangle, and a sawtooth start at 0 and rise. A square starts at 1. Halfway through each cycle, a square falls to −1, and a sawtooth falls from 1 to −1. A noise wave wanders smoothly at random. It passes through 0 at the start of each cycle and never repeats. The format doesn't set a noise wave's shape. On a ping-pong's way back, a wave plays backward. On a looping curve, the last keyframe's wave doesn't play.

#### cue

An event at a set time in a step. Its id is unique in its step among its keyframes and cues. A clip plays an Action of the GLB `file` of a model or a 3D text. Cinema 4D's Motion Clip works the same way. A text built from an `extrusion` has no Actions. A clip on it plays nothing and causes a warning.

Where: `steps[].cues.<cue id>`

| key | required | values | description |
| --- | --- | --- | --- |
| `time` | yes | 0 to 4294967296 seconds | When it happens. It is in seconds into the step. |
| `type` | yes | paragraph, play, clip | What it does. A `paragraph` cue shows a paragraph. A `play` cue starts an audio object, a video, or a web video. A `clip` cue plays an Action of a model or a 3D text. |
| `object` | yes |  | The id of the object it acts on: for a clip, a model, or a 3D text. |
| `action` | with type clip |  | The name of the Action that a clip plays. An unnamed Action is named Animation and its number in the file, as in `Animation 1` for the first. A clip naming an Action its object doesn't have plays nothing. It causes an `unknown-action` warning. |
| `blend-in` |  | 0 to 4294967296 seconds | How long the clip takes to blend in fully over the model's current motion. Without it, or at 0, the clip is fully blended in from its start. |
| `clip-scale` |  | more than 0 | How much longer a clip's Action plays than its file says. 2 is half speed, and 0.5 is double. Maya's Clip Scale works the same way. The default is 1. It isn't used by a model's clip with a `stride`. |
| `clip-trim` |  | 0 to 4294967296 seconds | The part of the Action that plays: a start and an end in seconds into the Action. |
| `loop` |  | repeat | With `repeat`, the Action plays again from the start of its `clip-trim` each time it ends. Without it, it plays once, even an Action made to repeat. A model's `stride` times it by travel instead. |
| `paragraph` | with type paragraph |  | The id of the paragraph that appears: the `<!-- id: … -->` ending its last line or alone on the next. A list item's ends its first paragraph. A reader warns when no paragraph of the text has the id. |
| `stride` |  | more than 0 and at most 1 × 10¹⁸ meters | How far the model travels per cycle of its Action in the GLB's meters. The Action's timing then follows the model's travel. It doesn't apply to a 3D text's clip. |

**A nested item.** A list item that no cue names appears with the nearest item that it's nested under and that a cue names. One that a cue names appears at its cue or with the item it's nested under, whichever comes later.

**A clip's clock.** A clip's time starts at its cue and runs on the show's clock: through the rest of its step, the waits for a click and later clicks, until the slide ends. `time` and `blend-in` are in the slide's seconds. `clip-trim` is in the Action's seconds, and `clip-scale` turns the slide's seconds into the Action's. While the slide waits, a repeating clip plays a whole number of times over the wait and is sped up or slowed down as little as fits.

**A model's pose.** Before a model's first clip starts, it shows that clip's first trimmed pose. With a `blend-in` above 0, it shows its rest pose and blends from there. A clip that plays once holds its last trimmed pose. Each later clip changes only the node properties its Action animates. Other properties keep the earlier clips' results or the rest pose. In a step with a `repeat-count`, a clip blends in over its `blend-in` or one play of the step, whichever is shorter. So it is fully blended in when the step's next play starts it again.

**Action names.** A clip names an Action by its name in the file, matched exactly. An Action with no name, or an empty name, is named Animation and its number in the file, as in `Animation 1` for the first. An Action can have the same name as an earlier one, or a generated name that is already taken. It then gets the first of name 2, name 3, and so on that isn't taken yet. The names the file gives are reserved first. So Walk, Walk, Walk 2 are read as Walk, Walk 3, Walk 2.

#### parameters

Animation parameters that aren't object keys. Each is written after its object's id and a dot. Together they make one key, such as "card.opacity". The object table lists each key's own parameters.

Where: `initial["<object>.<parameter>"]`, `steps[].curves["<object>.<parameter>"]`

| key | required | values | description |
| --- | --- | --- | --- |
| `frame.position` |  |  | `frame.x` and `frame.y` as one point, {x, y}. A step that keys it can't also key either part. |
| `scale` |  | 0 to 511 | How far a group scales about its anchor point. It is one number. A group has no `scale` key. |
| `translation` |  |  | `translation.x` and `translation.y` as one point, {x, y}. A move along a motion path keys them together this way. A step that keys it can't also key either part. |
| `translation.x` |  | −65536 to 65536 canvas units | How far the object is moved right from its frame in canvas units. |
| `translation.y` |  | −65536 to 65536 canvas units | How far the object is moved down from its frame in canvas units. |

**What can have a parameter.** Some records, such as `enter` and `repeater`, have no default. A parameter inside one, such as `enter.progress` or `repeater.rotation`, needs that record on the object. A table can't have a parameter that lays out its words. A text box that grows to fit its text can't have one either. That rules out a table's columns and its header row and column, and `align`, `bullet-styles`, `case`, `column-count`, `column-gutter`, `font-family`, `font-size`, `font-style`, `font-weight`, `frame.height`, `frame.width`, `inset`, `kerning`, `line-height`, `list-indent`, `number-spacing`, `padding-bottom`, `padding-top`, `paragraph-spacing`, `text-path`, `text-style`, and `tracking`. Only a text, a table, an image, a video, a shape, a path, an icon, an instance, a chart, a group, and a web video can have `translation`. A floor's only position parameter is `position.y`. A line's `start` or `end` has parameters only while that end isn't attached to an object. An object an auto layout places can't have `frame.x`, `frame.y`, or `frame.position`. A step moves it by its `translation`. A line an auto layout places can't have `start` or `end`. A text or a shape whose entrance has a `delivery` has no `enter` parameter, such as `enter.progress`.

#### interpolation

Named interpolations: how a value changes over a move, gradually or at once. Transitions can use linear, ease-in, ease-out, and ease-in-out. A keyframe's or a text's interpolation can instead be a named curve with its settings. That includes a cubic Bézier of its own.

Where: a keyframe's, a transition's, and a text's `interpolation`

| name | required | values | description |
| --- | --- | --- | --- |
| `anticipate` |  |  | Pulls back before it moves. |
| `anticipate-overshoot` |  |  | Pulls back first, then passes the keyframe's value and settles back on it. |
| `bounce` |  |  | Falls onto the keyframe's value and bounces off it three times. Each bounce is lower. It never passes the value. Its bounciness is 0.5. |
| `ease-in` |  |  | Starts slowly from the previous keyframe. CSS's ease-in works the same way. |
| `ease-in-out` |  |  | Starts slowly and ends slowly. CSS's ease-in-out works the same way. |
| `ease-out` |  |  | Slows down as it reaches the keyframe. CSS's ease-out works the same way. |
| `elastic` |  |  | Springs past the keyframe's value and swings into it. Each swing is smaller. |
| `hold` |  |  | Keeps the previous value until the keyframe's time, then jumps. |
| `linear` |  |  | Moves at a constant speed. |
| `overshoot` |  |  | Passes the keyframe's value and settles back on it. |
| `smooth` |  |  | Starts and ends gently, over a shorter part of the move than ease-in-out. |

**The named curves.** `ease-in`, `ease-out`, and `ease-in-out` are CSS's easing functions of those names. In CSS's cubic-bezier() form, `smooth` is (0.25, 0, 0.75, 1). Let b be the `back`. Its default is 1.70158. Then `anticipate` is (0.333333, 0, 0.666667, −b ÷ 3), and `overshoot` is (0.333333, (b + 3) ÷ 3, 0.666667, 1). They are Robert Penner's back in and back out. `anticipate-overshoot` is his back in and out, `elastic` is his elastic out, and `bounce` is his bounce out at a bounciness of 0.5. Blender's Back, Elastic, and Bounce are the same curves. Below an amplitude of 1, they differ: Blender's Elastic and `elastic` shrink the swing, and Penner's keeps it at 1.

#### keyframe-interpolation

An interpolation with its settings: how far `anticipate`, `overshoot`, or `anticipate-overshoot` pulls back or swings past, an elastic's swing, a bounce's bounciness, a spring's damping ratio, or a cubic Bézier's two handles. The handles' keys are named the way CSS's cubic-bezier() names its four numbers. A named curve with no settings is written as just its name. A cubic Bézier that is the same as a named curve is written as that named curve's name too.

Where: a keyframe's or a text's `interpolation` written as an interpolation with its settings

| key | required | values | description |
| --- | --- | --- | --- |
| `type` | yes | anticipate, overshoot, anticipate-overshoot, elastic, bounce, spring, cubic-bezier | Which interpolation it is: a named curve, a cubic Bézier, or a spring. |
| `amplitude` |  | 0 or more | The size of an elastic's swing in multiples of the move. The default is 1. |
| `back` |  | 0 to 1 × 10³⁰⁷ | How far `anticipate`, `overshoot`, or `anticipate-overshoot` pulls back or swings past. Robert Penner's back curves and Blender's Back use it the same way. The default is 1.70158. |
| `bounciness` |  | 0 to 1 | A bounce's rebound speed in fractions of its landing speed. At 0, it lands dead. At 1, it rebounds to its height each time. The default 0.5 is Blender's Bounce. |
| `damping-ratio` | with type spring | 0.3 to 1 | How strongly a spring is damped. At 1, it doesn't swing past its keyframe. Less damping swings further. |
| `period` |  | more than 0 and at most 4294967296 seconds | How long one swing of an elastic lasts. The default is 0.3 of the length of the move. |
| `response` |  | more than 0 and at most 4294967296 seconds | The spring's natural period. A shorter one springs faster. Without it, the spring settles by the end of the move. |
| `x1` | with type cubic-bezier | 0 to 1 | The time of a cubic Bézier's first handle in fractions of the move. |
| `x2` | with type cubic-bezier | 0 to 1 | The time of a cubic Bézier's second handle in fractions of the move. |
| `y1` | with type cubic-bezier | any number | The value of a cubic Bézier's first handle in fractions of the change. It can be below 0 or above 1. The move can then go past an end. It stops at the end of the parameter's range. |
| `y2` | with type cubic-bezier | any number | The value of a cubic Bézier's second handle in fractions of the change. It can be below 0 or above 1. The move can then go past an end. It stops at the end of the parameter's range. |

**Springs.** A spring's `response` is its natural period, in seconds: how long one swing would take with no damping. Its `damping-ratio` d is how strongly it is damped. SwiftUI's response and dampingRatio mean the same. A ratio of 1 is critical damping. With damping, each swing lasts the response divided by √(1 − d²). At a ratio of 0.3, that is about 1.05 times the response. A Position constraint's `response` and `damping-ratio` mean the same. A spring keyframe reaches its value at its time. The format doesn't set the motion between beyond its response and damping ratio. A SwiftUI spring keyframe with no duration lasts for its spring's settling duration.

#### fonts

The family each font role uses. MarkdownPoint bundles Inter, Archivo, Source Sans 3, Source Serif 4, Schibsted Grotesk, Fraunces, Atkinson Hyperlegible Next, and Source Code Pro. They need no files. Any other family comes with the theme in `font-files`. A role whose family is neither bundled nor in `font-files` reads with a `missing-font` warning. A family's name is never a CSS generic family: `serif` names a family called serif.

Where: `fonts`

| key | required | values | description |
| --- | --- | --- | --- |
| `display` | yes |  | The family of text whose `font-family` is `display`, such as titles. |
| `body` | yes |  | The family for running text. |
| `mono` | yes |  | The family for code. |

**Families.** Family names match by Unicode's canonical caseless match. It uses the full case folding of Unicode 17.0.0. For example, INTER is Inter, and Café is one name whether its é is one composed character or an e and a combining accent. In CSS's matching, those are two names. A theme can have its own faces for a bundled family too. Its slides then draw those faces wherever they draw that family. Each `font-files` key is matched to the families `fonts` names this way. The slides draw the faces under the key and read no family name from the faces themselves. Two keys that match are one family, and a theme lists it only once. A key that no role names is kept and reads with an `ignored-key` warning. Its faces aren't drawn.

**Faces.** A face's weight is the range of its `fvar` table's `wght` axis, else its OS/2 table's `usWeightClass`. It is italic when its OS/2 table's `fsSelection` or its `head` table's `macStyle` sets the italic bit. OpenType defines these tables. Each character is drawn in the face that CSS Fonts Level 4's font matching chooses for the text's weight and style among the faces of the family that draws it. No face is slanted or made bolder to stand in for one the family lacks. So italic text stands upright in a family with no italic face.

**Embedded faces.** An .eot file has one face in Embedded OpenType. PowerPoint documents embed their fonts in this format. It is defined by a W3C Member Submission. The file is plain, or scrambled with the flag 0x10000000. It is never compressed with 0x4. The face's OS/2 table's `fsType` alone decides whether it is drawn. A face is drawn when it is installable or editable. It isn't drawn when it is restricted, preview and print, or bitmap only, when its table is version 3 or later and sets more than one of the restricted, preview and print, and editable bits, or when it has no OS/2 table. Before version 3, the least restrictive of those bits counts. A face that isn't drawn reads as `invalid-font`, and the theme still reads.

| `file` |  |  | The image's path in the theme's folder, or one path per color scheme. A map names light and dark, and may name other schemes. A slide in a scheme it leaves out uses its appearance's image. |
| `grayscale` |  | 0 to 1 | How far the colors fade to gray. After `temperature`, it is CSS's `grayscale()` of `grayscale` on the sRGB values. 0 leaves them unchanged. |
| `opacity` |  | 0 to 1 | How opaque the image is. The default is 1. |
| `saturation` |  | −1 to 1 | How much more or less saturated the image's colors are. After `contrast`, it is CSS's `saturate()` of 1 + `saturation` on the sRGB values. 0 leaves them unchanged. |
| `temperature` |  | −1 to 1 | How much warmer or cooler the image's colors are. After `saturation`, red is multiplied by 1 + `temperature` ÷ 4 and blue by 1 − `temperature` ÷ 4. 0 leaves them unchanged. |

## <a id="schemas"></a>JSON Schemas

Each JSON file has a draft-07 JSON Schema in [schemas/1.0](schemas/1.0/). The schema is named for the `type` the file states. The folder is named for the version, 1.0. Each minor version's schemas are in a folder of their own. A published folder never changes. A schema's `$id` is https://markdownpoint.com/format/schemas/1.0/ followed by its file name. Refer to a schema by its `$id`. Its `definitions` are its own and may change. A schema checks a file's keys, their values, and the keys a record needs. It refuses what a later minor adds: a key, a word, an object type, or a number outside a range. MarkdownPoint passes over each and keeps it. MarkdownPoint also reads a number to six decimal places before checking it. A schema checks the number as written. The schemas' patterns are ECMA 262 regular expressions, the dialect draft-07 names, and they use lookahead. A validator whose engine has no lookahead, such as RE2, can't compile them.

MarkdownPoint also checks what a schema doesn't:

Every JSON file:

- A JSON object never has the same name twice. A file that does is refused.
- Objects and arrays nest at most 256 levels deep. The outermost one counts as the first level. A file nested 256 levels deep is read, and one nested 257 is refused.
- A file may start with a byte order mark. MarkdownPoint skips it.
- A file with a number too large for a double is refused.

[presentation.schema.json](schemas/1.0/presentation.schema.json):

- A locale names each variant once.
- A transition's `delay` goes only beside `start: automatically`.
- Every file a background or an object names is in the presentation's media or generated folder.
- A file path is in Unicode's composed form (NFC). Each of its names is at most 255 bytes in UTF-8.
- A composition's id isn't also a slide's id. No composition contains itself, directly or through another. The instance that closes the loop draws nothing and causes a warning. A composition's text has no `model`.
- A composition's controls have unique ids. A number control's minimum is below its maximum. Its default is from its minimum to its maximum. A choice control's options have unique ids. Its default is one of their ids.
- Only the camera and the World have the ids `camera` and `world`.
- A 3D object's parent is a model or a light, and not the object itself. Any other is skipped with a warning, its `parent-node` and `parent-inverse` with it. A constraint's target is one its constraint takes. Any other is skipped with a warning.
- A flat object's parent is a group, and not the object itself. A text with a `model` has none. Any other parent is dropped with a warning. Groups nest at most 200 deep. A deeper group stands at the root with its members and causes a warning. No object is its own parent through others. In groups and in 3D alike, every link of such a loop is dropped with a warning. No Aim's target waits on the model it turns. Such an Aim turns nothing and causes a warning. The parents in its loop stay.
- A shape with text, or a group that can't repeat, keeps its `repeater` and makes no copies. The repeater is ignored with a warning.
- A slide's or a composition's objects have unique ids. None of its own objects has an id that its overrides change.
- A 3D object's rotation in degrees has no w. In quaternion mode, it has w, x, y, and z. A quaternion's parts don't all read as 0.
- A web video's address names a video.
- A path's `geometry`, an image's `mask`, and a text's `text-path` are well-formed SVG path data that starts with a move. Each point and handle, once made absolute, is a finite number. A video's or an audio object's `media-trim` ends after it starts. An object's constraints have unique ids.
- A text's enter or exit has a `seed` only when `order` is `random`. An enter with a `delivery` has `based-on` set to `paragraph`. Its `order`, `spread`, `pause`, and `progress` are then at their defaults.
- A binding is on a composition's own object and names one of its controls, of a type that can set the key. A value written beside a key that a binding sets is checked as any value is but isn't used. It causes a warning, and a save writes the binding alone. A binding to a control the composition doesn't have, or to one that can't set its key, sets nothing. The value beside it is used and causes no warning. A control can also bind one number part of a record, such as a group's `tilt.x`. That part's value stays in the record and causes no warning. Where a binding sets the part, the control's value is used in its place. An `initial` value or a keyframe of a key or part that a binding sets causes a warning. A save keeps either one.
- An override's key and value apply only to an inherited object that can have them. Other overrides are kept but ignored, and cause a warning.
- An animated parameter is one its object has. A keyframe's value is a valid value of that parameter. A name or a value that isn't valid for any object's parameter is refused. One that is valid elsewhere but not on its own object is ignored with a warning.
- Only a keyframe of `scale`, `scale.x`, `scale.y`, `scale.z`, or `crop.scale` can have `exponential-scale`. Only a parameter of one number that moves smoothly can have `oscillate`. `volume` only fades and can't have it. An `initial` value can't set a point parameter, such as `frame.position`. It can set the point's parts.
- A slide's or a composition's steps have unique ids. A step's keyframes and cues have unique ids among them all. A keyframe's move starts before its time. An interrupted move would have reached its value at or after the keyframe's time. Only a noise wave can have a seed.
- A composition's steps have no cues. They have no `loop` either. Either one is ignored with a warning. With every pass counted, they last at most 4,294,967,296 seconds. Otherwise, the composition is read with a warning.
- Only a point keyframe can have a motion path. It is one open contour from 0 0 to 1 0. A clip's trim ends after it starts.
- Every string and key is well-formed Unicode. None holds an unpaired surrogate. A lone `\ud800` is one.

[master.schema.json](schemas/1.0/master.schema.json):

- A font family's name starts with a letter or a digit of any script. It has only letters, combining marks, digits, spaces, periods, underscores, and hyphens. It doesn't end with a space. A `font-files` key is spelled the same way. No two `font-files` keys name the same family. They are matched the same way `fonts` matches a family.
- A file path is in Unicode's composed form (NFC). Each of its names is at most 255 bytes in UTF-8.
- A brand color a scheme names is one the brand has.
- The scheme named light is light, and the one named dark is dark.
- The words in `text` belong to the master's own text, table, chart, and shape objects.
- Its objects pass the presentation's object checks.
- Every string and key is well-formed Unicode. None holds an unpaired surrogate. A lone `\ud800` is one.

[layout.schema.json](schemas/1.0/layout.schema.json):

- The words in `text` belong to the layout's own text, table, chart, and shape objects.
- A placeholder names one file, not one per scheme.
- Its objects and overrides pass the presentation's object checks.
- Every string and key is well-formed Unicode. None holds an unpaired surrogate. A lone `\ud800` is one.

[theme-package.schema.json](schemas/1.0/theme-package.schema.json):

- Nothing beyond its schema.

[version.schema.json](schemas/1.0/version.schema.json):

- Nothing beyond its schema.

[style-library.schema.json](schemas/1.0/style-library.schema.json):

- Nothing beyond its schema.

[image-generation.schema.json](schemas/1.0/image-generation.schema.json):

- A prompt and an image style are in Unicode's composed form, NFC.
- A file path is in Unicode's composed form (NFC). Each of its names is at most 255 bytes in UTF-8.
- An output has no more pixels than an image can have. It has the aspect ratio asked for.
